## 一句话玩法

攻略修女=打BOSS,选票=掉落物。每15-20楼一次修女会议,玩家提案篡改现有院规,通过的规则全局改变修道院并反哺攻略,最终按规则组合把修道院改造成想要的形态。

## 核心循环

```text
攻略修女(多手段攒支持度/堕落度)
→ 每15-20楼自动开会(道具可手动开启/延缓/冻结/跳过)
→ 提案篡改一条院规一档(赞成>反对即通过,弃权不计,平票院长裁决)
→ 规则生效 = 全局世界书开关(所有修女行为/着装/日程改变)
→ 攻略环境变好,滚雪球
→ 激进度累积 → 总部视察(后期高压事件)
→ 拿下多数修女 + 重规篡改 → 终局改造
```

## 对抗面

- **院长特蕾莎**:会议主持人,**平票裁决权**(无一票否决,否则前期没法玩)。玩家票不够的会议,她的紧缩提案通过(恢复原规/加码戒律),直接 debuff 攻略环境。
- **纠察嬷嬷**:替院长干脏活——突击查寝、盯梢神父、举报。**翻转她=中期里程碑**:院长瞎眼+全员投票情报透明+倒过来递情报。
- 层次:前期爪牙骚扰 → 中期提案对轰 → 后期决战院长。

## 院规体系(核心:篡改现有规则,不是立新法)

开局即存在一部**《圣维罗妮卡院规》约10条**,全部可见——院规列表就是提案菜单和内容树,玩家开局就能看到整棵树。

权重三级(越重门槛越高、激进度加得越多):

| 权重 | 章节 | 条目示例 |
| --- | --- | --- |
| 轻规 | 日常戒律 | 作息熄灯、服装规范、用餐缄默、饮食清规 |
| 中规 | 空间/仪式 | 男女之防、寝室制度、告解制度、苦修方式 |
| 重规 | 三大誓愿 | 贞洁、服从、清贫(终局目标) |

- 每条规则 **2-3 档篡改阶梯**(服装规:轻量化→便装→暴露→仪式性裸体),一次会议只推一档
- 每档定义:激进度值、全局效果文本(行为/着装/空间描写如何改变)、各修女偏好修正、部分档位带奉献金产出(经济类)

## 投票判定(双门槛,核心机制)

每条篡改案对**每个修女单独判**:

1. **支持门槛**(她愿不愿帮你)——比支持度
2. **堕落门槛**(她能不能接受这内容)——比堕落度,± 她对该类规则的偏好修正(如厨娘对饮食规 -10)

| 判定结果 | 条件 |
| --- | --- |
| 赞成 | 两个门槛都过 |
| 弃权 | 支持够、堕落不够(喜欢你但说不出口);或被把柄强制 |
| 反对 | 都不够 |

**通过条件:赞成 > 反对(弃权不计),平票院长裁决。**

弃权是战略资源——不必腐化所有人,把反对派做成弃权就够。手段分工由此成立:

- 真感情/利益交换 → 涨**支持度**(轻规的票)
- 色堕 → 涨**堕落度**(重规的解锁钥匙)
- 把柄/威胁 → **强制弃权**(她不投你,但她闭嘴)

**票数预测**:状态栏院规面板显示每条规则的各修女投票倾向预测(开会前就知道差几票、该攻略谁)。带情报雾:攻略到一定程度才可见该修女的倾向;纠察嬷嬷倒戈后全员透明。

## 总部视察(后期高压)

- 已通过规则的**激进度累计过阈值**(或固定楼数)→ 总部派巡查修女来访
- 视察期间:激进规则要么花道具/靠修女配合掩盖,要么被强制废除、甚至撤换院长(坏结局风险)
- **巡查修女=隐藏第8 BOSS**:拿下她=总部背书,解锁最激进的规则档

## 道具商店

货币**奉献金**。来源:攻略里程碑 + 经济类规则通过后的周期产出(规则也是印钞机,提案选择多一层取舍)。

| 类别 | 内容 |
| --- | --- |
| 攻略辅助 | 酒、香、礼物、告解室升级等 |
| 会议权限(战略层) | 手动开会(节奏快时提前收割)/ 延缓(票不够时拖)/ 冻结(视察期停摆)/ 跳过(躲院长的紧缩提案) |
| 视察应对 | 伪装、贿赂、临时复原 |
| 服装 | 见下节 |

### 服装系统

- 每个修女一个着装对象,按槽位存:`{ 头饰, 上身, 下身, 内衣, 腿足, 配饰 }`(7人×6槽=42字段,纯脚本记账)
- 每件服装有**大胆度**:堕落度不够 → 拒穿或只肯私下穿(复用云霜凝"阶段接受上限"教训,防越界)
- **私穿/公穿双段奖励**:堕落度决定她肯不肯穿,院规服装档决定她敢不敢穿出房门——规则没改前只在私室穿给你看,服装规篡改通过后才公开穿,立法价值+1
- AI 每轮只看到在场修女的着装编译文本(一行现状,不是换装历史)

## 终局

由通过的规则组合决定修道院最终形态,多结局。

〔待确认〕结局表草案:圣妓院(经济+暴露主导)/ 神父后宫(告解私密主导)/ 爱之家(真情主导)/ 表面圣洁暗地淫乱(纪律维持+暗规则)+ 坏结局(总部接管/神父驱逐)。

〔待确认〕情节黏合剂:修道院财政入不敷出、总部早有关院之意——串起院长软肋(保住修道院=她的一切)、经济规则的意义(创收续命)、视察的双层动机(查风纪也查账)。

## 技术架构(沿用云霜凝范式)

**总原则:机制层全归脚本,AI 只演戏。** 投票计数、楼层倒计时、货币、着装、激进度全部脚本计算存 MVU 变量,AI 每轮只拿到"这一幕需要的切片"(≤2k token)。

### 注入策略

1. 在场修女才全量注入当前阶段行为指导(EJS 按堕落度条件渲染,永远只有当前档)
2. 规则不注入立法史,脚本把已生效规则**编译成一份「现行院规快照」**(AI 读现状不读 diff,遵守"AI 无历史感知"原则)
3. 会议议程/各修女立场只在会议楼注入
4. 着装只注入在场修女的一行编译文本

### MVU schema(草图)

- 修女 × { 支持度, 堕落度, 阶段, 专线进度, 着装槽位, 情报可见性 }
- 院规状态表(每条规则当前档 + 篡改历史真值)
- 会议状态(倒计时楼数, 会议历史, 权限道具效果)
- 奉献金 / 激进度 / 视察状态

### 组件

- 世界书:世界观 / 院规(EJS 快照)/ 角色卡×8 / 阶段行为 / 事件注入
- 脚本:楼层计数触发会议、双门槛算票、院规快照编译、货币结算、视察触发
- 状态栏 UI(Vue):票数一览、院规面板(含投票预测)、商店、会议权限按钮、提案界面

### 云霜凝教训清单(直接继承)

- event 绝不给示例(会变固定模板)
- 物理画面优先,避免分档模板坍缩
- 性癖/解锁必须色情挂钩,解锁立见奖励感
- 一次性门控用 MVU 持久字段(模块变量会被 reloadOnChatChange 重置)
- 状态栏按钮要让 AI 下轮读到,直接写 message_id=-1,不能用 store.flush
- 阶段接受上限硬约束(各阶"她能被推进到哪"的物理边界)

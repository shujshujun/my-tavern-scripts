## 一句话玩法

攻略修女=打BOSS,选票=掉落物。每15-20楼一次修女会议,玩家提案篡改现有院规,通过的规则全局改变修道院并反哺攻略,最终按规则组合把修道院改造成想要的形态。

```text
攻略修女(多手段攒支持度/堕落度)
→ 每15-20楼自动开会(道具可手动开启/延缓/冻结/跳过)

→ 拿下多数修女 + 重规篡改 → 终局改造
```

## 投票判定(双门槛,核心机制)

每条篡改案对**每个修女单独判**:

1. **支持门槛**(她愿不愿帮你)——比支持度
2. **堕落门槛**(她能不能接受这内容)——比堕落度,± 她对该类规则的偏好修正(如厨娘对饮食规 -10)

| 判定结果 | 条件 |
| --- | --- |
| 赞成 | 两个门槛都过 |
| 弃权 | 支持够、堕落不够(喜欢你但说不出口);或被把柄强制 |
| 反对 | 都不够 |

**通过条件:赞成 > 反对(弃权不计),平票院长裁决。**

弃权是战略资源——不必腐化所有人,把反对派做成弃权就够。手段分工由此成立:

- 真感情/利益交换 → 涨**支持度**(轻规的票)
- 色堕 → 涨**堕落度**(重规的解锁钥匙)
- 把柄/威胁 → **强制弃权**(她不投你,但她闭嘴)

**票数预测**:状态栏院规面板显示每条规则的各修女投票倾向预测(开会前就知道差几票、该攻略谁)。带情报雾:攻略到一定程度才可见该修女的倾向;纠察嬷嬷倒戈后全员透明。

**算票引擎已落码(2026-07-12)**:`voteEngine.ts` 纯函数(计算单票/计算投票/偏好修正=具体规则id优先其次权重类别),平票裁决=按院长自己那票的立场;结算/预测面板/抢案预判三处复用同一引擎。

**院规法典面板已落码(2026-07-13,客户端"法典"页签)**:11 条规则卡=权重章+现行条文(**已修订条目 palimpsest 刮改视觉:旧条文划线半透明压在新条文上方**)+下一档预告+**七席投票倾向预测**(圆形席位章:赞成金/反对朱/弃权灰/情报雾"?"),情报雾=修女.情报可见(任一专线里程碑达成即透明,纠察倒戈全员透明),把柄强制弃权同步反映;会议议程列表复用同一预测席位。

### 会议流程(已定:会议=结算画面,不是RP戏)

**核心铁律:票由数值算出,会议过程固定,玩家无法通过RP/话术操纵投票结果。** 攻略博弈全部发生在两次会议之间,会议只是翻账本。理由:保护策略层(否则最优解变成会上说骚话)、防prompt操纵、AI分工干净(脚本算结果→产出"会议结果数据卡"→AI只演不改)。

游戏客户端场景切换(见「游戏客户端」章),会议触发楼自动进入:

```text
日常场景 ──(倒计时到/道具手动开启)──→ 会议场景(整屏牧师会礼堂)
会议场景界面:现行院规列表 + 本次议程(目标规则) + 8头像投票翻牌(赞成/弃权/反对) + 结果
投票完毕 → 脚本自动推进一楼(AI拿数据卡演会议现场:谁举手谁低头)
→ 出现「离开会议厅」按钮 → 点击回日常场景
```

- **票值快照**:会议触发楼立即快照全员支持度/堕落度,投票按快照算,会议楼内的数值变动不影响本次结果
- **提案时机**:会议模式开屏时玩家从院规面板选议程(玩家在会议中唯一的操作),点"开始投票"后全自动
- **院长抢案**:脚本预判玩家票面明显不够时,议程被院长换成她的紧缩案,同样自动结算

**已落码(2026-07-12,`meetingSystem.ts` + 客户端会议场景)**:倒计时归零→状态=会议中+票值快照存 chat 变量(`_会议`,不进 stat_data,AI 不可见)→客户端选议程(目标档=当前档+1,不可跳档)→UI 事件`禁忌修道院:开始投票`→结算:预测反对>赞成即抢案(紧缩=回退激进度最高的已改规则一档,无可回退则训诫案;玩家原案不进表决)/否则正常结算(通过即写院规档+激进度)→数据卡(铁票实录+只演不改+全局效果)注入下一楼由 AI 演会议现场(数据卡随 `_会议.结果` 常驻,swipe 重演不丢)→「离开会议厅」:回日常+倒计时重掷15-20+通过案排队**新规首夜**(零示例指令,注入一次,骨架取舍:swipe 不重演)。待接入:把柄强制弃权、难度档会议间隔、巡查入席。

### 核心玩法定位与好玩度诊断(2026-07-14 记录)

**核心幻想一句话:"我不是睡服了她们,我是把堕落写进了法律。"** 立法者视角的复利雪球:攒票→开会→篡改院规→全院随法而变→更容易攒票。会议倒计时=游戏心跳(15-20楼一次收获检定);短期(这楼去哪找谁)/中期(下次会议凑票)/长期(结局形态)三层目标嵌套完整。

诚实诊断——骨架对,缺三块肉,**实施优先级**:

1. **敌人回合(最高优先)**:院长主动提案紧缩案(玩家要凑票去否决=防守战)+ 视察系统上线 + 纠察突击。没有输的可能,赢就不值钱
2. **新规首夜蒙太奇**:法律生效之夜,三四个修女各自面对新规的第一反应(尤其投了反对票却必须遵守的人)——本作独有爽点,做足
3. **撞见/随机事件密度**:两次会议之间15-20楼不能是刷好感的磨,行动选项风险差拉开(大胆真的可能-3+警戒),推门撞见她独处的秘密(专线里程碑大半是撞见型,地图已给触发器)
4. 忏悔录图鉴+结局表(收集拉力+终点意义)

设施/自建房间排在这四个之后。**数据隔离结论(2026-07-14)**:快照数值隔离已是物理隔绝(房外修女数值根本不进prompt);人设条目维持按名字绿灯自然触发,marker隔离+公开印象方案**否决**(简单优先);远期记忆靠里程碑世界书解决(TODO)。

### 服装系统

## 技术架构(沿用云霜凝范式)

**总原则:机制层全归脚本,AI 只演戏。** 投票计数、楼层倒计时、货币、着装、激进度全部脚本计算存 MVU 变量,AI 每轮只拿到"这一幕需要的切片"(≤2k token)。

### 注入策略

1. 在场修女才全量注入当前阶段行为指导(EJS 按堕落度条件渲染,永远只有当前档)
2. 规则不注入立法史,脚本把已生效规则**编译成一份「现行院规快照」**(AI 读现状不读 diff,遵守"AI 无历史感知"原则)
3. 会议议程/各修女立场只在会议楼注入
4. 着装只注入在场修女的一行编译文本
5. **双通道快照**(道渊"隐性规则"升级,2026-07-12定):数值与语义分离——**记账通道**给数字(`堕落度: 42`,供AI做±3更新);**表现通道**由脚本查表把数值编译成感知语("她最近祈祷时总走神,又为此加倍苦修")。硬规则:正文描写与台词只准用感知语,**数字与机制词(堕落度/支持度/阶段)是穿帮词,禁止出现**。同一编译管道两个出口:AI侧出感知语,玩家侧出恶魔低语(见状态栏)

**已落码(2026-07-12,`snapshotSystem.ts`)**:每轮注入 `<修道院快照>` = 现行院规快照(未改条目给原规/已改给条文+全局效果)+ 焦点修女全量(记账数字+感知语+心理+情绪+着装一行+当前阶段接受上限硬约束)+ 背景修女一行 + 院内空气(警戒度感知语)+ **演出规则尾段**。感知语=支持档语+阶段基调+罪恶感语(罪恶感=max(0,堕落度-(100-信仰值)),三档查表)。焦点检测:扫 prompt 尾部 4 楼提及,末条(玩家输入)优先,**焦点上限暂按 2**(〔待拍板〕手动第 3 位);巡查修女登场前不参与检测。快照同时声明"仅焦点可更新数值"。

**机制规则不进世界书(用户定档 2026-07-12)**:人格防线/认知隔离/表现通道三条规则**藏在脚本里随快照注入**(玩家不可见不可关),并按场景裁剪省 token:表现通道每轮必带;有焦点修女才带人格防线;场上多于一人才带认知隔离。世界书只留"内容"(世界观/角色卡),不放机制规则。

### 变量安检机(道渊 Zod 校验层引入,2026-07-12定)

### 已落地修复

1. **任意时间推进串出其他房间正文**：不再只针对小憩。新增正文幕归属状态，以聊天 ID、时间线世代、消息锚、房间和“本次是否更新正文幕”共同判定；移动立即作废旧幕。手动时间推进只有确实生成本拍反馈时才更新正文幕，撤销不认领正文幕。
2. **远程楼务**：rq0.73 就存在 `进入()` 先乐观修改 UI 房间、后写 chat `_场景` 的竞态，并非拆分新引入。现在移动单飞，场景写成功后才提交本地房间；脚本楼务入口在启动与最终奖励提交前都读取权威 `_场景` 再拒绝异地结算。
3. **同场双角色立绘比例**：rq0.73 已使用相同 `object-fit: contain/cover` 规则，属于旧视觉缺陷，不是拆分丢失。六张普通立绘可见 alpha 高度本来一致，差异来自透明画布宽度令宽图先受槽宽约束。现改为等高裁切槽＋图片 `height:100%; width:auto`，双人头脚线一致；荣耀洞 16:9 特殊件继续使用独立舞台坐标。
4. **自定义 API 设置**：rq0.73 原界面只有手填模型并在 `change` 时自动写入，属于体验增强而非拆分回归。现在通过宿主模型列表能力读取模型，显式“保存并启用”，同通道重按不重置草稿，地址去尾斜杠，错误反馈会遮蔽密钥。
5. **好感／堕落／婚姻三轴**：整个卡框按 0—100 从左到右填充，三轴结构／尺寸／圆角一致，文字浮在填充上，保留夜间与减少动效规则。代码、测试、桌面／手机浏览器预览均已复审；**最终视觉仍待用户在真实游戏里确认，发布状态不能视为完成**。
6. **新手引导去信箱时报 AI 失败**：开局固定父亲来电完成后不再立即启动普通手机 AI 节拍，只刷新红点并确定性同步管理任务微信；手机 AI／节拍进行中时正文回合会明确拒绝，防止两个生成通道抢占。
7. **楼务正文消失、工具箱提示与重复弹出**：工具箱从设计上就是永久工具，不会被楼务结算消费。真正缺口是流式正文已经完整显示后底层 Promise 仍可能拒绝，旧失败路径删掉本轮正文并回滚楼务，于是任务再次出现、客户端又按旧进房由头提示工具箱。现在只对具备自然句末、无残缺协议的完整流式正文做失败保留并继续原子结算；半句、协议残片仍失败关闭。楼务成功提交前再次复核权威地点。
8. **角色头像、立绘与在场不一致／无推进时间仍离场**：0.62 后位置仍只按绝对时段与作息推算，没有恢复旧楼层推进移动。聊天中的离场来自“同次拜访连续三轮反感”软规则；旧计数跨房间／跨拜访串联，且实际离场只清部分在场状态。现按地点＋进房令牌计数，人物不在场即清计数，真实离场同时清 `_粘滞` 与 `_在场`，地图头像和舞台不再分叉。
9. **父亲来电后聊天与往事只剩开场父亲来电**：周期父亲通话不会创建宿主往事；只剩开场父亲来电说明第 1 楼之后的宿主消息被物理删除。0.74 新增临时楼转正使用 `setChatMessages(..., refresh:'none')`，酒馆助手真实实现只安排 1 秒防抖保存，Promise 返回不等于 `临时=true→false` 已落盘；而启动／重试恢复会扫描整个聊天并删除所有仍为 `true` 的楼。失败按钮不直接批量删楼，但重试会进入该扫描，因此可能成为触发点。现转正必须等待宿主 `saveChat` 真正落盘并复核两楼均为 `false`；自动恢复只允许删除聊天尾部同一令牌的一条 user 或连续 user＋assistant，多令牌、非尾部、超过两条、角色倒置一律保留并报警。手机小生成同时改为静默，只用于避免绑定全局停止按钮；`generateRaw` 本身不会创建聊天楼层。

## 2. 开工前玩家问题（已归档，处理结果见第 0 节）

1. **微信白屏**：手机壳能打开，但微信正文没有渲染。已定位为 `手机/内核.ts` 没有把唯一注册渲染挂载端口的 `手机/壳/渲染/index.ts` 纳入运行时导入图。
2. **设置缺能力**：主设置页的自定义 API 变量模型只有手填模型，没有读取模型列表，也没有明确“保存／确定”按钮。
3. **好感值／三轴样式优化**：好感、堕落、婚姻样式不统一，也不符合用户想要的视觉。正确设计是“整个数值卡框本身就是进度条”：颜色按 0–100 比例从左向右填充整个框架，标签、数值与堕落说明浮在填充背景上；不能在卡框内再放一条细进度条。三者结构、尺寸、圆角和交互表现必须一致，只用语义颜色区分，并覆盖日间、夜间、手机窄屏与减少动效。
4. **楼务可远程执行**：用户所说“远程瓷砖块”专指没有真正到达任务地点，就出现并能执行楼务处理瓷砖。远处房间只能显示“楼务／逾期”角标；两个处理瓷砖必须到场后才出现、到场后才可执行。
5. **立绘肉眼大小不统一**：用户随后明确为“同一场景两个角色的视觉比例不同”。不是单纯外框宽高问题；普通立绘透明画布宽度不同，`object-fit: contain` 会令宽图先受槽宽约束而缩矮。特殊场景立绘必须保留独立坐标规则。
6. **推进时间后串房正文**：用户随后明确不只小憩，任意推进时间都可能让其他房间记录出现在当前正文舞台。时间反馈只有确实产生本拍新正文时才可更新正文幕归属。
7. **总体风险**：用户判断 rq0.74 丢失了大部分以前修过的内容，要求完整重新审查。不能只修上述六个表象后宣称完成。

## 4. 开工前关键证据（已归档）

### 微信

`手机/壳/渲染/index.ts` 是注册手机挂载端口、红点和父亲 UI 的唯一模块；rq0.74 的 `手机/内核.ts` 未导入它，导致 `已注册端口?.重绘()` 静默空操作。规格在 `.delegate/fix-wechat-white-screen-v075.md`。

### 远程楼务

当前源码和 rq0.74 发布物 source map 中，`useRoomActions.ts::添加管理任务动作` 都有：

```ts
if (当前房间.value !== 地点) return;
```

瓷砖点击前也再次比较同一个 UI ref。因此不能把根因简单写成“条件被删了”。必须复现并追踪：

- `当前房间` UI ref 与 chat `_场景` 权威真值何时分叉；
- `进入()` 在 `写场景()` 之前乐观改 `当前房间.value`，写入失败／取消／回档／并发时是否未纠正；
- 地图房卡在移动、保持地图、旧弹窗和响应式重算时是否持有陈旧动作；
- 后端 `预检管理任务(data, 任务id, 选项id, 地点)` 目前只比较“任务地点”和客户端传入地点，尚未证明会读取 `读场景().房间id` 做硬终审。UI 门失效时后端可能照样接受远程执行。

正确修复应是双层地点门：UI 只负责隐藏，脚本用 chat `_场景` 做最终拒绝；不得只再加一条相同的 UI 比较。

### 立绘

真实所有者仍在 `界面/客户端/App.vue`：`立绘槽()`、`立绘列表`、`.portrait` 与手机全屏媒体规则。普通桌面使用 `contain`，手机双／三人和四人以上使用 `cover`。需要按素材可见 alpha 区域或经审计的角色缩放元数据统一视觉身高，不能直接拉伸位图；荣耀洞等 16:9 特殊件继续走独立规则。

### 小憩串房正文

- 小憩设计：时间事务直接结算，不调用 AI，不生成 `_待发送事件`。
- 当前正文舞台依赖 `当前房间`、`幕房间`、全局 `卷轴` 与从“最后一条玩家行动”截取的 `当前幕`。
- 下一窗口要完整追踪：小憩事件开始 → 时间事务 chat 快照／恢复 → `时间推进结束`／`回合完成` 监听 → `store.pull` → `刷新卷轴`／`幕房间` → `正文卷轴.vue` 可见门。
- 必须复现“在 A 房小憩后出现 B 房旧聊天”，并加入行为测试；不能只加模板字符串断言。

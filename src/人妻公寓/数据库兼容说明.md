# 《人妻公寓》数据库共生说明

数据库插件是可选增强项，不是游戏依赖。没有安装数据库时，地图、回合、手机、经济、背包和角色状态仍正常运行。

## 安装本游戏表

打开游戏手机的“我”页面，点击“安装/更新本游戏表”。游戏只向当前聊天合并四张 `RQ_`
表，保留玩家当前模板中的其他表，不修改数据库的全局模板。

- `RQ_剧情事件`：游戏脚本在回合成功落楼后写入，数据库 AI 不得修改。
- `RQ_人物长期记忆`：保存会影响人物未来反应的长期事实。
- `RQ_承诺与伏笔`：保存待兑现的约定、威胁、欠账、疑点和伏笔。
- `RQ_社交轨迹`：保存有后续意义的微信、朋友圈、邀约和赠礼结果。其中微信邀约结果、父亲来电结论、当面赠礼结果三类由游戏脚本在事件发生时直写（事件键 `RQP-` 前缀，固定措辞模板，不含聊天原文），不经过填表
  AI，因此不受"AI 回复最小长度"自动填表门槛影响；手机聊天不占楼层，填表 AI 本来也看不见。

对应的可手动导入模板是 [人妻公寓数据库模板.json](./人妻公寓数据库模板.json)。手机按钮与该文件使用同一份模板。

## 手机 AI 路由

“自动（数据库优先）”是默认模式：

1. 检测到数据库公开 `callAI` 接口时，由数据库代发手机内容请求。
2. 没有数据库接口时，使用当前正文 API 的 `generateRaw`。
3. 数据库请求已经发出但报错时，默认不再调用正文 API，避免重复请求或重复计费。玩家可以自行开启失败回退。
4. 玩家也可以强制使用数据库、正文 API，或配置独立的 OpenAI 兼容 API。

数据库 8.4 不允许外部读取 API
Key、URL 或完整预设内容。本游戏只使用其公开受限代理；预设名可手填，留空时使用数据库当前配置。

## 数据权威边界

MVU 始终是硬状态的唯一权威，数据库不会控制地图位置、金钱、背包、服装、道具和角色当前状态。生成正文前，游戏只按本场焦点人物筛选少量长期记忆组成“记忆胶囊”，并明确规定与 MVU 冲突时以 MVU 为准。

数据库数据跟随聊天楼层保存。重写或回档时，游戏使用稳定的楼层事件编码执行插入或更新，数据库插件同时按自身的消息删除/滑动监听恢复对应时间线。

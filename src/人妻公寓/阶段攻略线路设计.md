## 一、已经拍板的总原则

### 1. 自由RP不等于自由跳过游戏内容

玩家可以自由聊天、约会、行动和塑造过程，系统不阻止这些内容继续发生。但是，角色的关键成长必须经过设计好的固定攻略线路。

当关系数值抵达阶段门槛前一格，而本阶段线路尚未完成时，负责晋阶的数值被冻结：

| 当前阶段 | 目标阶段 | 晋阶门槛 | 未完成线路时的冻结值 |
|---|---:|---:|---:|
| 贞淑 | 动摇 | 20 | 堕落值19 |
| 动摇 | 越界 | 40 | 堕落值39 |
| 越界 | 沉沦 | 65 | 堕落值64 |
| 沉沦 | 归属 | 90 | 堕落值89 |

玩家仍可获得好感、进行RP和体验普通事件；只有完成该角色当前阶段的固定线路后，冻结才解除。

### 1.1 晋阶叙事必须从“当前阶段上沿＋半档”继续

固定路线不能假设玩家只做过设计文档点名的最低限度互动。只要某种行为属于当前阶段的接受范围，路线就必须按“玩家可能已经把这一阶段玩到最深”来写；晋阶前的铺垫还可以向下一阶段试探半步，但不能提前兑现下一阶段的核心奖励。

| 当前阶段 | 路线默认已经可能发生 | 晋阶前允许推进的“半档” | 仍须留给晋阶的质变 |
|---|---|---|---|
| 陌生邻里 | 职务往来、入户检修、客套帮助 | 对玩家产生私人印象、破例多说一句 | 正式允许私人关系进入生活 |
| 贞淑 | 家常闲聊、单独相处、小礼物与人情往来 | 有意延长接触、短暂不躲、接近接吻但仍停住 | 主动承认心动，开放拥抱与接吻 |
| 动摇 | 拥抱、舌吻、长时间亲吻、隔衣抚摸等不越过入衣和床线的亲密 | 解衣边缘、卧室门口、身体已经愿意但意识最后停下 | 2→3第一夜，真正发生性关系 |
| 越界 | 已经发生过性关系，可能不止一次；基本私密玩法不再新鲜 | 延长停留、有限主动、在安全私域尝试变化 | 从“做但心虚”变为主动经营偷情 |
| 沉沦 | 私下主动、服饰、花样与更大胆地点已经可能发生 | 主动安排风险和招牌性癖的前兆 | 完成角色最深性癖与归属选择 |

因此：

- 禁止在2→3线路重新演“第一次羞涩接吻”；应默认舌吻、拥抱和隔衣抚摸都可能已经发生。
- 禁止在3→4线路把“她主动亲一下”当作重大突破；该阶段的玩家可能已经与她多次发生关系。
- 禁止把阶段0开门礼物、已经送出的服饰或已经演完的事件再次当作待完成任务。
- 晋阶正戏的开场必须承接当前阶段上沿，不能从关系较浅的模板重新起步。

### 1.2 已发生事实只能产生后效，不能要求重演

阶段路线激活前已经由脚本完成的动作，直接作为历史事实使用；玩家在自由RP中可能已经扩写过的内容，后续路线只写新的余波、选择和结果，不复演原场景。

例如`livehouse双人票`是夏乔0→1已经送出的开门礼物。1→2可以写票后来被怎样保存、这件事怎样改变她的日常，却不能再次要求送票，也不能强制重新演一次演出约会。

若系统无法可靠判断自由RP里某个细节是否发生，设计上应绕开重复风险：把硬节点放在新的、脚本可控的后效事件上，而不是尝试让AI判断玩家是否说过或做过某件事。

### 1.3 每条线路增加“节点0：上下文承接层”

固定线路无法预先知道玩家把当前阶段的自由RP演到了哪里。解决方式不是继续猜测，也不是把自由文本直接当作通关条件，而是在四个固定节点之前增加一个不计进度的上下文承接层。

```text
既有事实与近期上下文
→ 节点0选择当前最合适的接入叙事
→ 生成第一条动态关系暗示
→ 节点1开始固定功能线路
```

节点0遵守以下规则：

1. **只承接，不通关**：节点0不占`完成位图`，不增加`1/4`进度，也不能代替道具、调查、时段和地点关卡。
2. **只认已发生事实**：证据优先级为`脚本完成记录 > 特殊场景记录 > 数据库明确经历 > 近期正文明确事实 > 本阶段最高实际尺度 > 当前阶段上沿默认值`。
3. **承接最高事实，不回退表演**：如果已有接吻、抚摸或更深经历，路线只写它留下的后效、矛盾或新选择，禁止重新表演第一次接吻。
4. **不靠关键词直接判通关**：AI负责把事实组织成自然开场；脚本只提供候选事实并继续掌握正式节点完成状态。
5. **信息不足有默认接法**：无法确认历史时，按“当前阶段上沿已经可能发生”处理，但不虚构具体礼物、地点、承诺或性行为。
6. **相互矛盾时保守承接**：明确记录优先于尺度推定；只知道尺度而不知道具体行为时，用“你们已经亲近到不必从客套重新开始”等抽象表达，不擅自补造细节。
7. **上下文必须改变任务内容**：承接层不是在固定任务前加一段回顾，而是让同一节点根据历史换掉动机、对话重点和奖励含义。
8. **“第一夜”是主题节点，不强制是身体第一次**：若可信历史已经确认发生性关系，2→3末节点仍保留相同前置功能链，但正戏改为该角色第一次完成本阶段主题选择（例如夏乔第一次不为日期、许曼君第一次不标价、安若妍第一次完全不留记录），不得让双方假装从未做过。

同一条许曼君2→3线路可以这样接入：

| 已有事实 | 节点0接法 | 固定线路仍然保留 |
|---|---|---|
| 只有暧昧 | 她第一次尝试把无法偿还的人情包装成交易 | 丈夫账目、制造空窗、不记账第一夜 |
| 已有深吻或抚摸 | 她不是第一次靠近，而是第一次试图给既有亲密标价 | 同上 |
| 已发生更深关系 | 她第一次坚持把已经发生的关系写进账本，玩家面对的是“能否被定价” | 同上，晋阶正戏改演拒绝定价后的质变，不重演身体第一次 |
| 玩家曾拒绝交易 | 她带着账本追问“为什么不要我还”，矛盾从偿还转向接受 | 同上 |

关系线索页的第一条也由节点0动态生成，但显示为不带勾选的“当前关系侧写”，例如：

```text
关系线索：0 / 4

· 有些账，似乎早就不是第一次算了。
◇ 他不知道的那一页
◇ 一段被主动空出来的时间
◇ 她仍想给已经发生的事标一个价格
◇ 有一晚，账本必须合上
```

节点0刷新只允许更新这条侧写，不得重置四个正式节点，也不得因玩家反复改写上下文而刷进度。

### 2. 地图功能是全局“游戏动词”，不是某个角色的一次性钥匙

翻垃圾是101裂缝的初始渠道，但不只服务101；摄像头是102裂缝的初始渠道，但不只服务102。以下现有功能都应被编入多条正式阶段线路：

- 翻垃圾
- 安装及查看摄像头
- 街坊打听
- 与丈夫对饮
- 动态广场考古
- 入户检修与工具箱
- 地点事件：大堂、信箱区、管理员室、楼梯间、天台、公共洗手间及各户
- 微信私聊、朋友圈、楼务群、姐妹群
- 催租、宽限、代垫与收租
- 服饰、礼物、人情、运作、药物及特殊场景道具
- 丈夫疑心/信任、丈夫外出安排
- 性癖装载与开幕正戏
- 荣耀洞、雌竞、换装余波等后期功能

功能进入线路的前提是它能继续揭示角色，而不是为了“用到功能”硬塞一次操作。

### 3. 固定线路必须是因果链，不是并列打卡

错误结构：

```text
送礼 → 看摄像头 → 去大堂 → 去天台
```

正确结构：

```text
礼物改变她的日常
→ 经过固定楼数后，摄像头记录到她独处时如何对待礼物
→ 这段观察使玩家能看懂白天大堂里发生的异常
→ 异常事件结束后，脚本预约她下一个晚上去天台
→ 天台谈话完成这段人物变化
```

每一步必须回答三个问题：

1. 玩家为什么要做这件事？
2. 这一步让玩家新知道了什么？
3. 它如何导致下一步发生？

### 4. 可以等待，不可以碰运气

硬门槛只能依赖脚本能够完全掌握的条件：

- 玩家主动操作；
- 已持有或使用指定道具；
- 经过固定楼数；
- 到达固定时段；
- 完成前置节点；
- 进入指定地点后主动启动事件；
- 脚本确定的丈夫状态或由玩家主动制造的外出窗口；
- 脚本必定发送的微信、朋友圈或地点事件。

禁止把以下条件作为硬门：

- 等角色随机走到某处；
- 等AI主动提及某句话；
- 识别玩家自由文本是否“答对”；
- 没有保底的随机事件或随机掉落；
- 只开放一次、错过便永久消失的时间窗；
- 等丈夫恰好随机外出；
- 等随机朋友圈刷出指定内容。

固定时段只控制氛围。错过当晚后，后续同一时段继续开放，永不永久错过。

### 5. 地图瓷砖只负责通知“故事已经准备好”

脚本完成前置条件后，预约角色在下一个合适时段出现：

```text
前置未完成：地图无变化
前置完成、时段未到：关系线索页给出含蓄等待提示
时段到达：地点瓷砖出现角色头像、微光或事件角标
玩家进入：出现一次性叙事按钮
剧情完整演完：节点才登记完成
```

玩家进入天台不是“把角色召唤到天台”。角色已经因前置故事被脚本安排在那里；瓷砖只是告诉玩家可以赴约。

### 6. 奖励不能在第一次点击后立即发放

调查功能至少应有“启动—成熟—读取—后效”中的两到四拍。例如：

```text
安装摄像头
→ 固定6楼采集
→ 记录100%成熟
→ 玩家主动查看
→ 次日出现与记录有关的角色反应
```

```text
第一次翻找发现不明物
→ 固定3楼后角色外观或行为发生变化
→ 再次调查得到可辨认信息
→ 后续地点事件完成解释
```

节点完成的奖励应包含剧情反馈，并推动下一节点；禁止只显示“线索+1”。

## 二、关系线索二级页面

入口放在角色档案的阶段信息与“跨过界线”按钮附近，始终可见。暂定名称为“关系线索”，不使用“任务列表”。

### 页面信息

```text
夏乔｜贞淑 → 动摇
关系线索：2 / 4

✓ 一件让她重新想起自己的东西
✓ 没人看见时，她对它比嘴上认真
◇ 最近几次，她似乎总在一楼磨蹭
◇ 晚饭以后，她偶尔会抬头看向楼顶
```

规则：

- 只给人物化暗示，不显示“去天台”“等待3楼”等系统答案。
- 未发现节点使用含混侧写；节点就绪后暗示变得更接近地点和时段。
- 已完成节点显示玩家实际看见的事实，不显示内部标签。
- 可显示总进度，如`2/4`，但不泄露剧情结论。
- 若数值已经冻结，显示“她似乎还有一件事没有想明白”，不显示“条件不足”。
- “跨过界线”按钮保持可见；未满足时置灰，点击只给人物化反馈。

### 节点状态

每个节点统一使用五态：

```text
未显影 → 已有暗示 → 准备中 → 可触发 → 已完成
```

倒计时和内部条件不直接展示，但文案必须让玩家知道该继续等待还是现在行动。

## 三、线路配置与状态建议

静态配置保存每户、每目标阶段的故事线路；变量只保存当前线路的最小进度。

```ts
interface 阶段线路状态 {
  目标阶段: 2 | 3 | 4 | 5;
  完成位图: number;
  活跃节点: number;
  节点起始楼: number;
  预约时段?: 时段名;
  预约地点?: string;
}
```

不为每个步骤创建独立布尔变量。地图、商店、侦探、微信、经济、性癖等系统在成功动作后统一上报线路事件标签，由阶段线路系统判定是否推进。

节点0不新增持久字段。每次打开关系线索页或启动当前阶段线路时，由现有经历记录生成“当前关系侧写”；正式四节点仍只使用上面的最小状态。为避免同一页面反复跳文案，可在一次页面会话内缓存显示文本，但不得把AI总结作为通关数据。

阶段本身就是已完成旧线路的永久凭证：升入下一阶段后，只保留新阶段线路状态，不长期积累二十四套任务字段。

## 四、六人路线总表 V0.1

说明：

- 阶段0→1完全沿用现有裂缝设计，仅在表中标注，不修改。

1. **没有发布的照片**：固定4楼后翻301垃圾，第一次只发现拍摄废片包装；再隔3楼复查，确认唯独缺少玩家拍的那张。
2. **镜头后的保存位置**：安装摄像头并等待6楼，记录她把拍立得照片放进加密相册旁，而不是扔掉。
3. **大堂临时补拍**：下一个白天大堂出现预约事件。她设备临时出问题，请玩家帮忙掌镜；剧情中玩家拍到一次真正的笑，但不立即给奖励。
4. **她没有要求重拍**：固定2楼后，她把那张没有修过的照片通过微信只发给玩家。演完解冻19。

主要复用：垃圾房多拍、摄像头、大堂、微信图片。

### 2→3 动摇→越界：第一次让镜头彻底关掉

核心变化：她已经接受真实照片，却仍会把亲密变成表演；第一夜必须发生在她主动放弃记录的时刻。

1. **后台不是动态广场**：继续考古到一条非裂缝关键旧动态，结合当前阶段生成“同一场景拍了多次”的新观察。
2. **没人签收的双人份**：使用`物业巡检表`确认江辰长期不在，再到信箱区触发她自己签收“丈夫送的礼物”的固定事件。
3. **关掉自己的设备**：固定到晚上，301出现拍摄准备事件。她起初仍架起相机，玩家进入后由脚本演出她主动关机。
4. **没有镜头的第一次**：接入301的2→3第一夜正戏。结束后解冻39。

主要复用：动态考古、物业巡检表、信箱区、拍摄设备、第一夜。

### 3→4 越界→沉沦：她开始拿真实冒一点公开风险

核心变化：第一夜可以不被记录，但她还在公众面前维持完美婚姻；这一阶段让真实第一次渗进她经营的账号。

1. **你选的衣服**：送出L3/L4服饰，等待换装余波成熟。
2. **没有注明“他送的”**：固定3楼后，她在朋友圈发布穿搭，但第一次没有把礼物归功于丈夫。
3. **评论区的缺口**：再等2楼，动态广场出现一条脚本评论事件；玩家查看她没有补写恩爱话术。
4. **大堂不找机位**：下一个傍晚预约大堂撞场，她当着邻居与玩家说话时没有寻找镜头。演完解冻64。

主要复用：服饰、换装余波、朋友圈、动态广场、大堂。

### 4→5 沉沦→归属：镜头不再替她撒谎，而替她保存真实

核心变化：必须体验招牌性癖`镜头高潮`；路线结论不是“摆脱镜头”，而是夺回镜头的使用权。

1. **装载镜头高潮**：购买并装载，完成专属开幕正戏。
2. **她亲自保留原片**：固定3楼后出现回看事件，由她决定不删除、不剪辑。
3. **公开版本与真实版本**：完成一次朋友圈发布；公开版仍体面，玩家私聊收到未剪版本。两个版本必须由脚本绑定生成。
4. **红点亮着也不是表演**：下一个晚上由她主动布置并预约最终事件，完成后解冻89。现有特殊场景`合拍`作为跨角色扩展奖励，不作为她个人通关硬门。

主要复用：招牌性癖、回看事件、朋友圈、微信私聊、拍摄系统。

## 302 母亲：从“这栋楼的一部分”回到她自己

### 0→1 陌生邻里→贞淑：看见母亲身份之外的她

保持现状：父亲来电两条＋旧动态两条→送一件认真挑给她本人的衣服→破墙。

### 1→2 贞淑→动摇：她第一次把一段时间留给自己

核心变化：衣服让她意识到自己被当成女人看见，但她仍会立刻把一切解释为“儿子孝顺”。

1. **没有围裙的一刻**：破墙后固定4楼，摄像头或回家事件记录她试穿衣服，却在听见玩家脚步前重新套上围裙。
2. **父亲只问了楼**：下一通父亲例行电话由脚本必定加入一段纯楼务话题；玩家接听即可，不等待AI随机提到母亲。
3. **给她空出一个下午**：使用`全楼聚餐`或完成一次楼务安排，替她卸掉当天做饭/照应住户的职责；线路事件固定安排，不依赖她随机离家。
4. **以她自己的名义出门**：下一个下午，302瓷砖出现她已换好衣服的预约状态；玩家陪她完成一次不以买菜、办事或照顾人为目的的外出。解冻19。

主要复用：服饰、家庭摄像/回家事件、父亲来电、全楼聚餐、预约外出。

### 2→3 动摇→越界：现有药物首夜门保持，但补足因果链

核心变化：原设计的安眠药仍是固定关键道具，但不能变成“买药→点晋阶”的单步按钮；必须先演完她如何一步步失去维持母亲身份的借口。

1. **父亲的缺席被确认**：接听下一通固定父亲电话，得到明确的长期不归窗口。
2. **家里第一次不用等人**：使用`外地项目介绍`的母亲线等价事件或完成父亲事务安排，脚本锁定该晚不会有外部打断。
3. **安神助眠剂窗口**：只有前两项完成后商店才上架`安眠药`；购买只是取得钥匙，不完成节点。
4. **首夜与第二天早饭桌**：按现有设计自动消耗药物，先演2→3首夜，再强制完成下一楼早饭桌第二幕。两幕都结束后才解冻39。

主要复用：父亲来电、运作窗口、药物商店、现有首夜、早饭桌第二幕。

### 3→4 越界→沉沦：她不再只用“照顾儿子”解释亲近

核心变化：第一夜后她会拼命把关系重新塞回母子日常；本阶段要让她第一次主动做一件无法用照顾解释的事。

1. **照常做饭**：固定3楼后回家触发日常事件，她把一切演得过分正常。
2. **楼里别人的目光**：使用`节日礼盒全员装`或触发一次全楼互动，姐妹群出现关于她新衣服/状态的固定侧写。
3. **没有递到手里的那碗汤**：下一个晚上厨房事件中，她第一次停下习惯性的喂饭动作，并主动改变相处方式。
4. **她来敲管理员室的门**：固定2楼后，深夜管理员室出现她的预约头像；这次不是送饭、不是提醒睡觉。演完解冻64。

主要复用：302家庭日常、全员礼盒、姐妹群、厨房、管理员室夜访。

### 4→5 沉沦→归属：照顾不再是遮掩，而成为她主动选择的欲望

核心变化：必须实际完成母亲专属`哺育癖`开幕与后效。它不上普通货架，应由故事自然解锁。

1. **一碗汤的变化**：阶段4后固定晚间厨房事件，明确哺育主题已经发生变化。
2. **剧情解锁哺育癖**：事件结束后自动获得可装载项，不通过普通商店购买。
3. **装载并完成开幕正戏**：装载`哺育癖`，完整演出专属开幕，不以装备成功直接计数。
4. **不再把话绕回“妈”**：固定3楼后完成一次她主动发起的家庭后效事件；她不再用母亲职责撤回自己的选择。解冻89。`家宴`保留为多角色后期奖励，不作为母亲个人晋阶硬门。

主要复用：厨房、剧情解锁性癖、哺育癖开幕、家庭后效。

## 六、下一轮细化检查

每条线路进入实现前必须逐项通过：

1. 是否继续推进该角色唯一核心主题？
2. 四节点之间是否存在明确因果，而非并列点击？
3. 玩家是否能主动推动每个节点？
4. 每个等待是否有固定上限和100%保底？
5. 错过时段是否能在下一周期重现？
6. 是否完全不依赖AI自由文本判定？
7. 是否至少复用两个现有功能？
8. 道具是否改变故事，而不是交付即打勾？
9. 性癖是否实际演完开幕与后效，而非仅装载？
10. 暗示页是否能让玩家推断方向，却没有明示操作答案？
11. 节点结束后是否有视觉、微信、地图或角色行为反馈？
12. 是否避免依赖其他角色进度卡住单人线路？
13. 是否按“当前阶段接受上沿＋半档”承接，而没有把玩家关系写浅、重复已经允许或已经完成的行为？
14. 线路引用旧事件时，是否只写新的后效，没有要求玩家重送、重演或重新证明？
15. 是否存在不计进度的节点0，用最高可信历史事实改变节点1的动机与开场？
16. 节点0是否只承接叙事、没有凭AI判断替玩家完成任何固定关卡？
17. 历史不足或冲突时，是否能退回阶段上沿的抽象默认接法而不编造具体经历？
18. 玩家已做过更深行为时，晋阶奖励是否转向主题质变，而非机械重复“身体第一次”？

# 母亲结局《双重继承》：商店启动、终幕后收束与长期后效权威设计（2026-08-29）

> 状态：用户于2026-08-29拍板，作为《回国》与《双重继承》后半段的当前权威设计。  
> 上游：《回国》已经完成母亲入群、玩家经营资格确认、母亲停止替玩家圆场以及父亲愿意回来交接的口头决定。  
> 覆盖范围：本文件覆盖旧设计中“《回国》冻结父亲回国绝对时段并自动启动《双重继承》”“视频第7张直接提交结局”“结局后继续由父亲审核楼务”的规则。  
> 唯一事件名：承接事件《回国》、结局事件《双重继承》。不存在第三个《托付》事件。

## 一、最终结论

母亲线的完整结构为：

```text
承接事件《回国》
→ 商店上架结局场景票《双重继承》
→ 玩家购买
→ 玩家在管理员室使用
→ 玩家到公寓外部迎接父亲
→ 八区公共验收
→ 管理员室完全交权
→ 玩家取得公寓楼总钥匙
→ 三日后的302家庭早餐
→ 父亲离楼并从机场发起微信视频
→ 七张一次性终幕
→ 视频退出到确定性302转场
→ 玩家亲自把总钥匙放到母亲钥匙旁
→ 母亲完成最后收束
→ 《双重继承》原子完成
→ 进入长期结局状态
```

三个核心原则：

1. 《回国》只在人物对话中确认父亲准备回国、愿意回来交接，不保存具体抵达日期，也不按世界钟自动启动结局。
2. 玩家购买并使用《双重继承》场景票，才表示正式交接已经准备好；玩家决定何时进入结局。
3. 视频第7张只证明手机已经交还、视频现场已经结束；玩家完成总钥匙动作后，结局才真正完成。

## 二、《回国》的“回国”只保留口头事实

《回国》仍需要脚本保存路线阶段、父亲消息、母亲入群、母亲转变和完成ID，但不保存：

```text
父亲回国绝对时段
父亲抵达倒计时
自动开启双重继承的日期票
```

父亲最终只表达：

- 海外项目正在收尾；
- 他近期准备回国；
- 他接受自己以交接者而非现任管理员身份回来；
- 玩家把正式交接准备好以后通知他。

母亲最终只表达：

- 玩家准备好后会通知父亲；
- 父亲真正来楼里时，应由玩家走在前面；
- 父亲跟随玩家看公寓当前怎样运行。

《回国》完成只提交：

```text
系统._回国.阶段 = 已完成
系统._已完成特殊场景 += 回国
```

《回国》内部“经营归档发出以后至少隔一日才收到父亲回复”“两条父亲消息之间至少隔一个自然时段”等消息节奏仍由脚本控制。这些是承接剧情内部节拍，不等于保存父亲实际回楼日期。

## 三、商店结局场景票《双重继承》

### 3.1 商品

```text
ID：双重继承
名称：「双重继承」
类别：特殊场景
建议价格：1500
启动方式：背包使用
使用地点：管理员室
```

描述：

> 父亲已经答应回来完成正式交接。一套用于整理签字页、交接回执和总钥匙牌的文件夹。带到管理员室准备妥当，再通知他来楼里。

这笔价格购买的是特殊场景的启动凭证和交接材料，不是购买父亲的认可。认可已经由《回国》的真实经营与人物变化建立。

### 3.2 上架条件

```text
《回国》已完成
《双重继承》尚未完成
系统._双重继承.阶段 = 未开始
背包中没有“双重继承”
当前不处于坏结局
```

购买只执行：

```text
现金 -1500
背包 += 双重继承
```

购买不能让父亲出现，不能改变地图人物，也不能启动公共检查。

### 3.3 使用条件

玩家必须在管理员室从背包使用。脚本再次检查：

```text
《回国》仍然完成
“双重继承”仍在背包
当前地点 = 管理员室
没有亲密场景
没有其他特殊场景
没有场景剧情事务
没有父亲活动电话或待接来电
母亲没有医院硬锁
```

使用成功后：

```text
背包移除“双重继承”
系统._双重继承.阶段 = 待迎接父亲
记录启动楼层
```

不建立绝对抵达日期。玩家在任一后续安全下午前往公寓外部，点击“迎接父亲”，父亲才真实进入本次结局同行状态。

这样玩家可以暂停，也不会发生父亲按旧日期自动出现、日期过期或尚未购买道具却被结局强行抢占的问题。

## 五、视频终幕到普通剧情层的硬转场

### 5.1 为什么不能直接恢复普通输入

视频现场正文使用独立隔离线程，不直接污染普通正文历史；但若第7张完成后立刻开放普通输入，弱模型仍可能被旧正文历史拉回错误场景：

- 误写父亲仍在线；
- 继续成人动作；
- 重复手机交接；
- 把父亲传送回302；
- 一次性补完钥匙、关门和结局；
- 把机场视频的隐秘内容带入普通日常。

因此，退出视频不能依赖模型自行理解上下文切换。

### 5.2 第7张完成后的状态

视频第7张完成只执行：

```text
母亲视频通话状态 = 已完成
父亲通话进入正常收尾
双重继承阶段 = 待总钥匙归位
```

不执行：

```text
双重继承阶段 = 已完成
_已完成特殊场景 += 双重继承
```

### 5.3 确定性转场

视频退出后，正文舞台不显示普通旧正文，而由客户端显示一条不进入长期历史的确定性转场：

> 手机里的画面已经暗下去。机场那头的声音彻底消失，母亲也把手机接回了手中。302里只剩下你和她。

这段只冻结四个事实：

```text
父亲已经挂断
父亲不在302
母亲已经接回手机
刚才的视频现场已经结束
```

在该阶段：

- 玩家仍锁在302；
- 普通输入框不开放；
- 地图、商店和其他功能不开放；
- 只显示一个房间动作。

### 5.4 最后动作

```text
把公寓楼总钥匙放到她的钥匙旁
```

点击以后启动一次性收束正文。模型只读取极短硬快照：

```text
父亲已经从机场挂断并离开；
父亲不在302，也始终不知道母亲与玩家的真实关系；
母亲已经接回手机，视频不会重新接通；
刚才的成人动作已经完全结束，不得继续；
302当前只有玩家和母亲；
玩家正在把父亲交出的公寓楼总钥匙放到母亲钥匙旁；
本拍只演母亲对此的反应和最终确认。
```

禁止：

- 父亲重新说话或回到302；
- 视频重新亮起；
- 继续成人动作；
- 复述整段视频；
- 其他角色进入；
- AI自行宣布系统结局完成。

建议最后一句：

> 楼是他交给你的。这个家，是我自己留下来的。

正文有效落库后脚本才：

```text
从背包移除公寓楼总钥匙
系统._双重继承.阶段 = 已完成
系统._已完成特殊场景 += 双重继承
恢复普通地图、房间动作和正文输入
```

钥匙并列只承担最后一幕的视觉与情感收束，不建立长期环境状态，不在以后每轮提示AI。

## 六、结局后的经济系统

### 6.1 保留

```text
收租
欠租
现金
商店消费
公共楼务
维修费用
住户反馈
风闻本身
经营造成的现实困难
```

### 6.2 永久停止父亲审核

《双重继承》完成以后永久停止：

```text
父亲按期查账
父亲依据楼务、账本、上交、胜任度或风闻质问玩家
最后通牒
父亲收回管理员钥匙
“滚去打工”的管理失败坏结局
漏接父亲电话形成失联责任
风闻责任报给父亲
母亲替玩家向父亲圆场
```

`胜任度`和楼务状态仍可作为公寓内部经营质量，但不再决定玩家是否有管理员资格。

结局后经营不好可以造成：

- 现金紧张；
- 维修拖延；
- 欠租与催租压力；
- 住户抱怨；
- 公共设施问题；
- 风闻和关系后果。

不能再造成父亲收楼或管理资格被取消。

### 6.3 上交

父亲交出的是管理权，不等于自动改变产权。现有业主款可以继续按后台财务流水自动结算，但：

- 不生成父亲报表；
- 不要求口头汇报；
- 不进入通牒；
- 缺口只能形成现金或经营压力，不能重新成为继承资格考试。

## 七、母亲圆场永久结束

《回国》已经完成母亲“不再把玩家当作需要自己向父亲说好话的孩子”的转变。《双重继承》又让父亲退出公寓管理。

因此结局完成时：

```text
清空通牒状态
清空母亲圆场危险轮次
清空母亲圆场事件ID
以后不再生产圆场气泡或父亲转述
```

母亲仍可以提醒玩家、提出意见和参与生活，但不会再为楼务联系父亲、替玩家求情或争取父亲认可。

## 八、父亲长期联络

### 8.1 独立家常模式

结局后的父亲联络不能继续由楼务问责生产器生成。建立独立模式：

```text
双重继承后家常
```

建议固定约每14个游戏日一次，比结局前约每周一次明显降低。未接：

- 不扣胜任度；
- 不形成失联责任；
- 不升级为通牒；
- 不叠加新的楼务内容；
- 保留为普通待接电话。

### 8.2 话题

允许：

- 父亲海外生活与生意近况；
- 身体、饮食、睡眠；
- 节日、亲戚和家庭旧事；
- 玩家自己的生活与未来；
- 母亲普通生活近况；
- 家常托付与转达问候。

禁止主动谈：

```text
账本
上交
维修
租户
公共楼务
胜任度
通牒
管理批准
重新收楼
```

玩家主动提到公寓时，父亲可以以曾经管理过这里的长辈身份简单回应，但不能恢复审批、问责或要求报表。

父亲始终不知情，禁止“早已看穿”“故意成全”“照顾好你妈另有深意”。

## 十、手机、朋友圈与姐妹群的结局期变化

### 10.1 认知不是全员强制全知

手机生成时按真实数据临时构造每名角色的关系层级：

```text
当前攻略阶段
已完成承接事件
已完成结局
已真实落库的姐妹群消息
已真实发布的朋友圈
本人私聊记忆
丈夫认知状态
```

不能因为母亲结局完成，就让所有角色凭空知道其他人的未公开剧情。

### 10.2 《双重继承》完成后的姐妹群首次余波

结局完成后的下一次安全手机节拍生成一次5～8气泡余波：

- 母亲说明父亲已经离开，公寓正式由玩家管理；
- 母亲可以确认自己继续留在302；
- 其他成员按各自真实结局与关系状态回应；
- 已经完成结局的人不得失忆后再次惊讶；
- 尚未完成结局的人不得提前获得未来事实；
- 不提机场视频的隐秘现场；
- 不重新演《回国》茶话会。

使用稳定消息键去重；失败不落键，下次重试。

### 10.3 结局期普通群聊

《双重继承》完成后，姐妹群从“彼此隐约有数却都不说破”进入成熟关系期：

```text
已经在群内公开的关系不再反复试探真假；
争执重点从“有没有关系”转为时间、陪伴、优先级和生活安排；
已完成结局的角色说话更笃定；
羞怯者仍羞怯，但不能失忆；
强势者可以直接争取，不必只靠阴阳怪气；
母亲可以调侃或缓和，但不成为纪律委员；
不得把每轮都写成排班、比色情程度或全员争宠。
```

话题可以自然扩展到：

- 玩家把时间花在哪里；
- 各自结局后的生活；
- 邀约、聚餐、礼物与共同活动；
- 已公开的丈夫态度；
- 共同经历过的真实特殊剧情；
- 谁更了解玩家习惯；
- 母亲进入群后的长期变化；
- 玩家正式成为唯一管理员；
- 节日、生日与未来安排。

### 10.4 称呼

按信息层分开：

```text
公开朋友圈：玩家姓名、管理员或社会上可解释的称呼
姐妹群：玩家姓名、管理员、真实群聊中已经使用过的昵称、符合本人性格的自然昵称
私聊／仅你可见：已完成结局的角色可以使用本人稳定的亲密称呼
```

禁止所有角色统一使用同一个称呼，也禁止模型凭空创造与角色无关的姓氏、身份称谓或公开泄密称呼。

### 10.5 朋友圈

《双重继承》完成后，母亲产生一次公开安全动态，方向为：

```text
父亲已经完成交接；公寓以后正式由玩家管理。
```

公开动态和评论不能暴露母亲与玩家真实关系。姐妹群成员即使知情，在朋友圈评论区也必须使用社会上可解释的口径。

普通朋友圈长期保持公开可解释；仅你可见与私聊可以按角色已经完成的结局更直接。

### 10.6 私聊

不在结局后瞬间让所有角色同时轰炸手机。每名角色在下一次自然主动消息或玩家打开本人私聊时，按自己的结局状态改变口吻：

- 已完成结局：不退回低阶段试探，允许稳定称呼和已成立生活关系；
- 只到第五阶段：保持归属感，但不虚构尚未完成的结局；
- 已有丈夫知情结构：不得让丈夫失忆；
- 未公开事实：仍不得凭空在群或朋友圈说出。

当前已落地可识别差分首先包括夏乔《借种》和母亲《双重继承》；后续角色结局沿同一接口扩展。

## 十二、完成标准

只有以下全部成立，才可称母亲线真正完成：

1. 《回国》不再保存或消费父亲回国绝对时段；
2. 《双重继承》通过商店购买和管理员室使用启动；
3. 父亲不会在未使用场景票时自动出现；
4. 视频第7张结束后进入待总钥匙归位，而非直接完成；
5. 确定性转场隔离旧视频上下文；
6. 玩家亲自执行总钥匙动作；
7. 最后一幕成功后才写入完成ID；
8. 结局后经济继续，但父亲审核、通牒、收楼、漏接扣分和母亲圆场永久停止；
9. 父亲只通过低频家常模式联系；
10. 姐妹群、朋友圈和私聊读取真实结局状态并保持公开层边界；
11. 专项测试覆盖购买、使用、未启动、终幕转场、最终提交、经济分流、父亲家常模式和手机余波；
12. 未经用户明确要求，不正式构建、组卡、commit、tag或push。

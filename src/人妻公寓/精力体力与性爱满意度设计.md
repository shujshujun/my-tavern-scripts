# 《人妻公寓》精力、体力与性爱满意度设计

> 版本：2026-08-01 首轮落地稿
> 状态：Schema v5、结算脚本、时间活动、补给商店、外出地点、HUD、亲密场景面板与首批素材均已实现。
> 上位规则：世界时间仍只认 `系统._绝对时段`；本系统不得恢复消息楼计时，也不得让 AI 直接记资源账。

## 1. 核心职责

三套数值必须回答不同问题，不得互相替代：

| 数值 | 作用域 | 回答的问题 |
| --- | --- | --- |
| 精力 | 玩家当天的现场社交资源 | 今天还能主动发起多少楼面对面互动？ |
| 体力 | 玩家当天的性爱续航资源 | 已进入性爱后还能持续多少楼？ |
| 本场性爱满意度 | 每名参与角色、仅当前场次 | 她在这一场里是否已经满足，可以圆满收尾？ |

硬原则：

- 圆满由本场性爱满意度决定，不以体力归零为条件。
- 体力归零代表失控或特殊结局，不是全角色通用的最优结局。
- 精力上限让玩家一天能铺垫、攻略更多角色；体力上限让玩家一天能承担更多性爱场次。
- 熟悉角色偏好应当比单纯堆体力更高效。

## 2. 术语与计费边界

- **普通现场楼**：玩家主动提交并成功生成的一楼面对面普通交流、暧昧或前戏。
- **性爱开始楼**：本楼首次被可靠判定为实际性爱，场景由普通状态切入性爱状态。
- **性爱楼**：进入性爱状态后，每个成功生成的新现场楼；即使本楼以对话为主，也视为身体行为仍在持续。
- **有效场次**：从性爱开始到正常收尾、失控收尾、角色中止或玩家离场之间的一段连续状态。
- **重掷**：替换同一行动和同一结算，不是新楼消费。

### 2.1 消耗规则

| 行为 | 精力 | 体力 |
| --- | ---: | ---: |
| 普通面对面交流、暧昧、前戏 | -1 | 0 |
| 首次可靠确认的性爱楼 | 0 | -1 |
| 性爱状态中的后续楼（含纯对话） | 0 | -1 |
| 玩家主动选择的最终收尾楼 | 0 | -1 |
| 体力归零后的脚本强制收尾续写 | 0 | 0（最后一点已由触发楼消耗） |
| 微信、朋友圈、手机事件 | 0 | 0 |
| 系统按钮、界面开关、重掷 | 0 | 0 |
| 生成失败后的同行动重试 | 0 | 0 |

补充约束：

- 同一楼只走一种主资源，性爱楼不得同时扣精力和体力。
- 资源只在新楼成功落地后提交；取消或生成失败不扣除。
- 重掷、撤回、删楼和回档必须随现有楼层快照恢复资源与场景状态，不能重复获利或重复消费。
- 强制事件或角色主动开口不应消耗玩家资源；只有玩家主动发起的新现场行动计费。
- 体力为 0 时不能开始新的性爱，但只要仍有精力，普通交流仍可进行。
- 性爱已经开始后，即使精力为 0，玩家仍可继续使用体力完成或收束当前场景。

## 3. 恢复、睡眠与时间事务

- 两项当前值只有成功执行“睡到次日早晨”的睡眠事务后才能完全回满。
- 单纯从深夜点击“推进一时段”跨到第二天早晨，不视为睡眠，不得回满。
- 小憩只恢复部分精力与少量体力，必须调用统一时间事务并推进一个时段，不能成为零时间无限恢复。
- 小憩和普通商店恢复道具都不得把当前值推到完整上限；睡眠保留唯一“完全恢复”权力。
- 小憩首轮定为每日一次：精力恢复 `max(2, ceil(上限×35%))`、体力恢复 1，且两项都钳在“上限 -1”。
- 等级提升或永久上限增加只改变上限，不即时补充当前值；完整新上限要等下一次睡眠才能填满。
- 睡眠、小憩及未来锻炼引起的时间变化必须进入现有时间事务和撤销快照，不能另造旁路时钟。

## 4. LV1—LV5 成长

精力与体力各自拥有 `LV1—LV5`。显示等级与上限从累计训练经验派生，避免同时存储“经验、等级、基础上限”三份可互相矛盾的真值。

建议持久化最小账本：

```ts
玩家资源: {
  精力: { 当前值: number; 训练经验: number; 永久上限加成: number };
  体力: { 当前值: number; 训练经验: number; 永久上限加成: number };
}
```

首轮训练经验门槛：

| 等级 | 累计训练经验 |
| --- | ---: |
| LV1 | 0 |
| LV2 | 3 |
| LV3 | 8 |
| LV4 | 15 |
| LV5 | 24 |

首轮基础上限已经固定：

| 等级 | 精力上限 | 体力上限 |
| --- | ---: | ---: |
| LV1 | 8 | 5 |
| LV2 | 10 | 7 |
| LV3 | 12 | 10 |
| LV4 | 14 | 12 |
| LV5 | 16 | 15 |

永久道具加成在上述基础上叠加；升级和永久加成均不即时补当前值。

### 4.1 精力训练

- 首轮精力训练采用晨跑：从地图底部“外出”进入公寓外部，再前往晨跑公园。
- 同一世界日最多获得 1 点普通精力训练经验，避免把每日流程变成重复点按钮。
- 精力等级只增加面对面互动容量，不直接增加性爱满意度。
- 晨跑只在早上开放，每日一次，成功后推进一个世界时段并提供 1 点精力训练经验。

### 4.2 体力训练

- 健身房锻炼，或当天第一场达到圆满的性爱，可获得体力训练经验。
- 健身与普通性爱共享同一世界日的常规体力训练收益上限；玩家可以自然游玩升级，也可以主动健身替代，不必两项都做。
- 新角色首次圆满、独特特殊场景可以提供一次性额外经验，使用唯一标识防重复。
- 健身房已经作为外出地点落地；锻炼每日一次，显式推进一个世界时段并提供 1 点体力训练经验。

### 4.3 体力等级对满意度的有限加成

体力成长可以缩短满足角色所需的楼数，但不得每楼乘倍率：

- LV1—LV2：无额外满意度加成。
- LV3—LV4：本场首次有效性爱楼额外 `+1` 满意度。
- LV5：本场首次有效性爱楼额外 `+2` 满意度。
- 只有本场开始时当前体力不少于上限的 60%，才触发等级加成。
- 等级加成每名参与角色、每场最多触发一次；多人场景不得按人数反复扣或反复给玩家同一份体能奖励。

## 5. 性爱状态机

```text
普通互动
  └─ 可靠命中性爱开始楼
       └─ 性爱进行中
            ├─ 每个成功新楼：体力 -1；逐角色结算满意度
            ├─ 玩家选择位置并确认：正常最终收尾
            ├─ 玩家选择“停下并收尾”：正常中止
            ├─ 角色明确拒绝或脚本场景结束：角色／脚本收尾
            ├─ 玩家直接离开房间：异常离场并结算关系惩罚
            └─ 体力耗尽且未主动收尾：按当前行为失控收尾
```

进入后不能因为某一楼没有身体开发增量、只出现对话或尺度暂时回落就自动退出。退出必须来自明确收尾事实、场景脚本或玩家离场。

### 5.1 建议场景账本

```ts
系统._性爱场景 = {
  状态: '空闲' | '进行中' | '收尾中';
  场次标识: string;
  开始楼层: number;
  有效楼数: number;
  当前接触部位: '无' | '嘴' | '胸部' | '小屄' | '屁穴' | '其他';
  当前行为: '无插入' | '口交' | '乳交' | '阴道插入' | '肛门插入' | '玩具' | '其他';
  保护状态: string;
  参与者: Record<门牌, {
    满意度: number;
    满意目标: number;
    偏好命中: string[];
  }>;
};
```

字段名是实现建议，可在编码前调整；语义不可丢失。数据结构即使在空闲时也保留空默认值，UI 只在性爱状态显示，以保证刷新、回档和 Zod 裁剪后的状态稳定。

## 6. 性爱开始与当前行为判定

不得新造一套与成人 CG、尺度稽查互相冲突的性爱检测。应复用现有三路证据：

1. 脚本已知的第一夜、性癖开幕、特殊场景及其他明确正戏拍次；
2. 临时尺度判定与玩家行动／正文中的实际行为证据；
3. 身体开发变量在本楼的正增量，作为部位与行为路由的重要证据。

身体开发增量可以帮助判断当前接触部位，但不能成为唯一的持续条件：AI 可能漏记，部位达到阶段上限后也不会继续增长。无新增量时应沿用上楼已经确认的行为，而不是结束场景。

当前行为证据优先级：

1. 玩家刚刚点击并确认的动作或收尾瓷砖；
2. 玩家本楼明确输入的行为；
3. 脚本控制的场景拍次；
4. 本楼身体开发变量增量；
5. 尺度判定与 AI 正文中的硬动作证据；
6. 没有新证据时沿用上一楼。

必须分开保存“接触部位”和“具体行为”。例如“小屄”增长可能来自手、玩具或阴道插入，不能只凭部位增长断言插入事实。

角色高潮和玩家射精也必须分开；普通“高潮”字样可能只指角色，不得因此结束玩家体力状态。

## 7. 本场性爱满意度

### 7.1 生命周期

- 满意度是每名参与角色、每场独立的临时变量，不是角色永久累加属性。
- 多人场景逐角色记账；一人达标不能自动让全员达标。
- 场景结束后清空当前值，可为每名角色保留一条简短的上次结果与完成场次记录，供后续态度和体力训练使用。
- 满意度只由脚本结算，AI 可以读取结果演出，但不得直接写数值或目标。

### 7.2 增长规则

- 每个成功落地的性爱楼为本楼实际参与角色提供基础满意度 `+1`。
- 性爱状态中的纯对话楼同样计算基础满意度，因为上楼身体行为默认仍在持续；若脚本已经确认暂停、拒绝或中止则不加。
- 本场首次命中该角色的偏好行为或部位，额外 `+1`，使用命中表防止重复刷同一偏好。
- 体力等级按第 4.3 节提供一次性加成。
- 未遂、拒绝、生成失败、重掷同楼不得增加满意度。

首轮角色目标基线：

| 角色阶段 | 基础满意目标 |
| --- | ---: |
| 阶段3 | 3 |
| 阶段4 | 4 |
| 阶段5 | 5 |

每名角色可按性格、偏好和场景上下修正 1 点；角色档案另有不同的理想楼数上限，因此进入正向“过久”档所需时长并不相同。

### 7.3 结束评价

- 未达目标主动结束：评价为“太短”，角色按性格表现调侃、理解或不满。
- 达标且处于角色理想楼数区间：评价为“合适”，正常圆满并保留剩余体力。
- 达标且超过角色理想楼数上限：评价名称保留为“过久”，含义是“超满意”，属于明确的褒义档；六名角色分别提供符合人格的正向态度。
- 体力归零：失控特殊结局；保留归零前真实满意度，不自动补满。
- 某些高阶段、特定偏好角色可以喜欢失控结果，但只能作为角色例外，不能成为全局最优策略。

角色态度由脚本先计算结论档，再交给 AI 演出。输入至少包括：

- 本场满意度与有效楼数；
- 主动收尾、体力耗尽、角色中止或突然离场；
- 当前行为与最终位置；
- 角色阶段、好感值、堕落值与专属性格；
- 是否采取保护措施。

## 8. 收尾瓷砖与体力耗尽

### 8.1 玩家主动收尾

- 性爱状态开始后显示收尾瓷砖，选项根据当前行为、角色阶段和道具状态动态过滤。
- 候选包括：停下并收尾、体外、口中、胸前、阴道内、肛内、安全套内等；不可能或未获许可的选项必须锁定或不显示。
- 手机端为防误触，点击瓷砖先选中，再点击一次“确认收尾”；确认后立即启动最终楼，不把偏好长期悬挂。
- 收尾生成失败时保留待确认事实，重试不得再次扣体力或改变位置。

### 8.2 最后一点体力

- 体力剩余 1 时，UI 必须明确提示：“继续一次将耗尽体力；若不主动收尾，将按当前行为失控结束。”
- 玩家仍可在最后一点体力时主动选择合法位置并正常收尾。
- 未选择而继续，成功楼消耗最后一点并进入脚本强制收尾；强制收尾失败可免费重试。

### 8.3 未选择时的原位失控结果

“未选择”不等于凭空切换为阴道内射，而是根据已经确认的当前行为原位结算：

| 当前行为 | 体力耗尽默认结果 |
| --- | --- |
| 阴道插入 | 来不及抽出，阴道内射 |
| 肛门插入 | 原位肛内射精 |
| 口交 | 来不及退出，在口中射精 |
| 乳交、手交、外部摩擦 | 射在当前接触部位 |
| 无插入或行为不明 | 失控体外射精，不虚构插入 |
| 已使用安全套 | 射在安全套内 |

怀孕系统本稿不设计、不计算概率。当前系统只需准确保存参与角色、保护状态、当前行为和最终位置，作为未来接口。

## 9. 突然离场

- 性爱进行中直接点击地图离开或切换房间属于突然离场。
- 离开按钮必须先警告后确认；同时提供“停下并收尾”的正常出口，避免把玩家困在场景里。
- 确认突然离场后，脚本同时降低相关角色的好感值与堕落值，并排队性格化反应。
- 惩罚幅度按是否已经进入插入行为、持续楼数和角色阶段分档；确切数值属于调参项。
- 生成失败、刷新、重掷、回档、脚本中止和角色主动拒绝不得误判为玩家逃离。

## 10. UI 布局与风格

UI 必须延续当前 `App.vue` 的玻璃框、圆角、阴影、字体、场景色、暗色模式和“减少动效”开关，不另造一套悬浮手游皮肤。

### 10.1 顶部资源 HUD

桌面端在现有“日期／现金／胜任／风闻”框架内扩展，建议顺序：

```text
[日期·时段] [现金] [精力 LV] [体力 LV] │ [胜任] [风闻] [待收租]
```

- 精力与体力复用现有电池格瓦片；显示 `LV`、当前值／上限和比例格。
- 精力使用蓝紫色，体力使用胭脂玫红；低于 25% 才进入红色呼吸警告。
- 性爱状态中体力瓦片增加柔和亮边，精力瓦片降低强调度但不消失。
- HUD 不常驻显示训练经验；点击瓦片打开等级、经验、升级门槛和永久加成详情。
- 手机端改为两行：第一行“日期时段＋现金”，第二行“精力／体力／胜任／风闻”；仍在同一 HUD 外框中。

### 10.2 性爱状态面板

面板只在性爱状态出现，并占用正文舞台本身：平时仅在舞台底边保留一条缩略状态栏；点击“管理”后，从舞台底边向上展开抽屉。玩家管理主焦点或收尾时不需要同时阅读正文，因此展开态允许遮住正文舞台，但不能遮住顶部 HUD、行动输入和底部 Dock：

```text
正文舞台（展开时由亲密抽屉临时占用）
当前房间／在场者／离开
【舞台底边：亲密缩略栏／展开抽屉】
收尾瓷砖／行动选项
输入框
底部功能 Dock
```

禁止把它长期放入顶部 HUD；收起态不得长期挤压正文或把整个页面撑高。

详细抽屉内容：

- `PRIVATE SCENE / 亲密场景` 小标题；
- 当前角色头像、姓名、满意度数值／目标和定性文案；
- 体力当前值／上限、当前行为与接触部位；
- 横向收尾瓷砖。

2—5 人共用同一套主焦点队列。缩略栏只显示当前主焦点、全员完成进度与体力；详细抽屉使用可滚动的纵向角色卡，点击任一未完成或已完成角色都可切换主焦点。当前主焦点达标后自动轮到下一名未完成角色；非主焦点只有在正文明确写出本人实际参与动作时才增加满意度。收尾瓷砖采用“选中位置→确认”两步触控，避免误触。

状态演出：

- 进入性爱时只出现舞台底边缩略栏，玩家点击后抽屉从底边向上展开；
- 满意度增加时，花瓣或宝石格逐枚点亮；
- 达标时名牌变为暖金粉，合法收尾瓷砖出现柔光；
- 体力剩余 1 时边缘转暗红并播放克制的心跳动画；
- 结束后短暂显示 `SCENE RESULT` 与结果档，再收起。

内置图像模型只负责透明花纹角饰、和纸底纹、花瓣刻度与瓷砖小图标等无文字位图；所有文字、数值、按钮、状态切换与响应式布局均由 Vue／CSS 实现。

## 11. 实现纪律与验收底线

- 所有资源、等级、场景状态和满意度均由脚本维护；AI 只能按快照演出，不能记账。
- 不用 `localStorage` 保存游戏真值；必须进入现有 stat 快照、回档、重掷和数据库链路。
- 身体开发增量是行为路由证据，不是场景唯一开关，也不是性爱次数。
- 每个有效场次只为体力训练计一次，多人参与不把同一场重复算成多场玩家训练。
- 精力耗尽后手机、朋友圈、系统按钮和重掷仍可用，界面必须给出明确恢复／睡眠出口。
- 性爱开始后由体力接管，不能因为精力耗尽卡死正在进行的场景。
- 多人场景逐角色结算满意度、偏好和结果；不允许一人达标自动全员达标。
- 低体力警告、收尾选择和突然离场确认必须同时适配桌面与手机。
- 所有动效遵守“减少动效”，所有状态同时提供文字／数值反馈，不能只靠颜色。

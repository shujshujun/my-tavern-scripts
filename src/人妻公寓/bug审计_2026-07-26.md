## 🔴 高危

### H1. 重掷 / 回档 / 重开都不还原 `_反感连续`，重掷 3 次能把人永久逼走

**位置**：`脚本/游戏逻辑/回合引擎.ts:278`、`:291`（写）；`snapshotSystem.ts:444`、`:462`（读）

`_反感连续` 是 chat 变量，但：

- 不在 `回合变量键`（`回合引擎.ts:39-53`）→ 重掷不还原；
- 不在 `回档至` 的清理表（`回合引擎.ts:762`）→ 回档不清；
- 不在 `重开一局` 的清理表（`回合引擎.ts:876-893`）→ 跨局残留。

**触发（最容易撞上的恰好是最自然的操作）**：稽查违规 → 吃中断卡（`稽查系统.结算违规代价` 好感-3 → `结算连续反感` 计数+1）→ 玩家当然重掷 → 删楼让 `好感值` 和 `_上次违规楼层` 都回滚（所以违规代价的同楼去重门重新放行、好感重新-3），但计数留着 → 再+1 → 第 3 次触发 `离场`。

**后果**：妻被移出 `_粘滞` / `_赴约`，正文被 `补离场正文` 强行追加一段"转身离开"。另外 `snapshotSystem.ts:462` 在计数 ≥2 时给 AI 注入"她已连续两个互动回合因你的言行降低好感，本轮若仍反感必须演出她告辞离开"——这条警告同样被污染。

**修的时候注意**：正常游玩时该计数会自愈（`回合引擎.ts:284`：本回合好感没降就归 0），所以它只在重掷/回档/重开这三条路上出问题。

### H2. `镜像直写` 没有「回档作废」判定，而且会把过期镜像洗白

**位置**：`脚本/游戏逻辑/守护系统.ts:116-146`（对比 `:75-110` 的 `同步镜像`）

`同步镜像` 有作废判定（`:81` `mirror.楼层 <= floor` 才取大并入）。`镜像直写` 一条都没有：

1. `:119` 无条件读旧镜像；
2. `:131-138` 只对**目标户**取大，`mirror.户` 里其余所有户的旧值原样保留；
3. `:139` `mirror.楼层 = floor` —— 把来自被删时间线的镜像重新盖上当前楼戳。

此后 `同步镜像` 的 `<=` 判定永久通过。

**触发**：`回档至`（`回合引擎.ts:750-778`）刻意不清镜像（注释说交给守护系统的楼层判定）。回档后玩家只要点任意一个 UI 抬升按钮——`翻垃圾`、`读信揭晓`、`偷窥选细节`、`送礼开门`、`请求晋阶`（这些函数都在调用方 `落地`/`脚本写入 → 捕获保护快照` **之前**就跑了 `镜像直写`）——整份旧镜像被重新盖戳，紧随其后的 `捕获保护快照 → 同步镜像` 就把旧时间线的阶段/堕落/碎片/裂缝确认/情报可见 `Math.max` 并回快照，下一回合 `回滚保护字段`（`:234`）写进新时间线。

**后果**：回档作废语义被绕过，**不只被点的那户**，整份旧局镜像复活。`重开一局` 的注释（`回合引擎.ts:863-864`）其实已经承认过"镜像直写不校验楼层作废"，那里靠显式清镜像绕开，回档路径没有。

### H3. 后续入住户开局倒收 / 倒欠多期房租（真实楼 vs 钟楼单位混用）

**位置**：`脚本/游戏逻辑/经济系统.ts:61`（读）vs `入住系统.ts:92-94`（写）

- `经济系统.ts:61`：`期号 = Math.floor((现钟 - 节点._入住楼层) / 期长)`，其中 `现钟 = 楼层 + data.系统._时段偏移楼`（`:39`、`:51`）。
- `_入住楼层` 存的是**真实楼**：`入住系统.ts:92` `创建配置户节点(目标, 楼层)`，`楼层` 来自 `回合引擎.ts:526` 的 `生成楼层`。

`收租周期 = 25`（`stageConfig.ts:1017`），`杀时间` 每次 `_时段偏移楼 += 3`（`楼层时钟.ts:54`）。

**触发**：201 的入住条件是 101/102 到阶段2（`入住系统.ts:20`、`:87`），这中间玩家用过若干次 `杀时间`，偏移很容易攒到 25~75。搬入后的**第一个 AI 楼**（`经济结算` 在 `回合引擎.ts:512`、`入住检测` 在 `:526`，所以是次楼）算出 `期号 = Math.floor(偏移/25) ≥ 1`，而 `_上次收租期 = -1` → `笔数 = 期号`。

**后果**：201（月租 900、`天生欠租`）开局凭空背 N 笔欠租，立刻弹"得上门催了"并在上交日吃 `欠租每笔扣分`；202 / 301（1100 / 2200）白拿 N 期房租——偏移 75 时 301 直接进账 ¥6600。首批户不受影响（`_入住楼层 = 0`，与 `全局期 = floor(现钟/期长)` 同轴，杀时间加速收租本身是设计意图）。

**修的时候注意**：`入住系统.ts:88` 的 `楼层 - data.户['201']._入住楼层 >= 二批错开楼` 按**真实楼**语义读同一个字段。两个读者单位不同，改哪边都得同时调另一边。

### H4. `floorMark(-999)` 被自己的 transform 夹成 -1，荣耀洞开局就报「今天已经用过了」

**位置**：`schema.ts:35-40`（`floorMark` 定义）、`:218`（唯一受害字段）

`floorMark` 的 transform 是 `Math.max(-1, Math.round(v))`，而 zod 的 `.prefault(def)` 会让默认值走完整管道，哨兵值被自己夹掉。

**实测（仓库自带 zod 4.3.6）**：

```text
floorMark(-999).parse(undefined) = -1
floorMark(-999).parse(-999)      = -1
```

`_荣耀洞上次楼`（`schema.ts:218`）是全项目**唯一**默认值低于 -1 的 floorMark，也正是唯一需要 -999「从未用过」语义的字段（冷却窗口 18 远大于 1）。其余 15 处 floorMark 默认值都是 -1，不受影响。

**后果**：`荣耀洞.ts:91-92` 的 `钟楼 - 记 < 荣耀洞冷却楼(18)`：钟楼=1 时 `1-(-1)=2 < 18` → 恒真。**新游戏整个第一天招牌功能不可用**，且提示语是误导性的"今天已经用过了——这种事,一天一次是隔间里不成文的规矩。"。客户端 `App.vue:1949` 的 `?? -999` 兜不住（存的是 -1 而非 undefined），所以按钮**直接不出现**。脚本与客户端同步失效。

计算：钟楼 ≥ 17 才可用。每回合 +2 楼，即约前 8 个回合不可用。

## 🟠 中危

### M1. 冷落事件每楼重复排队，且在管理员室永远无法自愈

**位置**：`脚本/游戏逻辑/结算系统.ts:219-233`

命中后只写 `data.系统._待发送事件`，**既不推进 `上次互动楼层` 也不落任何已发标记**。而事件通道在本楼开头就被转存清空（`回合引擎.ts:499-502`），`冷落检测` 又排在 `回合结算` 最后（`:544`），所以 `:220` 的 `if (data.系统._待发送事件) return` 拦不住下一楼。

**无法自愈的证明**：`上次互动楼层` 全项目只有两处推进（`回合引擎.ts:492`、`index.ts:851`），都要求该户在 `妻在场` 里。地图模式下 `妻在场` 要求 `粘滞命中 || 妻位置推算(m, 种子楼) === 房间id`（`snapshotSystem.ts:173-174`），而 `妻位置推算`（`楼层时钟.ts:126-157`）的返回值只可能是 **门牌号 / 天台 / 垃圾房 / 大堂 / 楼梯间 / 外出**。玩家待在 **管理员室**（正是杀时间的地方）、信箱区、洗手间时，任何人都不可能被判在场；`_粘滞` 又只能从上一轮非空的 `妻在场` 引导（`回合引擎.ts:332`），无法自举。

**后果**：只要有一户阶段≥2 且 `距 ≥ 25`，【她来找你了】就在**每个 AI 楼**重新注入，AI 只能让她一遍遍下楼。只有 `打断检测` / `绿帽线检测` / `入住检测` / `换装起疑` 抢到通道的楼才被压住。

# 《人妻公寓》AI 状态快照矩阵审查（2026-08-03）

本文件记录本轮对单人、双人、3—5 人和不同场景提示上下文的审查结果。源码与自动测试是运行真值；这里只保留结论、已修问题和仍需处理的边界。

## 一、已经闭环

| 场景             | 当前结果                                                                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 普通单人         | 只给本人日常状态、简尺度协议和本轮日常约束，不加载亲密账本。                                                                                     |
| 单人亲密         | `_性爱场景` 是硬真值；玩家只说“继续”也保留当前行为、部位、保护、满意度、人格和边界。                                                             |
| 双人亲密         | 持久 `主焦点门牌` 排第一；两人均得到本人状态、成人表现和各自边界。                                                                               |
| 3—5 人亲密       | 全部参与者进入同一焦点真值；主焦点优先，其他人使用紧凑状态块，不受普通“一主两次”上限截断。                                                       |
| 结构化多人事件   | `【事件在场妻／夫】` 冻结实际演员；未点名角色不混入现场。                                                                                        |
| 录像带／静音会议 | 作为独立脚本场景：保留演员人格、情绪和边界，但不输出普通尺度协议，不创建或推进体力／满意度性爱账本。屏幕、录像、回忆和转述不算管理员室现场行为。 |

本轮修复的三个高优先级问题：

1. 亲密参与者归一化原本只发生在快照文字内部，回合审计、变量守护和结算仍可能使用地图首人。现在归一化已经并入 `检测焦点`
   的统一出口，两条正文路径取得同一主焦点与完整参与者名单。
2. 持久特殊场景原本可能因 AI 报告尺度 `3—5` 而污染普通
   `_性爱场景`。现在录像带前置、录像带和静音会议使用显式独立结算策略；已实现的特殊场景启动口也会拒绝与进行中的普通亲密场景重叠。
3. 世界书变量基线不再注入全体住户与全局存档；每楼只提供焦点且本人在场者的可写叶子。日常楼不提供堕落／身体开发，独立脚本场景为空户表。角色长档案采用“完整→最小→最小→完整”成功楼节拍，换场、换焦点、人物进出、亲密或边界变化即时完整刷新。

0.65 发版复审继续闭环：

4. 普通4—5人地图场景保留全部真实在场者；本轮点名优先，未点名的“继续”承接上一轮仍在场焦点，换房／离场自动失效。
5. 亲密写权细分到逐妻参与者；旁观者只保留日常字段。首次入住、独立特殊场景和坏结局均为空写权。
6. AI可写心理、情绪和着装文本统一压成短单行，并钝化提示边界字符；渲染侧再次规范。
7. 亲密路由不再使用“亲密、床上、越界、高潮、暧昧”等裸名词，只认结构化亲密状态、脚本事件或明确人物／身体动作。
8. 外置MVU请求沿用冻结范围，外置终值不会再被本地 `parseMessage` 二次应用；热重载初始化与无快照手动重处理均已补上守护。

## 二、仍需完善

### S02 丈夫三级打断与普通亲密收尾

- 三级打断要求强制离场，但普通亲密提示又要求不得自行结束。
- 需要给事件增加结构化“终止普通亲密”元数据；一级、二级保持场景，三级确定性结束且本楼不增加满意度。

### S05 主路径与原生路径的记忆上下文

- 固定 0 楼主路径会拼接数据库、微信摘要和近期微信；原生路径尚未完全复用同一个安全胶囊构建器。
- 多人私聊摘要按顺序占用总额度，后排角色可能失去连续性；后续应主焦点优先并公平分配额度，同时保持每人的私密信息隔离。

### S06 荣耀洞隔离演员胶囊

- 隔离线程已有匿名纪律和固定拍，但缺少当前角色的人格、情绪、衣着、婚姻语境与阶段边界。
- 后续应增加只读角色胶囊，不提供精确机制数值，也不放宽匿名身份纪律。

### S08 通讯例外

- 快照规定微信只由手机系统发生，但丈夫打断事件仍可能要求在正文直接出现丈夫私信。
- 应改成结构化系统事件例外，或先写入手机消息库、正文只演通知。

## 三、验证矩阵

自动回归覆盖：

- 单人亲密中性“继续”不降级日常。
- 双人主焦点排序与双方边界。
- 五人提示、审计和结算焦点同源，五人快照长度小于 `20,000` 字符。
- 普通单人保持精简协议。
- 结构化多人事件只出现冻结演员。
- 录像带与静音会议不输出普通尺度协议；即使伪造尺度 `5` 也不建立普通性爱账本。
- 普通亲密进行中无法启动录像带前置、录像带或静音会议。
- 普通五人点名切焦与连续对话焦点保持；显式空地图不从历史姓名复活演员。
- 亲密参与者和旁观者的逐妻写权隔离；首次入住两路只读。
- AI表现文本伪系统块被单行化、限长和边界钝化。
- “床上床单、不要越界、亲密关系、音乐高潮、裸体艺术、上床睡觉、讨论体位、调教设备”等日常语句不开放成人写权，明确人物动作仍进入详尺度协议。
- MVU外置终值只采用一次；辅助请求不递增正文轮令牌；手动重处理无内存快照时按旧值全量恢复。

## 已确认并集中修复的 BUG

### BUG-090C-001：数据库旧时间线失效后仍从当前楼空转扫描到第 1 楼

1. **设计初衷**：数据库补写是回合完成后的可选后台任务；一旦切聊天、回档或时间线身份变化，应立即停止，绝不能继续占用前台。
2. **正常链路**：逐楼扫描时，`已记录.has(楼层)` 只跳过这一楼；`提交校验()` 失败则应结束整个旧任务。
3. **游戏影响**：`补齐缺失数据库事件骨架` 的截止楼层可等于长档当前楼。旧任务在一次 SQL `await` 后失效时，剩余循环会同步执行到第 1 楼；超长档可能在切聊／回档时出现无意义 CPU 空转和界面卡顿。
4. **根因**：代码把 `!提交校验()` 与 `已记录.has(楼层)` 合并在 `continue` 条件里，错误地把“整个事务作废”降级成“只跳过当前楼”。
5. **复现与修复**：以 10001 条消息构造“入口校验有效、进入循环后立即失效”的后台任务，旧代码会完整空转到底。现已把事务失效拆成 `return 已补写`，只有“本楼已记录”继续 `continue`；不回滚已获 SQLite 确认的写入，也不继续广播。

### BUG-090C-002：独立事件 generateRaw 永久 pending 时，取消也不能释放前台生成租约

1. **设计初衷**：睡眠、监控、荣耀洞等独立事件生成失败或取消时不提交正文／时间／任务，并立即恢复其他玩法。
2. **正常链路**：取消或超时解除本地等待；底层即使迟到也只能被丢弃，`finally` 有界释放 `生成中` 与前台租约。
3. **游戏影响**：供应商请求若不响应 `stopAllGeneration()`，睡眠会一直处于生成态，时间无法推进，主正文和其他独立事件也永久被共享前台锁拒绝，只能刷新页面。
4. **根因**：正文通道直接 `await generateRaw`，没有看门狗或本地取消 Promise；`取消隔离事件` 只设 `已取消=true` 并调用宿主停止，必须等原 Promise 返回后才会检查取消旗并进入 `finally`。
5. **复现与修复**：永不 settle 的 `generateRaw` 下，旧取消不会释放租约。现新增共享“受控生成等待”：取消立即拒绝本地等待，正文通道十分钟绝对保险，按请求 ID 尽力停止底层；迟到结果不能复活，`finally` 有界释放。数据库通道仍服从独立租约与不二次计费规则。

### BUG-090D-001：独立事件请求与流式边界读取了两套不同的预设启用状态

1. **设计初衷**：睡眠、监控等独立事件应复用玩家当前预设中真正启用的提示词，并按 `chatHistory` 分成前后两段；流式正文边界也必须依据同一套生效提示词。
2. **正常链路**：SillyTavern 的权威启用状态和顺序来自 `prompt_order`；没有该结构的旧预设才回退 `prompts.enabled`。
3. **游戏影响**：`隔离事件引擎` 是 `预设破限段` 的生产消费者。当前可能把玩家已经关闭的旧词条发给睡眠／监控，同时漏掉当前启用的新词条或正文封套，造成输出协议与流式验收不一致，表现为思维链泄漏、正文被判空或睡眠无法推进。
4. **根因**：v0.90 新增 `读取预设启用词条` 并用于正文标签／流式边界识别，但旧 `预设破限段` 仍直接遍历 `预设.prompts`、检查 `p.enabled`，没有复用权威合并结果。
5. **复现与修复**：替身中旧请求会发送 `old` 且漏掉 `new`；13 份真实预设进一步证明影响。现已让 `预设破限段` 与流式边界共用 `读取预设启用词条`，保留无 `prompt_order` 的旧预设回退、`chatHistory` 分段、`in_chat` 后置、原顺序和本拍宏覆写。

### BUG-090D-002：正文纯文本转换把普通尖括号叙事误删成 HTML

1. **设计初衷**：最终显示正则可能产出 HTML/CSS/脚本外壳；游戏只应移除真实标记并保留玩家可读的故事文字。
2. **正常链路**：明确的 `style/script/iframe` 和合法 HTML 标签被清理；数学比较、门牌文字、昵称或其他普通尖括号内容必须原样保留。
3. **游戏影响**：`转为正文舞台纯文本` 同时进入玩家显示门和业务成功门，误删会让玩家看到残缺正文，并让后续变量／事件结算依据与模型原文不一致。
4. **根因**：最后的通用规则使用 `<[^>]+>`，没有验证标签名和 HTML 形状；它会从任意 `<` 一直吞到下一个 `>`。
5. **复现与修复**：旧代码会破坏比较式与 `<请勿打扰>`。现改为只移除白名单 HTML 标签及明确危险外壳，保留未知尖括号文字、比较符和 `<3`；实体、段落换行、未闭合 style/script、SVG 与真实美化 HTML 均有反例。

### BUG-090D-003：正文显示正则会改写微信气泡并可破坏语法

1. **设计初衷**：手机有自己的 `<回复>` 完整性协议和硬编码机器标签清理；玩家的正文预设不能把微信拉成长篇或泄露思维链。
2. **正常链路**：手机只抽取完整通讯封套并清理已知协议，保留模型实际生成的口语内容。
3. **游戏影响**：`净化消息` 额外调用 `formatAsTavernRegexedString(..., 'ai_output', 'display')`，而这些显示正则通常为小说正文删词、美化或改写，最终会直接改变所有私聊、群聊、朋友圈和父亲通话文本。
4. **根因**：把“沿用正文正则以清协议”与“保留手机内容语义”绑在一起；显示正则没有只删除协议的能力声明或白名单。
5. **复现与修复**：13 个用户预设×30 条自然微信共 390 组，15 组被改写并出现病句。按真实 A/B 拍板，手机现完全绕开小说正文显示正则，继续保留 `<回复>` 完整封套、手机自己的思维／机器协议清理、半句话拒绝、消息顺序与计费／重试语义。

### BUG-090D-004：睡眠／监控等隔离正文会把美化 HTML 标签当普通文字保存和显示

1. **设计初衷**：所有游戏正文舞台只显示故事纯文字，不复制预设 HTML/CSS/动画；隔离事件也应服从同一呈现边界。
2. **正常链路**：显示正则处理后，真实 HTML 结构转为换行和纯文本，再写入隔离日志。
3. **游戏影响**：使用 `span/section/strong/br/details` 等美化正则时，睡眠反馈、监控和荣耀洞史册会出现字面 `<span>...</span>` 标签，且这些内容会长期存档。
4. **根因**：`净化隔离事件正文` 自行维护另一套清洗，只删除完整 `style/script` 和 `p/div` 标签，没有复用主正文的纯文本转换边界。
5. **复现与修复**：上述输入旧代码会保留字面标签。现已在既有思维／机器协议清理之后复用修正后的 HTML→纯文本能力；未完成正文仍失败关闭，不写日志、不结算时间。

### BUG-090F-001：同楼 swipe 延迟裁枝会删除切换后刚写入的新分支微信

1. **设计初衷**：明确 swipe 后删除旧分支在该楼产生的微信／朋友圈／稳定键；切换完成后新分支产生的内容必须保留。
2. **正常链路**：swipe 监听同步作废旧手机租约，后台协调完成后只裁旧分支记录；协调期间要么冻结新写入，要么以事件前截止序号区分新旧。
3. **游戏影响**：监听使用下一任务拍和共享 MVU 队列收口，期间手机发送、自动通知等没有统一的 `时间线切换协调中` 写门。玩家在新分支刚发出的消息可能先显示，随后被旧协调任务删除。
4. **根因**：`裁同楼切分支记录` 对 `条.楼 === 切分支楼` 的所有带锚记录一律删除，隐含“裁枝前不可能出现新记录”的假设，但实际协调是异步排队的。
5. **复现与修复**：新分支消息先写入时会被同楼裁枝删空。现于唯一 `写库增量` 入口在进入变量队列前和 updater 提交前双重检查同步协调锁；协调期间新手机写入失败关闭，原有真实 swipe 对旧无锚自动内容的隐私优先裁枝保持不变。

### BUG-090B-001：手机正文／自定义 API 永久 pending 会永久占住全局生成槽

1. **设计初衷**：手机短生成与主正文共享生成槽；成功、失败、取消、超时和供应商永久 pending 都必须有界结束并释放租约。
2. **正常链路**：请求在独立时限内完成；超时只判本条失败，不写半句，`finally` 释放手机租约，主正文随后可继续。
3. **游戏影响**：一笔永久悬空的微信、朋友圈或父亲通话请求会让 `手机AI生成中()` 永久为真；玩家所有正文回合持续被“手机后台消息正在生成”拒绝，只能刷新页面恢复。
4. **根因**：数据库手机通道经 `全局数据库AI租约` 有 90 秒门，主正文有看门狗；但 `正文API生成` 和 `自定义API生成` 直接 `await generateRaw`，没有 `Promise.race` 超时或可解除等待门。租约只在 `小生成` 的 `finally` 释放。
5. **复现与修复**：永不 settle 时旧手机租约永久占用。正文／自定义两路现共用四分钟绝对保险和请求 ID 定向停止；切聊／回档／红灯取消令牌失效会主动结束本地等待，迟到结果不能复活。手动批次外部 ID 原样保留，单次请求、自动同路线重试和不二次计费语义未变。

### BUG-090A-002：借种 CG 已展示集合跨聊天残留，会压掉另一存档的同场次画面

1. **设计初衷**：同一场借种中的同一关键帧只展示一次；切换聊天后所有场景瞬态必须重建，不能共享“已看过”状态。
2. **正常链路**：`CHAT_CHANGED` 清当前借种画面、队列、来源键和已展示集合；新聊天第一次收到 CG 信号时按本聊天场次重新展示。
3. **游戏影响**：两个存档可能在相同绝对时段和相同楼层进入借种，生成相同 `借种结局:101:<时段>:<楼层>`。B 档会继承 A 档的已展示集合，对应专属 CG 不再出现。
4. **根因**：`客户端聊天切换` 只执行 `当前借种CG.value = null`，没有调用完整清理，也没有重置 `借种CG来源键` 和 `借种CG本场已展示`；去重键本身不含聊天 ID。
5. **修复**：新增完整场次瞬态清理并在 `CHAT_CHANGED` 调用：清当前画面、队列、来源键和已展示集合；全局 CG 解锁收藏不动。相同场次字符串跨档也会重新展示。

### BUG-090A-003：借种结局后的监控纪律接在不可达分支，日常观察不承接结局事实

1. **设计初衷**：借种结局后再看 101 监控，应持续承认陆嘉明知情、三人家庭关系、真实照片与孕产状态，禁止退回“丈夫受骗／父亲未知”。
2. **正常链路**：裂缝确认后的 `构造监控日常观察` 应把借种后果加入提示和观察签名；结局、三人照或产后照变化应形成新的可观察状态。
3. **游戏影响**：当前日常监控只得到通用婚姻／孕产方向，模型可能把陆嘉明写回普通不知情丈夫；若阶段与数值档未变，旧的已见签名还可能直接压掉结局后的新观察。
4. **根因**：`借种结局监控提示(data)` 只拼在裂缝尚未确认的四拍调查返回值里；裂缝已确认分支在此前已经构造观察并返回。正常借种完成档必然走已确认分支，使专用提示成为实际不可达消费者。
5. **复现与修复**：构造合法完成档时旧日常不含借种纪律。现只在裂缝已确认后的 101 日常观察接入系统硬事实，并仅在借种后果存在时给旧八段签名追加后果哈希；非借种旧档签名完全不变，照片变化可开放一次新观察，裂缝四拍不提前泄露。

### BUG-090H-001：当前 0.90 的存档拒绝提示仍自称 v0.86，并漏列 0.86～0.89

1. **设计初衷**：非空损坏、过早或未来数据版本必须失败关闭，同时告诉玩家当前游戏实际支持哪些旧档。
2. **正常链路**：验证仍按数据版本 7／8／9；提示使用当前发布口径，不能与游戏版本号手工漂移。
3. **游戏影响**：合法旧档不会被误拒绝，但玩家遇到坏档或未来档时会看到错误版本与不完整兼容清单，容易误判自己装错版本。
4. **根因**：`schema.ts` 在 rq0.86 手工写死 `v0.86` 和“列到 v0.85”，后续发布只更新了游戏版本常量，没有统一这条错误文案；一项源码测试还显式断言旧字符串。
5. **复现与修复**：0.90 旧提示仍以“v0.86”开头。现改为不随角色卡小版本漂移的“当前版本仅兼容数据版本 7、8、9”；拒绝条件、数据版本和迁移逻辑完全不变。

## 已确认 BUG

### BUG-090A-001：借种阳性邀约重复已读会反复伪装成存档变更（用户要求暂停边审边修前已完成修复）

1. **设计初衷**：借种报孕微信只是一张赴 101 看检测结果的邀请。玩家真实读到后登记一次持久“邀约已读”，但孕情继续保持 `待告知`，直到三人真实同场确认。
2. **正常链路**：消息真实已读 → 首次登记 `借种:阳性邀约已读:<场次>` → 调用层因返回一项变更而写档一次；后续手机状态、挂载或切聊重建重复同步应返回空。
3. **游戏影响**：该同步由客户端挂载、聊天重建和手机状态刷新触发；非空返回会让 `同步孕产微信已读` 再次调用 `脚本写入` 和保护快照。
4. **根因**：普通报孕以 `待告知→已告知` 状态迁移天然幂等；借种为了等实地确认不迁移状态，却遗漏了对已经存在的 `借种阳性邀约已读` 持久键的前置判断。
5. **修复与兼容**：借种分支登记前先检查同场次已读键；已读旧档直接返回无变更，首次读取、保存失败重试、实地阳性确认和普通报孕均保持原语义。没有数据迁移。

复现测试先得到 `actual=['101'] / expected=[]`；最小修复后，`夏乔借种结局`、`怀孕系统`、`孕产手机胎次反应`、`微信跨状态生命周期修复` 共 67／67 通过。

## 已发现但尚不能判为 BUG 的设计歧义

- 借种启动会清除已经消费一枚安全套形成的 `保护准备`，以保证本场不带保护；当前没有退款或玩家提示。设计资料只明确“安全套不能完成借种”，没有明确拆封道具是否应返还。未经产品语义确认不修改，后续在玩家资源消费者审查时继续判断。
- 完整提示词快照会随最多 60 条监控／荣耀洞叙事长期存入 `_隔离事件`。13 份用户预设按当前错误的 `prompts.enabled` 统计，单份实际快照提示词最高约 2.35 万字符，60 份约 141 万字符（UTF-16 文本约 2.7 MiB，未计 JSON／正文）；目前只有条数上限、没有总字符上限。用户明确要求历史提示词可查看，因此先记为存档体积风险，不在没有实测卡顿／保存失败前判为 BUG。
- rq0.88 在 `GENERATION_STARTED` 入口用无条件 `return` 关闭原生正文逃生路径，但保留了其后整段不可达实现；多项源码契约测试仍只匹配这段死代码里的字符串与顺序。当前游戏入口不依赖该路径，因此不判玩法 BUG，但这是明确的验证盲区，后续整理时应删除死代码或让测试验证真实可达行为。

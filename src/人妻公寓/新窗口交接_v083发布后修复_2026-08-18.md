## 四、最近完成：`RQ_剧情事件` 无法更新与假成功提示

### 现象

玩家已经安装数据库插件和五张游戏表，首次准备页却显示“全部完成”；实际 `RQ_剧情事件` 长期不更新。回合结束时界面还会无条件显示“数据库记录完成”。

### 设计边界

`RQ_剧情事件` 不是填表 AI 自动维护的表。模板中自动更新频率为 `0`，该表只允许游戏脚本通过 SQLite mutation 写入。不能恢复普通 `insertRow` 兜底，否则重 ROLL、回档或切分支后可能把事件挂到旧消息时间线。

### 根因

1. 首次准备页旧判定只检查“插件已安装＋五张表已安装”，没有检查 SQL 查询接口、`executeSqlMutation` 和当前 SQLite 运行时是否真的就绪。
2. `记录数据库回合()` 旧代码没有检查 `同步数据库回合()` 的布尔返回值，并在 `finally` 中无条件显示“数据库记录完成”。

### 已完成修复

新增统一的脚本写入能力模型：

```text
src/人妻公寓/脚本/游戏逻辑/数据库脚本写入能力.ts
```

它明确区分：

```text
数据库未安装
游戏模板未安装
缺少 SQL 写入接口
缺少 SQL 查询接口
SQLite 未就绪
就绪
```

数据库桥新增权威检测入口：

```text
检测数据库脚本写入能力()
```

它把静态 API 能力与真实 `SELECT 1 AS ok` SQLite 探测合并，供首次准备页和回合写入失败说明共用。

首次准备页现在只有在以下条件全部满足时才显示“全部完成”：

- 数据库插件存在；
- 当前聊天安装了五张游戏记忆表；
- SQL 查询接口存在；
- `executeSqlMutation` 存在；
- SQLite（SQL）运行时真实就绪。

否则主步骤直接显示“开启 SQLite（SQL）存储”，并提供“打开数据库设置”和“重新检测写入能力”。

回合写入现在：

- 成功时显示“数据库记录完成”；
- 失败时显示“数据库记录未写入”；
- 弹出具体原因：`⚠ RQ_剧情事件未写入：…… 本轮正文与游戏结算不受影响。`；
- 同一种失败在同一聊天内只提示一次，恢复成功后重置失败提示签名；
- 时间线已经变化时仍按事务规则中止，不把取消误报成数据库配置错误。

主要修改：

```text
src/人妻公寓/脚本/游戏逻辑/数据库脚本写入能力.ts
src/人妻公寓/脚本/游戏逻辑/数据库桥.ts
```

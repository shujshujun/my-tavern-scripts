## 一、最终方向

302在《双重继承》后进入的核心状态定为：

> **共居。**

母亲原本就住在302，因此“母亲继续留在302”本身不能算结局后玩法。结局后真正发生的变化是：

1. 她留下是自己的决定，不是继续履行等待丈夫、照顾儿子和替儿子圆场的旧职责。
2. 玩家与母亲从单向照顾关系进入真实共同生活：双方都需要说明安排、兑现约定、承担家务、照顾对方，也允许出现生活分歧。
3. 已经成立的关系不会因普通冷落或一次争执失效，但共同生活的温度、情绪和相处质量仍会改变。
4. 302不重做新地图；通过时段动作、轮换环境痕迹、手机反馈与持续记忆，让玩家实际感到两个人正在一起生活。
5. 《双重继承》只令“管理考验”和“302母亲线”进入自由阶段；其他尚未完成的住户线路、经济、楼务、孕产、衣柜和通用生活系统继续运行。

三个概念必须分开：

- **结局完成事实**：稳定，不被普通关系波动推翻。
- **共同生活质量**：持续变化，可以亲近、平淡、闹别扭或和好。
- **旧结局过程**：可供档案和回档查看，但不再持续占据普通AI上下文。

## 二、共居不是“她继续照顾玩家”

### 2.1 结局前后差分

| 结局前 | 结局后 |
|---|---|
| 她做饭、等玩家、收拾家里，默认把自己放在照顾者位置 | 她会照顾玩家，也会要求玩家尊重她的时间、安排和需要 |
| 玩家晚回，她一直把饭温着 | 她会先问是否回来吃；没有答复就先吃，不无限等待 |
| 楼务出问题，她考虑怎样向父亲解释 | 她只与玩家讨论现实处理，不再替玩家向父亲圆场 |
| 她的日常几乎都围绕儿子与公寓 | 她每周应有属于自己的外出、休息、穿衣和兴趣 |
| 玩家回302主要是“回家看看、休息、睡觉” | 玩家能参与饭桌、安排、分歧、和解与共同休息 |
| “妈”是她唯一被看见的身份 | 母亲身份保留，但正文和手机也承认她是有自己审美、欲望、时间与选择的成年人 |

### 2.2 作息原则

当前302的基础周作息可继续保留，不必另造一套庞大模拟：

- 大部分时段在302；
- 星期一早晨去垃圾房；
- 星期三中午、下午在大堂；
- 星期五傍晚去垃圾房；
- 星期日早晨去天台。

结局后改变的是这些安排的生活语义：

- 她外出不再只是为家里办事；
- 她可以有自己的采购、散步、天台停留、看衣服或短暂独处；
- 玩家临时找她，不等于她必须取消已有安排；
- 她不再作为永远留在家里等待玩家的待机角色。

建议长期节奏：

> 每三个母亲日常事件中，至少有一个围绕她自己的需要，而不是她为玩家做了什么。

### 2.3 302环境表现

此前“不建立总钥匙、挂钩、关门等长期环境状态”的结论继续保留，但不能误解为302结局后完全没有环境差分。

允许采用轮换生活痕迹：

- 两只正在使用的杯子；
- 两副碗筷或已经收掉的一副；
- 她刚放下的包、披肩、购物袋；
- 玩家忘在沙发上的衣服；
- 餐桌上的便签；
- 她为自己买的东西；
- 衣柜中真正留给玩家或她自己的空间；
- 某次共同生活事件留下的短期痕迹。

纪律：

1. 不把所有痕迹每轮同时注入。
2. 总钥匙只属于结局收束，不变成永久重复提及的图腾。
3. 环境痕迹必须来自真实发生的生活事件，不凭空制造幸福共同生活。
4. 痕迹应随时间和后续操作自然替换，避免房间成为静态纪念馆。

## 三、302四个核心生活循环

先只把四个循环做实，再扩展其他低频事件。

### 3.1 早饭

可用时段：早晨；母亲在302；没有更强剧情、医院硬锁或冲突现场。  
建议操作：

- 一起吃早饭；
- 玩家第一次主动准备早餐；
- 玩家起晚后吃她留下但没有反复加热的早餐；
- 前一晚已约好外出时，早餐转为出门前短互动。

即时反馈：

- 谁先起床；
- 谁准备食物；
- 是否兑现前一晚安排；
- 饭桌话题承接最近真实事件。

后续反馈：

- 中午私聊；
- 一条公开可解释的朋友圈；
- 次日记得玩家口味；
- 若玩家连续承诺又缺席，进入生活分歧而非结局失效。

### 3.2 晚饭与当日安排

可用时段：傍晚至晚上。  
建议操作：

- 告诉她今晚回来吃饭；
- 告诉她会晚归；
- 告诉她今晚不回；
- 一起做晚饭；
- 陪她吃饭；
- 玩家回得太晚，只承接已经成立的结果，不让整桌饭无限等待。

必须保存的只是当日短状态：

- 回来吃饭；
- 晚归；
- 不回；
- 尚未说明。

纪律：

1. 答应回来后必须有实际晚饭入口。
2. 玩家错过时，母亲可以先吃、收桌、发一条短消息或表达失望。
3. 不因一次爽约直接大幅倒退关系或重开结局前试探。
4. 朋友圈只能反馈真实执行结果，不能把未发生的约定写成已经完成。

### 3.3 夜晚与共同休息

可用时段：晚上或深夜；父亲已离开；当前没有更强剧情或电话硬锁。  
建议操作：

- 陪她坐一会儿；
- 一起看电视、喝茶或聊当天的事；
- 和她一起休息；
- 睡到次日早晨。

共同休息不自动等于每次进入成人亲密场景。它首先是共同生活动作：

- 谁先睡；
- 是否仍有话没说完；
- 前一日争执是否影响气氛；
- 次日早餐与起床顺序产生差分。

### 3.4 她自己的安排

这是共居成立的必要循环，不能只把母亲做成新的伴侣待机角色。

可出现：

- 去天台；
- 买菜，但买自己想吃的东西；
- 看衣服、试妆或处理自己的物品；
- 与楼里熟人短暂来往；
- 自己先吃饭；
- 明确说今天已有安排；
- 拒绝玩家临时改变计划。

玩家可以陪同，但不能默认接管她的决定。

## 四、一次性生活里程碑

以下节点比再补一段结局独白更能证明共同生活成立：

1. 第一次由玩家主动给她准备早餐。
2. 第一次她没有等到玩家答复，按自己的饭点先吃。
3. 第一次她有自己的安排，没有因为玩家临时回来就全部取消。
4. 第一次玩家陪她为她自己挑选物品，而不是购买家用品或孝顺用品。
5. 第一次两人因晚归、忘记约定或家务产生小分歧。
6. 第一次分歧被真正谈开，而不是靠一条甜言蜜语瞬间清零。
7. 第一次两人共同出门或去天台，并在之后产生合适的手机回声。
8. 第一次共同休息后，次日早晨表现为已经习惯生活在一起，而非重复初次震惊。

这些里程碑可进入长期记忆；普通重复吃饭不需要逐次写数据库。

### 5.1 不依赖强制改称呼证明关系

母亲目前没有正式姓名，不能为了表现结局后变化而强行让玩家突然改口叫名字。

- 明早是否已有约定；
- 她自己的计划是否需要调整。

不能把她写成每轮参加排班、比较亲密程度或训话的群管理员。

## 六、朋友圈必须进入“共居后”新阶段

302地图进入共居后，手机不能继续只按旧“攻略阶段＋好感＋堕落”随机生成暗示动态。朋友圈应由以下四层组成。

### 6.1 一次性结局公开动态

《双重继承》完成后的下一次安全手机节拍，母亲发布一条必达公开动态，功能是宣布公开可解释的管理交接结果。

方向示例：

> 该交的都交完了。以后楼里的事由他自己拿主意，我也该少替他操一点心了。

允许配图：

- 普通交接材料；
- 收好的饭桌；
- 社会上可解释的家庭照片；
- 总钥匙可只在这一次作为交接象征出现。

禁止：

- 公开母亲与玩家的真实关系；
- 机场视频隐秘现场；
- 让父亲表现为早已知道、默许或故意成全；
- 让姐妹群知情成员在评论区泄密。

评论按真实知情范围分层：

- 父亲：普通家长与交接者口吻，只谈玩家以后自己承担。
- 夏乔：热闹祝贺“正式当家”。
- 沈静仪：克制祝贺。
- 周小满：安静表示以后仍请管理员照应。
- 其他人：只能理解为公寓管理权交接。

### 6.2 真实共居事件的朋友圈回声

朋友圈不能创造共同生活，只能反馈玩家确实完成的生活事件。

| 已真实完成的事件 | 朋友圈方向 | 可见范围 |
|---|---|---|
| 玩家第一次主动准备早餐 | 今天居然轮到她坐着等饭 | 公开可解释 |
| 两人一起买菜 | 菜价、挑菜、谁拿重物 | 公开 |
| 玩家答应回来吃饭并按时回来 | 饭桌、两副碗筷、菜没有反复热 | 公开或仅你可见 |
| 玩家未答复，她先吃 | 饭点不等人、凉了自己负责 | 公开可解释 |
| 两人一起去天台 | 风、晾晒、楼顶景色 | 公开 |
| 玩家陪她挑衣服或出门 | 她主要谈自己的审美和状态 | 公开 |
| 共同休息 | 不进入公开朋友圈 | 仅你可见或私聊 |
| 两人发生争执 | 不自动发朋友圈影射 | 默认不发布 |
| 争执真正谈开 | 隔日可有一句轻量生活感悟 | 依内容决定 |

### 6.3 母亲自己的朋友圈

共居不等于把母亲的人生从丈夫转而完全绑在玩家身上。

普通朋友圈建议长期保持约三类轮换：

- 约三分之一：她自己的生活、衣着、兴趣、外出和决定；
- 约三分之一：与玩家共同生活、但公开可解释的片段；
- 约三分之一：公寓、邻里、天气和普通家常。

她的变化应清楚呈现为：

> 以前主要拍儿子；后来会拍两个人的日子；最终也会单独拍自己。

### 6.4 “仅你可见”改为共居私密层

结局前的仅你可见主要承担攻略奖励和私密暗示。进入自由阶段后，应优先承接共同生活中的私密回声：

- 只给玩家看的想念；
- 玩家留在302的生活痕迹；
- 两人约定的暗号；
- 她穿了玩家陪她挑选的衣服；
- 对一次真实早餐、晚饭、爽约、和好或共同休息的私人回应。

仍可有亲密内容，但不应继续用“越来越露骨”作为唯一成长方向。

结局后的价值是：

> 她不需要不断加大尺度证明关系，却会把生活里只有玩家看得懂的一小块留给他。

仅你可见的硬纪律继续保留：只有玩家能看见，不得出现任何其他住户点赞或评论。

### 6.5 朋友圈节奏

结局完成后不能同一时刻集中轰炸手机：

1. 下一安全节拍先出现当事人私聊或必要群聊余波；
2. 再过一至两个时段出现一次姐妹群反馈；
3. 一至三天后出现公开交接动态或生活动态；
4. 后续由真实生活事件和正常冷却驱动。

### 7.1 邀约必须能执行

母亲发“晚上回来吃饭吗”，玩家答应后，晚上302必须出现对应入口。玩家拒绝、错过或世界状态发生冲突时，必须形成真实结果：

- 她先吃；
- 约定过期；
- 发送一条合适的短消息；
- 下一次互动记得玩家是否爽约。

消息不能只是一段气氛文本，地图却没有后续入口。

### 7.2 反馈只选择最合适的渠道

生活事件采用：

> 真实操作 → 当场反应 → 下一时段或次日回声 → 在允许的一个渠道产生反馈。

不是每顿饭都同时触发私聊、群聊和朋友圈。

## 八、持续记忆预算

### 8.1 值得长期保存

- 第一次共同早餐；
- 第一次由玩家照顾母亲；
- 第一次她不再等待并先吃；
- 稳定形成的称呼；
- 尚未完成的现实约定；
- 约定已完成、爽约或由角色取消；
- 生活分歧以及是否真正谈开；
- 公开范围：公开、姐妹群已知、仅玩家可见；
- 最近一次会明显改变下一轮态度的重要事件。

### 8.2 不需要逐次长期保存

- 每顿普通饭；
- 每次普通点赞；
- 每句无后果闲聊；
- 每次重复睡觉；
- 同质化天气、晒饭和家务动态。

普通重复互动只保存短期冷却、近期类别和未解决结果。朋友圈继续沿用现有原则：只有脚本明确标注长期记忆凭据的重要动态进入数据库，普通日常只留在手机原始库。

## 九、自由阶段封存原则

### 9.1 封存不是删存档

必须分成三层：

| 层级 | 处理 | 原因 |
|---|---|---|
| 完整存档状态 | 保留 | 回档、旧档兼容、图库、凭据、失败恢复 |
| 脚本运行状态 | 按消费者保留 | 父亲家常电话、群聊余波、经济、孕产等仍需运行 |
| AI可见投影 | 大幅压缩 | 只给当前生活所需的结果、安排、人物与近期事实 |

核心结论：

> 变量存在于存档里，不等于必须进入AI提示词。

### 9.2 可以退出普通AI的旧内容

- 《回国》的逐步阶段与任务说明；
- 父亲回信的过程文本；
- 八个公共区域的逐项检查结果；
- 最早到楼、早餐、视频时点；
- 三日早餐逐拍；
- 机场视频逐拍；
- 总钥匙归位过程；
- 母亲旧裂缝揭示全文；
- 父亲考验、最后通牒、母亲圆场等旧剧情方向；
- 已经完成的阶段升级目标；
- 已完成场景的具体对白和画面细节。

这些可留在存档、档案或数据库摘要中，普通AI不再反复接收。

### 9.3 必须继续保存和运行

`系统._双重继承`不能整体清空，至少仍有消费者需要：

- 完成状态与完成楼层；
- 群聊余波状态与最早时段；
- 父亲家常联络序号；
- 下次父亲家常联络时段。

此外继续保留：

- 世界时间；
- 人物位置；
- 现金、收租、欠租、维修；
- 当前情绪和心理；
- 当前穿着；
- 孕情、医院、生产；
- 手机知情范围；
- 当前生活约定；
- 回档、重掷与时间线凭据。

正确实施方式：

> 保留完整真值，关闭旧生产者，压缩AI投影。

不能把整个路线节点、母亲阶段或父亲状态归零，否则会破坏后续系统和旧档恢复。

## 十、攻略变量进入自由阶段后的处理

| 变量 | 自由阶段用途 |
|---|---|
| 当前阶段 | 保留第五阶段供兼容和权限判断，但不再向AI反复描述“正在攻略” |
| 好感值 | 可继续影响日常温度、分歧和和好；不再负责解锁结局 |
| 堕落值 | 保留图库和权限兼容，可减少或停止作为普通动态主题的主要驱动力 |
| 婚姻值 | 保存原值；母亲结局后不再编译旧婚姻崩塌感知 |
| 罪恶感 | 结局后停止注入，不再每轮演面对丈夫的旧负担 |
| 当前情绪 | 继续动态运行，是共同生活的主要活状态 |
| 当前心理想法 | 继续运行，但只围绕当下生活与未解决事情 |
| 穿着、孕产、身体状态 | 按现有系统继续 |
| 冷落后果 | 改为共同生活中的失望、抱怨和距离，不抹除结局完成事实 |

自由阶段不是没有后果，而是：

> 关系事实稳定，生活质量仍会变化。

## 十一、自由阶段AI最小上下文

302普通生活回合建议只给：

1. 当前日期与时段；
2. 当前位置与真实在场人物；
3. 一条稳定共居事实；
4. 今日安排；
5. 最近一个仍影响当下的重要生活事件；
6. 当前情绪和未解决事项；
7. 本轮玩家实际言行；
8. 只有命中风险时才加载隐私、父亲或亲密详则。

稳定事实可压缩为：

> 【302自由生活】《双重继承》已完成。玩家独立管理公寓；父亲在海外，只作低频家常联系且始终不知道两人的隐秘关系。母亲主动留在302，与玩家稳定共同生活。旧交接、早餐和机场视频过程已经封存，本轮只承接当前生活。

当前 `snapshotSystem.ts` 中已有数段近义的双重继承长期说明。后续落地应合并、按场景路由，避免同一回合重复强调父亲、交接和结局。

## 十二、历史正文的章节边界封存

只压缩变量提示还不够。八区检查、交权、三日早餐、机场视频和钥匙收束若持续作为完整聊天历史进入模型，弱模型仍可能被拉回旧场景。

建议建立“章节边界式上下文封存”：

1. 玩家仍能在聊天记录、图库和档案中查看原场景；
2. 每楼 `stat_data` 仍完整保留，回档不受影响；
3. 数据库保留可靠的短结果摘要；
4. 后续普通生成不再携带整段特殊场景正文；
5. 用一条固定结果摘要替代；
6. 玩家明确追问某段往事时，再从数据库或剧情档案按需召回相关摘要，而不是常驻整段原文。

原则：

> 场景可以永久存在于玩家界面里，但不必永久存在于每一次AI请求里。

母亲视频通话的独立线程与确定性转场已经提供了正确范例。

## 十三、世界书当前存在的结局前冲突

当前两个蓝灯常驻条目仍写着结局前事实：

### `世界书/系统设定/世界观.yaml`

包含：

- 管理公寓是父亲的考验；
- 管不好就去码头；
- 302里的母亲只是做饭、唠叨、把玩家当孩子。

### `世界书/角色/主角.yaml`

包含：

- 房租按期交给父亲；
- 父亲约每周联系并验收；
- 公寓是悬在玩家头顶的考卷；
- 母亲永远温饭等玩家。

这些内容属于蓝灯常驻。即使动态快照随后说“父亲已退出审核”，模型仍会同时接收两套互相冲突的世界事实，并不断被旧设定拉回。

因此，自由阶段封存必须同时处理世界书，不可只增加一条结局后提示。

## 十四、能否在结局完成时修改原世界书

### 14.1 技术结论：可以

项目运行环境提供：

- `getCharWorldbookNames('current')`；
- `getWorldbook(name)`；
- `updateWorldbookWith(name, updater)`；
- `getOrCreateChatWorldbook('current')`；
- `rebindChatWorldbook('current', name)`。

`updateWorldbookWith`可以修改世界书条目的：

- `enabled`；
- `content`；
- 激活策略；
- 关键字；
- 插入位置等。

当前项目的 `入住系统.ts` 已实际使用 `updateWorldbookWith`，根据当前存档开关角色世界书条目。因此在《双重继承》最终提交后修改或切换世界书，技术上完全可行。

### 14.2 直接改原条目的风险

角色卡主世界书是酒馆全局持久配置，不天然属于单一存档。若结局完成后直接把“梧桐里7号”或“管理员”的内容永久改写为结局后版本，会产生以下风险：

1. 一个已完成结局的聊天可能污染新开的聊天。
2. 切换到结局前旧档后，世界书仍可能停留在结局后文本。
3. 回档到结局前，世界书不会像每楼 `stat_data` 一样天然随楼恢复。
4. 两个浏览器标签页或两个聊天状态不同，会争抢同一个角色主世界书。
5. 世界书更新属于外部派生写入；若更新失败，不能让已经完成的结局回滚。
6. 直接覆写同一条内容容易覆盖用户自行调整的世界书文本。
7. 世界书在请求构建阶段已展开，生成开始后才修改对当前这一轮无效。

因此：

> 可以做，但不能把“直接修改原世界书”当作结局真值或唯一保护。

## 十五、推荐世界书架构

### 15.1 第一层：把原蓝灯内容一次性改成不变底色

正式落地时，源码中的主世界书应改为“任何阶段都不会错”的中性事实。

#### 梧桐里7号条目

保留：

- 楼体、房间、管理员室、老楼声音、邻里秘密必须被真实看见才会传播；
- 玩家负责现实管理；
- 管理权当前处于父亲考验、正式独立或其他状态，以实时快照为准；
- 302是玩家与母亲共同生活的家，具体关系与当下生活状态以实时快照为准。

移除常驻断言：

- 永远是父亲考验；
- 管不好永远会被赶去码头；
- 母亲永远只把玩家当孩子；
- 母亲永远温饭等待。

#### 管理员条目

保留：

- 玩家最初为何接手公寓；
- 会修东西、持有管理员权限；
- 性格由玩家实际言行塑造；
- 当前管理权限、父亲联络模式、家庭关系和已完成结局以实时快照为准。

移除常驻断言：

- 永远按期向父亲汇报；
- 父亲永远每周验收；
- 公寓永远是尚未通过的考卷；
- 母亲永远只是理所当然的照顾者。

### 15.2 第二层：阶段事实由存档驱动

推荐顺序：

1. **首选：脚本快照动态注入。** 这是每次请求按当前 `stat_data` 生成，天然属于当前聊天、支持回档，最可靠。
2. **需要让玩家在世界书界面看见阶段变化时：使用当前聊天专属世界书。** 通过 `getOrCreateChatWorldbook('current')` 创建一条“当前阶段投影”，只绑定当前聊天，不修改角色卡主世界书。
3. **备选：预制结局前／结局后两组角色主世界书条目，由脚本切换 `enabled`。** 只有确认单活动聊天假设成立时采用，并必须像入住条目一样在启动、切聊和回档时全量重同步。
4. **不推荐：不断覆写同一条原世界书正文。** 除非用户明确要求世界书编辑器内原条目文字本身随存档变化，并接受同步复杂度。

### 15.3 若采用聊天专属世界书

建议只放一个非常短的阶段投影条目，例如：

结局前：

> 【当前管理与家庭阶段】父亲仍保留管理审核权；母亲与玩家的生活关系以当前剧情进度为准。

结局后：

> 【当前管理与家庭阶段】《双重继承》已完成。玩家独立管理公寓；父亲退出楼务审核并只保留低频家常联系；母亲主动留在302，与玩家稳定共同生活。父亲始终不知两人的隐秘关系。旧交接过程已结束。

该条目只承担稳定结果，不存今日安排、情绪、具体事件或复杂变量；这些仍由快照提供。

## 十六、世界书同步生命周期

无论使用聊天专属世界书还是角色主世界书双条目切换，都必须覆盖：

1. 《双重继承》最终正文成功、核心 `stat_data` 已提交之后；
2. 游戏启动；
3. 切换聊天；
4. 新建聊天；
5. 回档、删楼或 swipe 到结局前；
6. 回到结局后楼；
7. 重开游戏；
8. 世界书外部更新失败后的下一同步点重试。

提交顺序：

```text
结局硬状态成功落入当前聊天
→ 正式楼与MVU提交完成
→ 世界书阶段投影作为可重建派生副作用同步
→ 同步失败只记录并重试，不回滚结局
```

世界书永远不是完成判据。真正权威仍是当前聊天 `stat_data` 与完成ID。

### 16.1 当前轮次保护

世界书在 SillyTavern 构造请求时可能已展开。若同步发生得太晚，当前轮仍可能带旧条目。因此：

- 结局最终收束本身继续使用独立硬快照；
- 完成后的下一轮生成前必须已同步；
- `snapshotSystem.ts` 仍需提供一条短硬事实作为兜底；
- 即使世界书短暂过期，快照也必须阻止父亲重新审核或母亲退回旧边界。

## 十七、建议拍板方案

本设计推荐最终采用：

### 方案A：中性主世界书＋动态快照＋可选聊天世界书投影

1. 将“梧桐里7号”和“管理员”改为中性、不随阶段失效的底色。
2. 结局前的父亲考验由动态快照注入。
3. 结局后的独立管理与302共居由动态快照注入。
4. 为了让世界书界面也能反映当前存档，可额外创建一个当前聊天专属的短阶段条目。
5. 当前生活安排、最近事件和情绪不放世界书，只放动态快照。
6. 完整旧剧情留存于聊天、图库和数据库摘要，不常驻AI上下文。

优点：

- 不会让新档继承旧档结局；
- 回档自然可重算；
- 主世界书不会在两个聊天之间互相污染；
- AI上下文最轻；
- 世界书更新失败也有快照兜底；
- 不需要反复覆写用户可编辑的原条目。

### 方案B：结局前／后条目切换

若不使用聊天专属世界书，可预制四条：

- `管理阶段·托管考验`；
- `302关系·母子日常`；
- `管理阶段·独立经营`；
- `302关系·稳定共居`。

脚本按当前存档只开启对应两条。该方案可以实现，但世界书是角色全局持久配置，必须在每次启动、切聊、回档时全量重同步，并需接受多标签页竞争风险。

### 不采用

- 结局完成时直接永久改写原蓝灯条目，此后不恢复；
- 删除旧世界书条目；
- 清空整个 `_双重继承`；
- 只靠世界书判断结局是否完成；
- 同时保留旧考验蓝灯和新增自由阶段蓝灯，让模型自己判断哪个为真。

---

## 十八、落地验收标准

后续实现完成前至少验证：

1. 新局仍明确处于父亲考验阶段。
2. 《双重继承》完成后的下一轮不再携带“管不好去码头”“父亲每周审核”等旧常驻事实。
3. 母亲在302进入稳定共居，但仍保持本人性格和母亲身份。
4. 切换到结局前旧档，世界书／阶段投影恢复结局前状态。
5. 回档到完成前后，投影随当前真值变化。
6. 世界书同步失败时，结局硬状态不回滚，动态快照仍能阻止旧剧情复活。
7. 两个不同聊天不会因某一聊天完成结局而永久污染另一聊天。
8. 朋友圈公开动态不泄露隐秘关系，父亲始终不知情。
9. 共居朋友圈只反馈真实发生的生活事件。
10. 仅你可见没有其他住户评论。
11. 旧结局正文仍能在界面和回档中查看，但普通AI请求不再长期携带整段过程。
12. 其他未完成角色线、经济、楼务、孕产和衣柜继续正常运行。

## 十九、302结局后背景CG换血

### 19.1 总体视觉原则

《双重继承》完成后，302背景必须从“母亲照顾儿子的旧家”切换为“母亲主动留下、两人共同生活的新家”。不重做地图结构，也不把房间改成豪华婚房；保持玩家熟悉的302构图，以光线、使用痕迹、饭桌、杯子、衣物、包与个人物件表现生活关系已经改变。

长期画面比例建议：

- 约60%为普通共居生活；
- 约25%为温柔亲密；
- 约15%为夜间私密或明显暧昧。

母亲不必永远站在画面中央。允许她外出、休息或不在镜头里，只通过仍在变化的个人物件证明她真实生活在这里。

### 19.2 两段式换血

第一层为结局刚完成后的余韵组，承担从终幕进入自由生活的过渡：

1. 结局后第一晚的302；
2. 次日早餐后的302；
3. 夜深以后安静下来的302。

第二层为长期轮换的共居组，按时段与实际生活状态选择，不永久固定一张：

1. 早晨早餐版：两副碗筷、共同起居痕迹；
2. 中午个人生活版：她可能不在画面中，但有杯子、包、披肩、书或购物袋；

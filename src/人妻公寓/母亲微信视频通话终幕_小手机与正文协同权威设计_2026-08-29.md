## 一、核心形态：仍然使用现有小手机

本终幕不改成独立全屏微信页面，也不把微信外观搬进正文舞台。

父亲必须先通过现有小手机发起微信视频通话。玩家打开的是当前游戏里真实存在、可拖动和缩放的小手机；父亲的头像、通话气泡、输入框、静音、扬声器、隐藏界面和挂断控制都继续属于手机UI。

沉浸感来自三层同时工作：

1. **小手机微信视频通话**：父亲真的在电话里，玩家只在这里输入并与父亲自由聊天；
2. **小手机内的当前CG背景**：显示玩家在302现场亲眼看到的母亲动作；父亲只看到玩家肩颈以上的安全裁切；
3. **主界面正文舞台**：根据本轮真实微信记录、当前CG详细语义和上一轮现场连续性，使用玩家当前正文预设演绎母亲与玩家在电话之外的现场。

CG大画面不是父亲收到的完整视频流。父亲从头到尾不知道母亲处于镜头裁切线以下，也不能因为玩家能看见CG而获得任何知情权。

## 二、接通后的场景硬锁

视频通话接通并进入母亲终幕后，系统写入持久运行态并锁定：

```text
玩家位置：302卧室
母亲位置：302卧室，玩家两腿之间／身边
父亲位置：机场远端，仅微信视频出现
游戏时间：冻结
地图移动：禁止
其他角色互动：禁止
商店／背包／监控／推进时间：禁止
普通微信自动内容：暂停
其他强制剧情与特殊场景：不得插入
```

这些不是客户端按钮灰掉就算完成。刷新、关闭手机、退出酒馆后重新进入时，仍须从持久状态恢复同一通电话、同一地点、同一CG和同一待回复／待正文序号。

关闭小手机只表示暂时收起设备，不等于挂断通话，也不解除地点与功能锁。主舞台应显示低干扰提示：

> 视频通话仍在进行中 · 打开手机继续回应父亲

真正离开只能走通话内明确的结束、挂断或取消结局流程。

## 三、普通正文输入框完全隐藏

通话期间，微信输入是玩家唯一输入源。

普通 `RoundInput` 不能只把textarea禁用，而应整体退出普通模式，避免仍露出：

- 正文普通输入框；
- 行动建议；
- 撤回／普通重掷；
- 变量重新生成；
- 推进时间；
- 与当前视频终幕无关的失败行动入口。

主界面仍保留正文舞台和本轮现场正文失败后的**专用重新演绎**入口。专用重试只能重用已经保存的微信往返与当前冻结CG，不能让父亲重复说一次、不能推进下一张CG，也不能消耗普通行动资源。

玩家在微信中的每一句话，就是该轮的真实玩家行动，不需要再在正文输入框补一句“继续”“看母亲反应”或命令母亲做什么。

## 四、两个模型请求，各自只做一件事

### 4.1 父亲通话模型

只读取父亲通话硬事实与微信记录，生成父亲下一句话：

- 唯一说话人是父亲；
- 不生成母亲台词、现场旁白或结局结算；
- 玩家输入与父亲回复都先持久保存；
- 失败保留待回复令牌，刷新后继续；
- 迟到结果必须核对聊天ID、时间线世代、通话标识和待回复序号。

### 4.2 正文模型

父亲回复成功保存后，正文模型读取：

- 本轮玩家真实说出的话；
- 父亲刚刚的真实回复；
- 最近若干轮完整视频通话；
- 更早对话的压缩概览；
- 当前CG的详细内容说明；
- 当前CG与上一张的动作连续性；
- 上一轮现场正文的结束状态；
- 302视频终幕专用最小快照。

正文仍由玩家当前预设决定长度、风格、流式过程和叙事密度。系统不把它压成固定短旁白，也不预写固定反应模板。

正文模型只负责：

- 母亲此刻的动作、表情、呼吸和注意力；
- 玩家一边接电话一边承受现场干扰的身体与心理反应；
- 母亲如何自然响应父亲刚才谈到的账目、家里、她本人、玩家能力或最终托付；
- 当前CG所代表动作在这一轮如何真实发生。

正文模型不得：

- 新增、复述或改写父亲与玩家的微信台词；
- 让母亲直接加入通话；
- 自行决定下一张CG；
- 自行让父亲知情；
- 自行推进游戏时间、地点、结局节点或数值；
- 提前进入高潮、挂断、关门或结局完成。

## 五、一轮通话的运行顺序

```text
玩家在小手机输入回答
→ 玩家微信气泡立即持久保存
→ 父亲模型生成并保存父亲下一句
→ 本轮CG推进到下一张并冻结
→ 正文模型读取本轮往返＋当前CG语义＋上一轮现场连续性
→ 主舞台按玩家预设流式生成现场正文
→ 正文成功后开放下一次微信发送
```

这里的“固定”只是事务顺序，不是固定剧情内容。聊天内容、正文演绎和母亲对具体话题的反应仍然完全动态。

正文生成中允许玩家在微信输入框继续编辑草稿，但不允许发送下一条。否则父亲、CG和正文会出现一轮错位。

如果父亲回复已经保存而正文失败：

- 玩家气泡保留；
- 父亲气泡保留；
- 当前CG保持冻结；
- 本轮硬节点不推进；
- 使用同一微信往返和同一CG重新演绎正文。

## 七、CG推进规则

### 7.1 接通入场只走一次

权威顺序：

```text
MVC-CG-001-draw1
→ MVC-CG-012-draw1@001-1
→ MVC-CG-002-draw1
→ MVC-CG-003-draw1
→ MVC-CG-004-draw1
→ MVC-CG-005-reused
```

`001-1`是用户亲自指定的位置。它表现母亲扶脸／调整头部、确认安全裁切，仍未发生嘴部接触。

### 7.2 主循环从含入段开始回环

主循环起点固定为：

```text
MVC-CG-005-reused
```

主循环末帧固定为：

```text
MVC-CG-024-draw4
```

普通聊天时：

```text
005 → …… → 024 → 005 → ……
```

绝对禁止：

```text
024 → 001
```

因此玩家即使和父亲聊几十轮，也只会在已经建立口腔连接后的动作段循环，不会突然回到“刚刚接起电话、母亲尚未靠近”的入场画面。

### 7.3 每轮推进一张

一轮以玩家微信回答为输入起点、父亲回复与对应现场正文成功收口为完成边界。每轮只推进一张CG，不根据正文模型自由猜测跳两张，也不因预设写得长而额外推进。

### 7.4 结束请求离开主循环

玩家选择“结束交接通话／让父亲登机”，或明确告别并确认结束后：

- 当前是浅含／中段：使用`MVC-CG-025-draw1`；
- 当前是深喉：使用`MVC-CG-025-draw2`；
- 当前是离口／舔舐／贴近：使用`MVC-CG-026-draw1`。

之后进入一次性终幕，不再回到005。

## 八、正文舞台背景与小手机同步

正文舞台背景应与小手机当前CG使用**同一帧编号**，但不能与小手机争夺主视觉。

### 小手机

- 显示清晰、完整的当前CG；
- 是本场景的主视觉；
- 父亲头像、气泡、输入框和通话控制覆盖其上；
- “隐藏界面”只移除微信UI，显示当前CG原图，不推进帧。

### 正文舞台

- 使用同一张CG；
- 通过CSS放大裁切、暗化、柔化或低对比处理；
- 为正文保留稳定可读遮罩；
- 只作为同一现场的氛围延伸，不生成第二份图片资源；
- 切帧必须与小手机同时完成，不能一边显示上一张、一边让正文解释下一张。

这形成明确主次：

```text
小手机当前CG = 清晰主视觉
正文舞台同帧 = 弱化氛围背景
正文文字 = 当前CG＋真实微信往返的动态现场演绎
```

## 九、逐图详细说明与画面偏差隔离

54张图的详细语义已经写入：

```text
src/人妻公寓/脚本/游戏逻辑/母亲视频通话CG语义.ts
```

每张包含：

- 运行时唯一ID；
- 原任务与draw；
- 真实物理源文件；
- 所属区段；
- 当前连接状态；
- 当前可见物理事实；
- 正文承接重点；
- 必要的画面偏差隔离。

用户最终保留的一些候选曾有生成偏差，例如额外器官、额外手、侧拍、衣物或脸型漂移。图片仍按用户决定保留，但这些模型偏差不自动升格为世界事实。语义清单明确要求正文始终服从：

- 同一位46岁成年母亲；
- 同一名玩家；
- 单一连续玩家身体来源；
- 母亲只有两只手；
- 同一302现场；
- 父亲始终不知情；
- 不存在摄影者、第三人或临时换衣。

CG提供视觉变化，脚本语义决定世界事实。

## 十、接线顺序

后续正式落地按以下顺序推进：

1. 以`母亲视频通话CG语义.ts`作为54张语义与推进的唯一来源；
2. 增加持久视频终幕运行态，保存通话标识、地点锁、当前CG、微信轮次、待正文轮次和结束阶段；
3. 让现有父亲通话支持“母亲终幕模式”，但保留普通楼务电话原行为；
4. 小手机`talk`页增加CG背景和视频控件；
5. 客户端识别终幕状态，隐藏整个普通`RoundInput`并锁定地图与其他功能；
6. 父亲回复保存后触发专用正文生成，注入当前CG语义和通话记录；
7. 正文成功后才开放下一次微信发送；失败只重试现场正文；
8. 手机和正文舞台使用同一CG帧，主舞台只做弱化显示；
9. 玩家请求结束时按当前连接状态选择衔接图，再进入一次性终幕；
10. 父亲挂断、最后回答、手机交接、钥匙与关门动作全部完成后，才提交《托付／双重继承》。

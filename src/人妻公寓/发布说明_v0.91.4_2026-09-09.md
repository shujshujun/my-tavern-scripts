## 本次修复

### 1. 重开一局后自定义变量 API 自动恢复

- 《人妻公寓》内置变量解析现在使用独立于聊天进度的宿主级权威配置 `rqgy_builtin_variable_parser`。
- 游戏“重开一局”只重建游戏数据，不再让自定义变量 API 的激活依赖 MVU 面板、模型列表或重新点击“读取模型”。
- iframe 重载、切换聊天及后续每个真实回合都会从同一权威入口实时决定数据库或自定义变量通道。
- 旧 MVU 自定义配置继续作为兼容迁移来源，但不再成为游戏内置解析运行时的隐含前置。

### 2. 变量设置保存事务与防双发

- 设置保存会真正等待 `saveSettingsDebounced()` 的 Promise；同步抛错或异步拒绝都会恢复游戏配置、MVU 兼容镜像、当前 API 方案及原对象引用，不再出现“界面提示保存成功、宿主实际没有落盘”。
- “读取模型”只读取并填写表单，不保存、不启用、不切换解析通道；只有“保存并启用”提交完整原子事务。
- 保存期间禁用重复保存、读取模型和通道切换。
- 游戏内置解析与 MVU 官方自动／手动路径继续由单一执行路径总闸互斥；同一个助手楼不能被两条自动变量请求同时认领。MVU 面板中的人工重试仍保留为明确失败后的恢复入口。

### 3. RQ 剧情事件撞数据库填表锁后的自动补写

- `RQ_剧情事件` 硬骨架若撞上数据库 `active-fill`／AI 填表占用，不再直接显示成永久写入失败。
- 游戏会先按当前聊天、楼层和事件码精确回读；若提供方已完成写入则直接确认成功。
- 尚未确认的记录进入带时间线身份的待补队列，填表锁释放后才执行单次幂等 UPSERT，并在回读确认后清除待办。
- 当前硬骨架未确认前不会继续抢占可选数据库 AI 填表，避免锁竞争被放大。

### 4. 数据库 Plot 采用链诊断与显式消息锚

- 数据库剧情规划桥新增 `intercepted`、`processed`、`adopted`、`formalInputSource`、`outcome` 控制流诊断。
- 规划探针携带当前聊天、真实玩家消息楼／ID及回合令牌；spv9.2.3 兼容层也只在已经由消息引用、ID和令牌锁定的唯一玩家楼安装临时锚。
- 正式正文只有在规划结果被处理并采用时才使用 `planned.user_input`；失败、超时、取消或运行时不可用时继续安全使用原玩家输入。
- 本版提升了 Plot 接线的可观测性和消息归属可靠性，但不把尚未经过玩家真实插件环境验证的 `$6` 历史挂载宣称为已经完全闭环；最终仍以新日志中的 `adopted=true`、非空 Plot 持久记录和下一轮 `$6` 为准。

### 5. 变量结算完成后的“内容正在生成”假提示

- 手动重新生成变量以前会先向客户端广播结束，再释放共享前台租约；变量实际已经更新，界面也已解锁，但底层仍有一个短暂忙态窗口。
- 现在统一先清变量事务、清生成 ID、释放共享前台租约并广播最新状态，最后才发送“变量重生成结束”。
- 客户端看到完成时，真实生成所有权已经释放，立即进行下一项操作不会再被上一笔变量任务误判为占用。

### 6. 手机节拍与时间事务真实收尾互斥

- v0.91.3 的“延后一轮微任务”升级为真实空闲调度：回合后的手机节拍会等待主回合、变量解析、MVU 队列、脚本写入、时间恢复记录／运行期租约、共享生成租约、原生正文租约、隔离事件及手机 AI 全部空闲后再启动。
- 等待期间的重复回合完成／补拍请求会合并；节拍执行期间的新请求会在首拍结束后补跑一次。
- 真正残留的恢复门不会被放宽；等待超时只留给下一次真实触发，不再把可选手机回执伪装成玩家操作失败。
- 推进时段、睡眠、小憩、晨跑、健身及时间撤销在建立时间事务前也会避让仍在运行的手机生成，形成双向互斥。

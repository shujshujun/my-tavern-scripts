
旧代码在手机节拍的Schema副本中写：

```ts
路线.群聊余波状态 = '已完成'
```

但只持久化微信库，不持久化主MVU状态。`提交双重继承结局群聊余波`实际上没有生产调用者。

结果：

- 主状态永久为“待发送”；
- 每次自动节拍或玩家手动发言都重新请求AI；
- 稳定键过滤重复气泡后，可能返回“成功”但实际插入0条；
- 玩家发言后看不到角色正常回复；
- 重复计费与普通群聊长期阻塞。

修复要求：

建立跨容器真实事务：

```text
生成候选
→ 5～8条余波全部真实写入微信库
→ 重读持久库确认本批所有稳定键存在
→ 发出带聊天ID、时间线世代、完成楼层、批次ID的主状态提交
→ 安全操作CAS写入 群聊余波状态=已完成
```

要求：

- 部分写入不能完成主状态；
- 切聊天、切分支、回档、刷新或迟到回调不能写错主时间线；
- 已有完整消息但主状态尚未提交时，只补交状态，不重新生成；
- `写库增量`或调用层必须区分“回调成功”和“实际插入N条”；全被去重不能冒充新回复；
- 成员不足或母亲不在群的无消息完成分支，也必须通过主状态真实提交，而不是只改副本；
- 手动群聊在余波完整提交后恢复普通姐妹群回复。

### 输入层

### 输出层

按当前角色和真实公开证据动态验收：

- 哪个角色完成了什么；
- 哪些事实已经由本人在群内公开；
- 哪些只能影响口吻、不能直接说出；
- 本次待验收消息不能反向成为它自己的公开证据；
- 借种、生物学父亲、丈夫知情、三人家庭等精确事实，在未公开时必须拒绝；
- 母亲机场视频隐秘现场和父亲知情继续永久拒绝。

新增测试至少覆盖：

```text
夏乔私下完成借种、群内未公开 → 精确三人事实拒绝
群内已有真实公开键           → 对应事实允许
本次候选第一次泄漏           → 不能自我转正
母亲结局普通交接事实         → 允许
机场视频隐秘／父亲知情       → 永久拒绝
```

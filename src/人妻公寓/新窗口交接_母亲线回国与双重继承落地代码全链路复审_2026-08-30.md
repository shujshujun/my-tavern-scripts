## 四、最终设计口径：必须逐项对照生产代码

### 4.1 《回国》只保留口头回国意向

《回国》内部仍有剧情状态、跨日父亲微信、母亲入群、群聊和完成 ID，但：

```text
父亲具体哪天回国、几点抵达，只是人物对白。
《回国》不得保存“父亲回国绝对时段”。
《回国》不得计算真实抵达时点。
世界时间经过再久，也不得自动启动《双重继承》。
```

完成《回国》后，只应表达：

```text
父亲答应近期回国；
正式交接准备好以后，由玩家通知；
商店开放《双重继承》。
```

重点搜索并核对：

```text
父亲回国绝对时段
待迎接父亲
迎接父亲
自动启动双重继承
回国完成后同步双重继承
```

任何仍由《回国》日期直接驱动父亲出现的生产路径都属于 BUG。

### 4.2 《双重继承》必须由商店道具主动启动

最终玩家链：

```text
《回国》完成
→ 商店“特殊场景”上架「双重继承」
→ 玩家花费1500购买
→ 道具进入背包
→ 购买本身不改变世界、不让父亲出现、不关闭旧父亲电话
→ 玩家到管理员室使用
→ 使用成功才消费道具、登记正式交接已准备
→ 父亲在当前或下一个安全下午回楼
→ 才进入八区公共验收
```

必须检查：

- 商品只定义一次，ID、价格、名称和特殊场景启动位置一致；
- 商店上架条件只认《回国》完成，且未购买、未启动、未完成；
- 重复购买、旧 UI 双击、现金不足、状态变化不会重复扣钱或重复入包；
- 购买后应是“待使用”阶段，不能立即关闭父亲旧问责链；
- 只能在管理员室使用；错地点、医院硬锁、活动电话、亲密、强剧情时失败且不消费；
- 使用成功后才关闭旧楼务问责来电；
- 安全下午调度遇强剧情只顺延，不能丢失、回退或越过验收；
- 不得存在第二套旧“迎接父亲”入口绕过商店票。

### 4.3 公共验收、交权、钥匙、三日早餐和机场视频

检查完整闭环：

```text
父亲回楼
→ 任意顺序检查八个公共区域
→ 每个区域只登记一次，11张主体CG映射正确
→ 八区完成后回管理员室
→ 两回合完全交权
→ AI不能提前把总钥匙放进背包
→ 玩家亲自点击领取唯一总钥匙
→ 父亲暂住302三天
→ 只屏蔽与父亲在场硬冲突的亲密动作，不屏蔽普通家庭聊天
→ 三日后安全早晨五回合早餐
→ 当日下午第一个安全时点预约现有母亲微信视频终幕
```

重点审查：

- 八区真实地图 ID 与显示名“公共洗手间”是否混淆；
- 未完成楼务只被看见，不被检查剧情偷偷完成；
- 场景事务的预期阶段、时段、地点、重掷、刷新和迟到票是否可靠；
- 管理员室与早餐逐拍越拍检测是否会误判否定句，或漏掉弱模型提前完成；
- 总钥匙是否始终唯一；旧档重复钥匙是否安全收口；
- 早餐顺延是否会无限推迟或错过后永久卡死；
- 视频预约是否会与普通父亲电话、医院、其他强剧情发生竞态。

### 4.4 视频第7张结束不能直接完成结局

正确状态必须是：

```text
视频终幕完成
→ 父亲已挂断
→ 母亲接回手机
→ 视频CG和视频输入层退出
→ _双重继承.阶段 = 待总钥匙归位
→ 不写入“双重继承”完成ID
→ 不移除总钥匙
→ 不立即开放普通自由剧情
```

然后302只开放一个真实动作：

```text
把公寓楼总钥匙放到她的钥匙旁
```

玩家点击后生成一回合专属收束，合格正文成功提交后才：

```text
移除全部公寓楼总钥匙
阶段 = 已完成
_已完成特殊场景 += 双重继承（唯一一次）
恢复普通地图、底栏和输入
初始化结局后长期状态
```

### 4.5 弱模型与上下文污染

视频终幕后不能把完整视频长线程塞回普通正文，也不能让普通模型自己猜场景切换。

最终一回合只允许得到极短硬快照：

```text
父亲已经从机场挂断并离开；
父亲不在302，也始终不知情；
手机已由母亲接回，视频不会重连；
刚才的成人动作已经结束，不得继续或复述；
302只有玩家和母亲；
本拍只处理总钥匙、母亲反应、她亲自关门和最后确认。
```

必须检查：

- 视频长正文是否泄漏进普通聊天历史或普通快照；
- 第7张后普通输入、Dock、地图是否在最终动作前被错误开放；
- 最终动作是否可能被普通行动绕过；
- 父亲重新说话、重新出现、视频重连、成人动作继续、第三人进入、AI自行宣布系统结局，是否会被语义验收拒绝；
- 第一次不合格是否定向重写；第二次仍不合格是否使用固定安全正文；
- 固定安全正文是否仍需要走真实提交事务，而不是直接跳状态；
- 失败、取消、刷新、重掷时总钥匙和路线是否保持可重试；
- 同一最终票重复回调是否幂等，不重置长期水位。

### 4.6 结局后经济：经济玩法继续，父亲审核永久结束

只有《双重继承》完成以后，才切换为：

```text
收租、欠租、维修、商店、现金、住户满意、公共楼务继续；
父亲查账、楼务问责、胜任度资格审核、最后通牒、收回钥匙、强制打工坏结局永久停止；
母亲替玩家向父亲圆场永久停止；
未接父亲家常电话不扣分、不形成失联责任；
```

重要边界：

```text
《回国》完成不能提前结束父亲审核；
只购买《双重继承》也不能提前结束审核；
使用场景票并进入正式交接后，旧楼务问责不应再插入；
正式结局完成后不得再次产生收楼坏结局。
```

必须追踪全部生产者和消费者：

- `经济系统.ts`
- 父亲来电生产与优先级
- 通牒期与坏结局
- 胜任度变动
- 母亲圆场对象
- 风闻转父亲问责
- 上交与自动财务流水
- 父亲通话收尾

不能用“直接停掉整个经济结算”来实现父亲退出管理。

### 4.7 结局后父亲低频家常联络

结局后父亲仍可从海外联系，但应走独立家常模式：

```text
每14～21个游戏日一次；
两次之间至少12天；
只在安全下午或晚上；
未接无责；
不叠加快速追问；
话题为彼此近况、身体、饮食、亲戚、节日、家庭旧事等；
不得主动谈账本、上交、维修、欠租、租户、胜任度、楼务审核或批准；
父亲始终不知情，不能写成早已看穿、默许或成全。
```

重点检查：

- 第一次调度初始化是否正确；
- 到期时已有活动电话或强剧情如何顺延；
- 是否错误用普通经济报表对象重新注入楼务词；
- 家常电话是否仍被父亲通话提示模板当成考核电话；
- 重载、回档、未接、挂断、重复同步是否会重复来电；
- 14～21日随机或确定间隔是否稳定、可测试且不出现0日循环。

### 4.8 母亲结局后长期语义

长期只需要让相关 AI 知道：

```text
玩家是公寓唯一实际管理员；
父亲已经退出公寓日常管理并留在海外；
母亲主动选择继续留在302；
母亲与玩家的特殊关系已稳定成立；
父亲始终不知情。
```

不要把以下一次性终幕细节长期塞进每轮提示：

```text
钥匙挂钩
饭桌座位
柜子
门锁
钥匙并列
```

检查普通快照、角色注入、母亲私聊和房间正文是否存在重复、过量或冲突注入。

### 4.9 姐妹群入群与动态群名

《回国》中已拍板：

```text
玩家点击邀请母亲入群
→ 立即写入微信系统提示“你邀请‘母亲’加入了群聊”
→ 群名仍保持旧名
→ 等待约5秒，显示“母亲正在修改群名”并锁输入
→ 再写入系统提示“母亲修改群名为‘{玩家名}人妻后宫群’”
→ 标题和会话列表同步改名
→ 至少1～2名成员先反应群名，母亲再接一句
→ 之后才开放玩家发言并进入坦白、逐人调侃和回国正事
```

必须检查：

- 玩家名来自邀请点击时的当前 Persona，并在该时刻冻结；
- 五秒期间修改 Persona，不会改变最终群名；
- 网页刷新、关手机、切分支、回档后不会用新的 Persona 重取群名；
- 入群与改名必须是两条真实、不同批次的系统记录；
- 系统消息能通过手机读库安全过滤，不会因 `发: 系统` 被错误丢弃；
- 系统消息不被普通群消息格式验收误杀；
- 五秒刷新恢复时前端立即锁输入，后端也拒绝陈旧 UI 发送；
- 首轮群名反应已写库但路线状态未提交的短竞态，不会允许玩家抢跑或重复生成；
- 入群按钮旧页面重复点击不会留下孤立系统消息；
- 母亲永久留群但不获得雌竞资格。

### 4.10 结局期手机社交

完成《双重继承》后，姐妹群、私聊和朋友圈进入成熟关系语义，但不能全员全知。

每名成员的认知只能来自：

```text
本人阶段；
本人已完成承接与结局；
群内真实摊牌记录；
公开朋友圈；
本人私聊记忆；
已落库的家庭结构事实。
```

必须检查：

- 一次性结局群聊余波只在下一个安全夜晚触发一次；
- 母亲说明父亲已离开、玩家正式接管、自己继续留302；
- 不泄漏机场视频或父亲知情；
- 已完成结局或已经摊牌的角色不会失忆后重新震惊；
- 未完成结局的角色不会被提前写成已完成；
- 公共朋友圈、姐妹群、私聊／仅你可见三层称呼和知识边界不同；
- 其他角色不会同时轰炸手机，首次反应应懒触发或按既有非阻塞机制；
- 群聊余波生成失败不消费状态；成功写库后才标记完成；
- 手机刷新、摘要压缩、引用、撤回、分支隔离不会删除或伪造强事件。

## 八、重点怀疑点

以下不是已确认 BUG，而是新窗口必须优先验证的高风险点：

1. 当前工作树可能同时残留旧版“待迎接父亲／迎接父亲”实现与新版商店票实现，存在双入口或状态枚举不一致风险。
2. `schema.ts`、`schema.json`、`initvar.yaml` 与生产系统阶段名可能不一致，`catch('未开始')` 可能把开发档中途状态静默重置。
3. `回国`完成可能被某个消费者错误当成“父亲审核已结束”，导致正式交权前经济审核提前停掉。
4. 购买《双重继承》与使用场景票可能共用同一个ID，商店完成名单、背包和商品可见性存在误判风险。
5. 视频第7张结束与`同步双重继承时间节点`可能形成两个完成生产者，导致直接完成、重复初始化长期水位或重复移除钥匙。
6. 最终收束固定兜底是否真的接入两次失败路径，而不是只有导出函数没有消费者。
7. 终幕后UI可能隐藏普通输入，却同时被`in-scene`或Dock条件误判，导致最终瓷砖也无法点击，形成软锁。
8. 父亲家常电话可能继续复用普通报表结构，并被通话提示模板带回楼务问责语义。
9. 经济系统可能为了停止父亲审核，顺手停止胜任度、收租、维修或现金等仍应继续的经营玩法。
10. 母亲圆场可能只在提示词中停用，生产器仍会写记录或污染父亲电话。
11. 结局姐妹群余波可能直接在局部数据对象把状态改成“已完成”，却没有通过MVU原子提交，刷新后重复发送。
12. 微信系统消息`发: 系统`、动态`群昵称`扩展字段、刷新镜像和原始库投影之间可能丢字段，导致刷新后群名重取或系统消息消失。
13. 五秒期间切Persona、关手机、刷新、回档、切聊天后，旧异步任务可能迟到写入新时间线。
14. 首轮群名反应消息已落库、路线状态未提交时，手动发送可能重复触发同一首拍。
15. 手机社交画像可能把全局完成ID直接当作所有群成员共同知识，破坏未摊牌角色隐私。
16. 9张《回国》CG、11张《双重继承》CG和母亲视频序列可能只在开发目录存在，正式资源函数或不可变标签并未真正接线。
17. 测试可能大量采用源码正则断言而没有走真实运行事务；需要补充行为复现证据后再下结论。

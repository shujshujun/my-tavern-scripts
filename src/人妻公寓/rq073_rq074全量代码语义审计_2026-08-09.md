# 《人妻公寓》rq0.73→rq0.74 全量代码语义审计（2026-08-09）

> 审计目标：以 `rq0.73` 为行为基线，完整比较 `rq0.74` 与当前修复工作树，区分“拆分直接丢失”“0.74 修复诱发”“旧缺陷被新流程放大”“设计性移除”和“未回退”。审计与修复已纳入 `rq0.75`。

## 0. 结论

全量审计确认：rq0.74 并没有丢失“大部分”旧功能，但确实存在两项由功能拆分直接造成的运行时丢失，以及一项由 rq0.74 临时楼修复诱发的高危数据删除缺陷。

1. **拆分直接丢失（2 项）**
   - 手机渲染注册模块不在生产入口的运行时依赖图中，导致微信白屏。
   - 移动端房内操作拆成抽屉后默认折叠，公园晨跑 `TRAIN` 动作仍被生产但入口不可见。
2. **0.74 修复诱发（1 项，高危）**
   - 临时回合楼“转正”只触发宿主防抖保存，Promise 返回不代表 `true→false` 已持久化；下一次启动或重试的全历史扫描会把仍为 `true` 的既有楼层误判为残留并批量删除。父亲来电不是删除者，正文失败按钮也不直接删历史，但重试可能触发这条扫描链。
3. **旧假设或交互缺陷被 0.74 新流程放大**
   - 无新正文的时间推进重新认领当前房间正文幕，造成跨房旧正文泄漏。
   - 新手引导完成立即启动手机 AI 节拍，与下一步正文生成争抢通道。
   - 完整流式正文已经显示、底层 Promise 随后拒绝时，旧失败路径仍回滚正文与楼务，造成正文消失、任务再次出现和误导性的工具箱提示。
   - 连续反感离场计数跨房／跨拜访串联，离场只清一部分在场状态，造成地图头像、立绘与在场人物分叉。
4. **确认不是拆分丢失**
   - 远程楼务竞态、同场双人立绘视觉比例、跨房正文幕所有权假设在 rq0.73 单体代码中已经存在。
   - `数据库失败回退正文 API`、`随AI输出`、跨回合变量补写、电话软事件占强队列等能力是 rq0.74 明确退役的旧语义，不应恢复为“丢失功能”。

## 3. rq0.73 发布后修复族审查

### 3.1 修复仍存在，未被拆分覆盖

- 日常时间行动独立生成，不把上一轮行动泄漏进新请求。
- 时间动作不会借数据库 AI；睡眠只在生成／事务成功后跨到次日。
- 原生正文租约区分正文生成与手机、数据库、隔离 `generateRaw`。
- 数据库四张 `RQ_` 表摘要约束、字数／枚举／SQL 边界。
- 微信未就绪 `-1` 时间线、实时已读锚与分支过滤。
- 数据库迟到租约、超时释放和记忆胶囊预算。
- 父亲电话硬状态、母亲线索原子合并、软余波不阻塞全局强事件。
- 跨户丈夫强制剧情归属与软上下文隔离。
- MVU 外置解析不回落正文 API，不做跨回合变量补写。
- 隔离行动草稿／准备／提交／回滚事务。
- 堕落值两段式精确写权、日额度按实际落地增量记账、阶段线路封顶。

### 3.2 确认由修复诱发：临时回合楼批量删历史

五问闭环：

1. **设计初衷**：生成开始时创建带本轮令牌的临时 user／assistant 楼；成功后转正，失败只删除本轮临时楼，避免误删既有正文。
2. **正常运行**：登记 `_rqgy回合临时:true` → 最终整表写入 → 两楼改为 `false` 并持久化 → 后续恢复扫描零命中。
3. **游戏作用与影响**：保证失败、取消、重掷、回档不残留半成品，同时保护所有历史聊天与往事索引。
4. **BUG 根因**：rq0.74 的 `setChatMessages(..., refresh:'none')` 只安排宿主约 1 秒防抖保存；Promise 完成不代表转正已写入聊天文件。启动／重试恢复又扫描全历史所有 `true` 标记，于是一次异常可删除多轮甚至几乎全部历史。父亲来电只是常见观察点；失败按钮只是可能进入下一次恢复，不是批量删除实现。
5. **修复影响与兼容**：转正后显式调用宿主 `saveChat()`，等待并复核 user／assistant 两楼均为 `false`；自动恢复只允许聊天尾部同一令牌的一条 user，或连续 user＋assistant。多令牌、非尾部、超过两条、角色倒置、对象／令牌不一致全部失败关闭并保留历史。旧异常数据宁可报警不自动删。

行为测试覆盖：对象引用漂移、楼号替代、错令牌、错角色、非尾部、多回合、多令牌、转正持久化、失败／取消、变量解析超时、回档／分支切换和数据库时间线栅栏。

## 4. 旧缺陷或交互链被 0.74 放大

### 4.1 任意时间推进串出其他房间正文

1. **设计初衷**：正文舞台只显示本房间当前幕；移动立即使旧幕失效。时间动作只有真正产生新正文才可成为新幕。
2. **正常运行**：房间、聊天 ID、时间线世代和消息锚共同确定幕归属；无新正文的推进只更新状态，不认领舞台。
3. **作用与影响**：避免 A 房操作后把 B 房旧记录错误显示为当前叙事。
4. **根因**：rq0.73／rq0.74 的 App 都在 `回合完成` 时无条件把 `幕房间` 设为当前房间；0.74 增加了更多“不生成新正文但会完成”的时间路径，使旧假设更容易暴露。
5. **修复与兼容**：新增正文幕归属状态；移动立即作废旧幕，只有本次确实更新正文才绑定当前房间。普通正文和独立演出仍能正常成为新幕。

### 4.2 新手引导去信箱时报 AI 回复失败

- 序章父亲来电完成后，旧接线立即启动普通手机 AI 节拍；玩家紧接着执行引导正文时两个生成通道争抢。
- 当前序章完成只同步确定性楼务微信和红点，不启动手机 AI 节拍；手机 AI／节拍在途时正文入口也有明确碰撞门。

### 4.3 楼务正文消失、工具箱提示和任务重复

- 工具箱是永久门槛，不是消耗品；`结算管理任务` 只扣体力／精力／现金等方案成本。
- 流式正文已经完整显示后，底层 Promise 仍可能拒绝。旧失败路径删除本轮正文并回滚任务，于是楼务仍处于活跃状态，下一次进入又显示楼务；客户端恢复到旧快照时还可能给出误导性的工具箱门槛提示。
- 当前只在完整回复封套、自然句末且无协议残片时保留完整流并继续原子结算；半句或协议残片仍失败关闭。失败广播延后到临时楼、聊天快照和事务锁都恢复之后，避免 UI 读取瞬态库存／任务状态。
- 成功结算和重复提交均新增行为断言：背包中的工具箱保持不变；完成票据保证奖励、资源和摘要只提交一次。

### 4.4 角色未推进时间却离场、头像／立绘／在场不一致

- 0.62 后位置仍只按绝对时段和作息推算，没有恢复旧版“普通聊天推动时间”。
- 不推进时间也可能离场是当前社交规则：同次拜访连续三轮真实反感会离开。
- BUG 在于旧反感计数跨地点／跨拜访串联，且离场只清部分 `_在场`，没有同步清 `_粘滞`，导致地图头像还亮、立绘和在场人物已消失。
- 当前按地点＋进房令牌计数；人物不在场即清计数；真实离场同时清 `_在场` 和 `_粘滞`。角色日程移动规则未改。

## 5. 设计性移除，不恢复

| 旧能力 | rq0.74 语义 | 结论 |
|---|---|---|
| 数据库报错后再尝试正文 API | 可能双请求、双计费，数据库失败必须原路失败 | 明确退役，不是拆分丢失 |
| `随AI输出`／正文变量路线 | 统一使用官方 MVU 外置解析；正文 API 不承担变量兜底 | 明确退役 |
| 跨回合变量待补／正文补写 | 当前回合解析失败不污染下一回合 | 明确退役 |
| 电话软事件占 `_待发送事件` | 强队列只保存真正强制剧情；电话软余波走独立状态 | 语义重构 |
| 一步式 `执行隔离事件` | 改为可回滚事务 | API 替换，不是功能丢失 |
| 阶段 0 任意晋阶 | 只允许验证过的礼物开门路径 | 规则收紧 |

## 1. 目标与来源

保留事件的因果、角色归属、信息揭示顺序和关系变化；允许重新设计景别、机位、姿势、剪辑点和每段所需图片数。
“大致剧情”不等于只保留氛围：观众应能说清谁带来什么、给谁看、为什么留下、观看改变了什么。

当前剧情依据是《录像带_整场叙事草案_v1_2026-08-31.md》及用户最新澄清；2026-08-25共享结局文件降为历史资料，不能据其预设何俊生被迫观看或搬离202。
本轮没有重新逐页审核原漫画，不把旧逐格描述伪装成本轮原作复核。

当前素材试做范围仍为周小满 → 顾国栋这一侧。整体叙事保留两户交叉关系；不自动把另一侧镜头翻倍生产。

## 2. 本轮改变什么

| 项目 | 新口径 |
|---|---|
| 漫画原框 | 作为剧情出处，不作为构图模板 |
| 镜头设计 | 从每一拍需要传达的信息重新设计，可以拆分、合并、换角度 |
| 数量 | 不再以原91框／剩余81张为生产配额；按节拍覆盖决定 |
| 结构控制 | 如确有需要，可按新分镜自制布局或姿态参考；不要求来自原漫画裁切 |
| 镜头相似度 | 不再要求姿势、边缘、主体占比与原框一致；不再以叠图相似度判定新镜头 |
| 素材身份 | 同一角色在相邻镜头中仍须可辨认；衣着、房间、道具保持连续 |
| 合格依据 | 画面能表达该拍事件，角色和空间不混乱，前后镜头能连起来 |
| 历史候选 | 保留原文件、SHA、拒绝原因与原结论；新口径不自动撤销旧审核 |
| 游戏接口 | 不改状态机、剧情结算、Schema、正式素材接线或发布产物 |

旧 `rqgy-vtr-shot-recreation` 的逐框定位、原漫画控制图、两框镜头相似度和81张生产门只描述旧任务，不能用于否决新叙事分镜。
通用的原件保护、明确编号、角色身份、图文一致、审核真实性仍保留。
不把改编授权理解成自动更新模型／节点、自动发布或批量复用失败图的授权。

## 3. 剧情节拍：先锁定事件，再安排画面

以下是非露骨的剧情提要，不新增原作没有的亲密动作，也不作为露骨画面生成指令。

| 节拍 | 必须传达的事实 | 可自由改编的表现 | 本轮状态 |
|---|---|---|---|
| B01 等待与到访 | 丈夫在家，另一户的妻子带着交付物上门 | 手机、钟声、敲门、开门可合并或拆分 | 已用现有图预演 |
| B02 确认身份与来意 | 来客身份明确，交付物与丈夫自己的妻子有关 | 双人中景、设备特写、短对白 | 已用现有图预演 |
| B03 留下共同观看 | 送片人留下，不是放下东西就走；播放尚未开始与已经开始必须区分 | 黑屏设备、邀请、移步室内 | 预演到邀请为止 |
| B04 观看与知情变化 | 记录来自之前发生的事情；观看现场与记录中的时空不能混淆 | 环境、人物反应与非露骨对白交叉组织 | 只有节拍，未制作画面 |
| B05 另一户的对应事件 | 两路交付属于同一安排，并行发生 | 通过对白和明确的空间标识揭示；不要求固定原作切点 | 只有节拍，未制作画面 |
| B06 各自的现场回应 | 两位丈夫都自愿观看，但反应可以不同；不预设何俊生的长期结局 | 不同反应与亲口回应 | 由2026-08-31整场草案重新讨论，不改结算 |
| B07 离场与交付确认 | 送片人完成本次任务后离开；不能提前宣布另一户也已完成 | 收起设备、门口告别、交付记录 | 只有节拍，未制作画面 |
| B08 返回与收口 | 两条线各自完成后再共同收口；新的关系事实承接已完成的事件 | 返回后的普通对话与结果核对 | 沿用当前结局设计，不改结算 |

## 5. 新的制作顺序与验收

1. 写清这一拍新增了什么信息、谁知道、谁不知道，以及它通向哪一拍。
2. 指定角色参考、场景参考、当前衣着和道具状态。先检查现有资产是否足够。
3. 设计一张或数张能传达事件的分镜；不对照漫画人体姿势追求相似。
4. 审核关键帧时先问“看得懂在发生什么吗”，再看身份、空间、手和道具归属。
5. 放入前后镜头一起查看。单张好看不能抵消服装跳变、人物换脸、时空混淆或动作断裂。
6. 确有动态需求时才进入图生视频；静态分镜失败不得靠动画或滤镜掩盖。
7. 将候选、已用资产和最终批准分开登记。此预演没有产生新的正式CG。

验收项：剧情事实、因果顺序、角色归属、角色外观连续、场景／道具连续、动作可读、相邻镜头衔接、图文一致。
“像不像漫画原框”不再属于验收项。

生产原件保持不可覆盖。人工编辑是否采用、如何登记派生版本，需要在后续具体镜头方案中写明；本轮不回头修复历史拒绝图。

## 6. 研究依据与可用边界

- [foxdit 制作复盘](https://www.reddit.com/r/comfyui/comments/1tv0yss/i_used_ltx_23_to_make_a_full_characterdriven/)：作者自述采用独立关键帧编辑、镜头生成和剪辑。属于创作者经验，未在本机复现。
- [Qwen 分镜作者说明](https://www.reddit.com/r/comfyui/comments/1v72wvk/storyboard_frames_with_opensource_ai_consistent/)：角色、场景与机位分别控制；作者明确多人更难。属于候选方法，不是本机效果保证。
- [Runway 官方长片流程](https://help.runwayml.com/hc/en-us/articles/26871350018835-How-to-create-longer-videos-and-films)：分镜、角色／环境参考、逐镜头制作与剪辑。
- [Qwen 官方模型说明](https://huggingface.co/Qwen/Qwen-Image-Edit-2511)：有多参考编辑机制，但本轮未安装、运行或验证该模型。

这些依据只用于普通剧情分镜与通用制作方法，不构成任何镜头的一键量产承诺。

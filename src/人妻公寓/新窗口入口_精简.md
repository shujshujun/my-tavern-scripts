### 已完成：原生正文租约与时间动作误锁

设计目的不是“任何 AI 请求都锁游戏”，而是保护酒馆原生正文从 prompt、助手楼到 MVU 结算的事务，避免时间推进中途改写状态。旧 `_isInAiCycle` 被任意 `CHAT_COMPLETION_PROMPT_READY` 置真，手机／数据库／隔离 `generateRaw` 没有匹配正文结算，导致小憩等永久提示“正文模型仍在生成或结算”；真实原生 API 失败也只发 `GENERATION_ENDED`，旧逻辑不会释放。

当前落盘：

- 新增 `脚本/游戏逻辑/原生正文租约.ts`：宿主 `GENERATION_STARTED` 登记开始票，PROMPT_READY 按聊天、时间线、user 楼、消息引用与不可复用 owner 认领；旧 owner 不能释放新租约。
- `index.ts`：时间推进／撤销只查询有效正文租约；辅助 prompt 不认领；隔离／时间事务中的真实原生请求明确拒绝；`GENERATION_STOPPED(id)` 忽略 Tavern Helper 的非空生成 ID；`GENERATION_ENDED(messageCount)` 以精确预期助手楼判断失败或继续等待 MVU。
- `GENERATION_ENDED` 在开始票仍处于“等待 prompt”时，不再无条件作废当前票；只有整数 `messageCount` 精确等于该票预期助手楼层时才清票。旧轮结束事件、缺失／非整数／较大消息数不能清掉新票；等待票本身仍不形成时间锁，下一次真实开始可以替换旧等待票。
- 专项测试：`原生正文租约.test.mjs`、`原生变量时间线事务.test.mjs`、`时间独立生成隔离.test.mjs`、`时间按钮接线.test.mjs` 共 39／39 通过。

## 七、v0.74 已完成：堕落值增长逻辑（2026-08-09）

### 玩家反馈与任务边界

玩家在 v0.73 强烈反馈：正常游玩中堕落值经常完全不增长，或增长速度明显慢到无法形成合理进度。v0.74 已按独立 BUG 完成语义排查与修复，没有用放大 `+1~3`、每日上限或降低晋阶门槛掩盖写权、守护与反馈问题。

### 已知源码事实（只作排查起点，不是根因结论）

- `schema.ts` 声明堕落值由亲密回合 AI 单轮写入 `±3`；`stageConfig.ts` 的晋阶门槛为 20／40／65／90。
- `回合引擎.ts` 已提示：实际暧昧／亲密／性内容应按人物反应更新堕落值；正文后还有尺度稽查。
- `mvuIO.ts` 现在采用“两段式权限”：解析候选视图先让本轮可写焦点妻看见堕落值与身体开发；稽查确认逐角色实际等级 ≥1 后才补精确亲密写权。旁观者、丈夫侧、实际等级 0 与拒绝兜底仍然关闭。
- 正文变量路线与 MVU 外置路线都消费同一份逐角色稽查结果，不再出现正文已经自然升级、外置解析却根本看不到堕落字段的死路。
- `守护系统.ts` 仍保留非亲密拍回、单轮 `±3`、冷落余波冻结、每日每妻 `+8`、阶段线路封顶与阶段底线；日账改按最终实际落地增量记录，被线路或日上限挡住的部分不再空耗额度。
- `冷落系统.ts` 会按世界时段结算下降与安抚余波；必须区分“本轮增长失败”和“增长后又被冷落结算抵消”。

### 排查结论与保留的完整生命周期门

1. **设计初衷**：哪些互动应涨、应不涨、应下降；单轮、每日、阶段线路与晋阶节奏各自想保护什么。
2. **正常链路**：玩家输入／强制剧情 → 亲密判定与尺度协议 → 正文 → 内置或外置变量解析 → raw 候选 → 守护 → 成长账／风闻／疑心结算 → 最终 `stat_data` → 客户端显示。逐步记录堕落值、`变量范围.亲密妻`、可写视图、解析变量块、守护前后值、`_堕落日账` 和线路封顶。
3. **游戏作用**：按真实门槛计算从各阶段正常晋阶所需的互动轮数与世界天数，判断玩家所说“十分缓慢”是否由多个本意合理的门叠加成不合理体验。
4. **BUG 根因**：区分至少五类——未开放写权、解析模型未写／写错路径、raw 被 Schema 或守护回滚、线路／日账／余波有意封顶、最终提交或显示读取旧值。
5. **影响与兼容**：任何修复都要覆盖正文模型变量路线与 MVU 外置路线、游戏内自定义输入与原生输入、重写稿、失败／超时／取消、重掷、回档与并发；只复现当前版本新局，不补旧存档迁移，不得扩大后台人物写权或绕开阶段线路。

### 最小复现矩阵与验收

- 路线：正文模型变量解析、MVU 外置内置解析（数据库可用／仅自定义 API）、MVU 外置旧桥接路径。
- 场景：显式亲密词、昵称／代词导致预判可能漏判、正文自然升级但输入不显式、稽查重写后实际等级 ≥1、普通闲聊对照。
- 状态：阶段 1—5、同日未满／已满 `+8`、线路未完成封顶／已完成、冷落余波无／诉苦待触发／安抚中、多人亲密主焦点与旁观者。
- 每格必须证明最终存档值，而不是只断言提示词或解析文本；合法 `+1/+2/+3` 应落地，超 `±3`、非亲密、后台人物和有意封顶仍应失败关闭。
- 先补能稳定复现玩家问题的行为测试，再决定是代码修复、节奏调参，还是两者拆成独立决策。未经语义证据不得批量调高收益或降低 20／40／65／90 门槛。

专项证据位于 `堕落值增长写权.test.mjs`、`堕落额度与可见反馈.test.mjs`、`变量守护.test.mjs`、`冷落系统.test.mjs` 与 `MVU外置与二次结算互斥.test.mjs`。后续若再出现“不涨”，必须区分字段可见性、精确补权、解析候选、守护落地、线路封顶、日额度、冷落余波及 UI 反馈，不得直接调门槛。

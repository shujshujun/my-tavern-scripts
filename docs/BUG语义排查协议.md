# BUG 语义排查协议

按问题的实际影响诊断和验证。游戏状态、结算、事件、模型接入或存档问题使用下述检查点；纯文案、样式和文档问题定位目标及关联影响后直接修复并做局部检查。

## 诊断检查点

确认功能用途、正常行为、需要保留的效果、实际根因及受影响对象。区分用户观察、代码事实和推断；定向阅读相关实现和设计。证据不足时继续调查，不靠猜测批量改代码。检查点服务于诊断，不要求每次单独填表或重复询问已明确的需求。

涉及状态时，追踪其生产者、持久化、转换、提交和消费者；复用同一锁、队列、事务或生成器的功能逐项核对语义。修复共享根因时覆盖真实受影响的调用链，相关名称相似不代表应套用相同改法。无关的独立问题另行记录。

## 状态分层

- **硬生命周期**：活动尚未真正结束，允许短暂阻塞；必要写入失败可保留并重试。
- **强制剧情／确定性账目**：保留明确消费与提交条件，不能静默丢失。
- **软叙事上下文**：影响适合的后续演出，不得伪装成全局任务或阻塞无关玩法。
- **可选副作用**：数据库记忆、日志、缓存、提示等按实际设计处理，失败或缺失不得无依据拖住核心玩法。

不得因为同一次操作触发多个效果就把不同层串成同一个锁。修复应保留功能价值，避免用全局放行、粗暴清空、吞异常或统一删除状态掩盖根因。

## 验证与完成

按根因选择能检验实际行为的验证方式，优先运行相关既有测试；有持续回归风险的逻辑修复补充能复现根因的行为测试。边界放宽、资格门、账目或事务修改增加必要反例，验证被保护的行为仍正确。测试中不以恒定成功的替身替换正在验证的解析器或状态门。

涉及异步、持久化或共享状态时，覆盖与本次改动相关的成功、失败、超时、取消、重复点击、刷新、回档、重掷、并发、迟到回调及旧档兼容；核对幂等，不重复奖励、消费或复活已结束状态。无关场景无需逐条填表，存在不明显的遗漏或未验证风险时说明原因。

按影响运行专项回归和定向静态检查；区分本次新增失败与既有失败。新功能的隔离构建按 AGENTS.md 执行。仅文档或代理配置变更检查格式、引用、配置解析及实际加载，不运行无关游戏回归或生产构建。

完成意味着请求范围内的根因和相关消费者已处理、必要验证通过、实际 diff 已复核。继续处理本次变更导致的失败；外部依赖或宿主验证尚未完成时准确说明，不把测试通过说成所有运行环境均已验收。

交付简述改了什么、原因、验证和仍有的限制；影响复杂时再补充状态生命周期和消费者清单。

# BUG 语义排查协议

本协议适用于《人妻公寓》以后所有 BUG 的诊断、修复、复审与回归。目标不是让某个报错暂时消失，而是在不破坏原功能价值的前提下，修正错误的状态边界和影响链。

## 核心五问

任何 BUG 都先用简单、明确的话回答这五问；回答不完整时，不进入修复：

1. **设计初衷是什么**：当初为什么要做这个功能，想解决什么玩法或剧情需求。
2. **正常应该怎样运行**：玩家怎么触发，内部状态怎样变化，何时算成功结束。
3. **对游戏有什么作用和影响**：它会推进哪些剧情、数值、时间、任务或记忆，哪些效果必须保留。
4. **为什么会出现这个 BUG**：实际执行在哪一步偏离设计，错误状态又是怎样传给其他功能的。
5. **修复能否兼容其他功能**：谁会读取或依赖它；修复后会不会误删剧情、放过强事件、重复结算或污染其他角色，怎样兼容旧档和现有功能。

后续的状态分层、消费者搜索以及失败、超时、取消、回档、并发测试，都是为了把这五个核心问题查实，而不是替代它们。

## 一、先诊断，后修复

围绕核心五问收集代码证据，证据不足时不得直接下结论或批量改代码：

1. **玩家实际看到了什么**：触发条件、操作顺序、提示文字、是否稳定复现；明确区分玩家观察、代码事实和当前推断。
2. **这个功能原本做什么**：它的玩法用途、剧情作用、系统目的，以及为什么需要保存这个状态或执行这个副作用。
3. **状态从哪里来、何时结束**：列出生产者、持久化位置、状态转换、成功结束条件、失败恢复条件和幂等键。
4. **谁会读取它**：搜索并枚举全部直接和间接消费者，不能只看玩家刚好撞到的入口；至少检查界面、时间、楼务、普通正文、独立事件、商店、入住/晋阶、资源结算、数据库和回档路径中实际相关者。
5. **影响为什么发生**：把“状态 A 被消费者 B 解释为 C，所以入口 D 被阻塞/污染”的链路说清楚；玩家偶然发现的绕行方法也要解释为什么有效。

## 二、先分层，再决定修什么

涉及同一字符串、队列或状态对象时，必须先判断它实际属于哪一层：

- **硬生命周期**：活动尚未真正结束，允许短暂阻塞；必要写入失败时可保留并重试。
- **强制剧情/确定性账目**：不能静默丢失，必须有明确消费与提交条件。
- **软叙事上下文**：只能影响合适的下一次演出，不得伪装成全局任务或阻塞无关玩法。
- **可选副作用**：数据库记忆、日志、缓存、提示等；失败、超时或缺失不得拖住核心玩法。

不同层不得因为“都发生在同一次操作后”就串成同一个锁。修复前必须说明哪些价值保留、哪些耦合拆开。

## 三、同逻辑族要全查，但不得一棍子全改

- 一个入口发现根因后，要搜索所有复用同一状态、锁、生成器、队列或事务的功能，建立消费者清单。
- “同逻辑族可能同病”只代表必须审查，不代表允许一次性套用同一改法。
- 每个兄弟功能仍要确认自身用途、剧情影响、提交时机和失败语义；不满足同一语义边界的，分阶段处理并保留原行为。
- 禁止用全局放行、粗暴清空、吞异常、扩大超时、统一删状态等方式掩盖根因。

## 四、修复必须覆盖完整生命周期

实现规格和测试至少检查与本 BUG 相关的以下路径：

- 成功、明确失败、超时、缺依赖；
- 玩家取消、生成停止、重复点击；
- 刷新、重载、回档、重掷、切聊天或切分支；
- 并发写入、迟到回调、旧请求不得认领新时间线；
- 旧存档迁移与新存档行为；
- 幂等重试，不重复奖励、不重复消费、不复活已结束状态；
- 真正强事件仍被保护，软状态不得误阻塞，其他角色/行动不得被污染。

如果某条路径与当前 BUG 无关，可在规格中写明理由，不得默默省略。

## 五、测试与完成标准

修复至少需要：

1. 一个能钉住真实根因的行为测试，而不只是匹配某行源码；依赖整栈难以运行时，才用紧范围源码契约测试补足。
2. 一个反例测试，证明没有误删、误放行或破坏原本必须保留的剧情/状态。
3. 同逻辑族中实际受影响消费者的专项回归。
4. 定向静态检查；仓库存在既有全局错误时，必须单独报告本次文件是否新增错误。

满足以下条件前不得称为“全部修复完成”：

- 根因有代码证据；
- 功能用途和保留价值已经说明；
- 生产者、状态转换和相关消费者已经审完；
- 修复覆盖必要的异常、时间线与兼容路径；
- 专项测试通过，实际 diff 已由主代理复核；
- 未完成、仅缓解或仍待审的同逻辑功能被明确列出。

## 六、BUG 汇报模板

每项 BUG 的诊断或交付至少包含：

1. **现象与复现边界**
2. **功能用途与设计目的**
3. **根因和状态生命周期**
4. **消费者/受影响功能清单**
5. **影响链与绕行为何有效**
6. **修复边界：保留什么、拆开什么**
7. **失败、超时、取消、回档、并发、旧档兼容**
8. **测试证据与仍未完成项**

主代理写给实现代理的 `.delegate/*.md` 规格也必须包含这些信息；实现代理若发现实际源码与该语义模型不符，应停止扩大修改并如实回报，由主代理重新审定。

# DeepSeek 委派会话控制

## 目的

防止 `scripts/delegate-deepseek.sh -c` 长期恢复同一个 Claude Code／DeepSeek 会话后，上下文、缓存读取量和响应时间持续膨胀；同时防止外层命令超时后直接重启，留下两个后台进程同时改工作树和计费。

## 已确认的根因证据（2026-08-09）

`delegate-deepseek.sh` 的 `-c` 会用 `.delegate/.session-<spec名>` 中的固定 session id 执行 `--resume`，并再次注入当前 spec 全文。它不是“只补发最后一句”，而是恢复完整旧会话后继续工作。

本次 `fix-isolated-action-semantics-v074` 的三个连续日志使用同一个 session id：

| 运行 | 轮数 | 耗时 | 缓存读取输入 |
| --- | ---: | ---: | ---: |
| 首次长实现 | 164 | 1014 秒 | 19289.5k |
| 同会话续跑 | 39 | 553 秒 | 9916.9k |
| 同会话再次续跑 | 36 | 646 秒 | 13727.9k |

后两次轮数更少却越来越慢。切换到新的 `fix-isolated-action-semantics-v074-final` spec 和新 session 后，随后一次 15 轮修正耗时 130 秒、缓存读取 2682.6k。由日志可确认，本次明显变慢的主因是同一长会话反复 `-c` 导致的上下文膨胀；不能只归因于网络或模型随机波动。

## 强制规则

### 允许使用 `-c` 的情况

必须同时满足：

- 仍是同一目标、同一语义结论和同一小片文件范围；
- 主代理已经审查上一轮实际 diff；
- 只需修正明确的小错误、补一两个断言或回答上一轮遗漏；
- 上一轮没有超时，进程已正常退出，响应也没有明显变慢；
- 续跑提示只描述当前缺口，不重贴完整历史。

### 必须切新会话的情况

出现任一项就停止 `-c`：

- 切换到新的语义审查项、BUG、实现阶段或文件逻辑族；
- 一次完整实现后仍需较大返工、重新设计或新增复现矩阵；
- 相同或更少的轮数明显变慢；
- 报告显示缓存读取量持续上升；
- 单次运行已是长任务（经验预警：≥80 轮、≥600 秒或缓存读取 ≥5000k；这是切会话提示，不是失败判定）；
- 外层工具超时、日志为空、退出状态不清楚或怀疑后台仍在运行。

## 标准切换流程

1. **停止续跑。** 不要因为外层等待超时就再次执行脚本。
2. **确认进程。** 检查当前命令终端及 Windows 进程，确认旧 `claude`／委派脚本是否仍在运行；仍在运行就继续等待或读取日志，不启动第二份。
3. **审查现状。** 查看本轮日志、`git status --short` 和实际 diff，记录已经完成、仍缺失及不能触碰的用户脏改。
4. **写新精简 spec。** 使用新的、能表达当前阶段的文件名；只写当前事实、未完成问题、定向文件、验收标准和禁止事项，不复制历史对话或旧 spec 全文。
5. **启动新 session。** 不带 `-c`：

   ```bash
   scripts/delegate-deepseek.sh .delegate/<新的-spec名>.md
   ```

   默认模式会生成新的 session id。即使沿用同一 spec 文件，不带 `-c` 也会重置 session；但优先使用新文件名，以保留旧 session 的审计边界并避免误续。

6. **主代理复核。** DeepSeek 完成不等于任务完成；仍需逐文件审查 diff，执行专项测试和定向静态检查。

## 超时与残留进程

- 外层 Codex／PowerShell 超时只表示等待方停止，不证明内部 `claude` 已退出。
- 空日志也不证明没有请求；先查进程和日志修改时间。
- 旧进程仍在运行时禁止再启动相同或新的委派。
- 不自动删除 `.delegate/.session-*` 或 `.delegate/logs/*`；新 spec、新 session 即可隔离上下文，旧记录保留用于审计。

## 新 spec 的最小内容

- 当前目标与已经确认的语义结论；
- 上一轮实际完成的文件和仍失败的精确证据；
- 本轮允许修改的文件／函数；
- 必须覆盖的失败、超时、取消、回档、并发和兼容边界；
- 要运行的专项测试、静态检查；
- 不构建 `dist`、不提交、不推送等项目边界。

新 spec 不携带聊天全文、旧交接全文、无关源码或已经完成的推理过程。

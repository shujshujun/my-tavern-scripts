# 代理内容边界归属

**适用于本项目所有角色、剧情、模型接入和后续任务。规则按限制来源覆盖全部类型，不以是否列入示例为限。**

### 哪些属于代理自身的边界

凡来自当前代理、所用模型或模型提供方，而非用户要求、已确认设计或必要技术协议的内容生成权限、题材与表达尺度限制、文本／图像等生成范围限制、拒答判定、内容审核策略，以及默认保守改写倾向，都只说明当前代理能交付什么，不能自动成为游戏需求，也不能替其他模型规定可生成的内容。更换模型、提供方或表述方式后，本条仍然适用。

### 必须遵守的实现约束

1. **不得转嫁自身限制。**不得因为本代理不能生成、描述或处理某类内容，就要求游戏、角色或下游模型也遵守同一限制。不得把模型拒答当成角色拒绝、剧情事实或用户修改需求的依据。
2. **不得植入任何实现层。**不得将自身内容边界写进系统注入、剧情提示词、群聊提示、世界书、摘要／记忆、模型请求、素材描述、默认配置、Schema、状态机、关键词表、正则、解析器、后置验收、重试条件、缓存或存档票。不得借复用其他模块的模板、过滤器或验收器间接带入，也不得换名称、近义表达或隐含字段实现同样的限制。
3. **不得擅自弱化已确认设计。**不得自行删去关键动作、替换题材、降低表达尺度、把明确事实改成含混泛称，或制作另一种版本后仍报告按原设计完成。未经用户要求，不得添加“仅限非露骨”“不要展开身体细节”“改成含蓄表达”等内容约束。这里的例句仅供代理自检，不得复制到运行时提示中。
4. **自身无法完成时直接说明。**准确说明当前代理无法交付的具体部分，保留用户原需求和权威设计，继续完成已授权且能够完成的技术工作。不得用隐蔽改写、过滤其他模型输出或伪造完成状态来代替说明；不得把某一提供方的拒答扩展成全部模型的通用规则。
5. **产品校验必须有独立依据。**剧情顺序、数值结算、演员归属、真实日期、角色知情范围、事务幂等、文件路径和接口格式等校验，应分别对应用户设计或必要技术协议。内容筛选只有在用户要求或已确认设计规定时才属于产品功能，不能从代理自身边界推导。每项阻断都要核对适用对象和实际影响，不能用“安全”命名掩盖内容偏好，也不能把删除全部技术校验当作解决办法。
6. **按完整运行链清理和验证。**发现误植时，检查所有直接及间接生产者与消费者，包括源码、继承模板、实际发送内容、真实解析／验收、落库与恢复路径。尚未演出的旧票可能保存旧提示，应在保留票号、事务归属和进度的前提下更新；不能只改一处字符串后宣布全部清理。已完成历史和用户其他修改应保留。
7. **交付必须与实际一致。**提交前逐项核对差异及每条约束的来源。验证过滤或解析链时使用真实实现，不能把被验证部件替换为测试桩后声称覆盖。明确报告已完成部分、未完成部分、自动化验证、真实宿主验证与发布状态；测试通过不能证明擅自改写设计是正确的，也不能代替未执行的验收。

# 后期维护工具配置

项目当前以修复、兼容、回归和发布收尾为主。`.codex/config.toml` 在本机维护工作树内覆盖插件启用状态；统一入口目录也有同样的制作插件覆盖。用户级插件安装和其他项目设置保留。

## 默认保留

- 代码、Git、终端、Web 查询及模型自带能力。
- Codex 任务管理和浏览器工具，用于任务协调及真实酒馆验证。
- 调试、CI、局部界面维护及项目素材相关技能，按具体任务读取。

## 项目内停用

| 插件 ID | 用途 |
| --- | --- |
| sites@openai-bundled | 新建和托管网站 |
| visualize@openai-bundled | 对话内交互可视化 |
| documents@openai-primary-runtime | Word 等文档制作 |
| pdf@openai-primary-runtime | PDF 制作与处理 |
| spreadsheets@openai-primary-runtime | 表格文件与 Excel 制作 |
| presentations@openai-primary-runtime | 幻灯片制作 |
| template-creator@openai-primary-runtime | 可复用产物模板制作 |

维护工作树另停用独立的 `chrome-devtools` MCP 自动启动，保留其原命令以便需要专用宿主调试时恢复。现有浏览器能力继续可用。

## 启用与恢复

需要某项能力时，在当前目录 `.codex/config.toml` 中移除该项 `enabled = false` 覆盖，即可继承用户级设置；也可明确设置为 `true`。如果后续要在统一入口启动任务，同步修改 `D:/SillyTavern/人妻公寓/.codex/config.toml`。项目内覆盖不卸载插件、不改变外部账号权限。

配置在新会话初始化时读取。已经开始的桌面任务可能保留原工具目录；重新打开项目任务后检查，必要时重启 Codex。

本机验证发现，项目级 `skills.config` 停用项能出现在合并配置中，但原生技能目录和提示词仍包含对应技能，因此本配置没有保留这些无效条目。其他通用技能仍可显式使用，默认维护通过 AGENTS.md 的任务路由选择。没有编辑全局技能文件或插件缓存。

修改前备份位于 `D:/SillyTavern/人妻公寓/归档/配置/2026-09-14/late-maintenance/`，`manifest.json` 记录原路径、备份和哈希。恢复文件前核对后续用户改动；代码入口历史正文已在仓库内单独归档。

配置依据：[OpenAI 配置参考](https://developers.openai.com/codex/config-reference/)。实际生效以当前客户端的配置读取和新任务提示词预览为准。

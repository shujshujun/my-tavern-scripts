# 自然对话与事件进度设计

日期：2026-09-15。适用：九类关键词完成门与母亲茶话会的持续停滞问题。

本文件定义九类自然对话的产品行为、技术边界和验收要求。0.92.6 已把九类判断接入正式业务入口或正式恢复入口，并增加自动化回归。独立原型、真实模型观察器、原有回归、正式业务自动化分别记录，不互相替代；本次按用户要求不再运行 TauriTavern 实际流程。

## 玩家体验

玩家按自己的意思聊天。角色接住当前内容，表达自己的想法，也可以闲聊、暂缓或结束谈话。事情是否已发生、玩家是否作了决定，由后台根据上下文理解；玩家无需说指定的词，也无需为了补齐标记重演动作。

角色主动提及未完事项的理由来自剧情：眼前话题有关、角色获得新信息、有自己的新想法，或眼前行动确实需要一个回答。它是一次可选的自然承接，不是必须向玩家发问。解释自己的顾虑、补充情况、顺势做自己能做的事，也都是合适的回应。

不向角色提供“连续未命中次数”“重试次数”“进度解析异常”之类数据。不能把两轮、三轮、某个概率或等待若干分钟当作催促触发器。话题自然发展、玩家主动重提、环境发生实际变化，才构成新的对话机会。同一情境刚谈过就不重复主动提起。

玩家明确暂缓、拒绝、转题后沿其方向聊天；重新提出相关问题时再回应。只有会影响眼前行动的真实歧义值得澄清。选择长期未决是允许的；不保证玩家不作选择也能自动完成所有剧情。

普通闲聊不等于明确转开某个话题。玩家没有提及未完事项时，角色仍可因自己的决定、新消息或眼前安排主动说明情况。对话上下文需要分别记录“内容与事项无关”和“玩家明确要求暂不谈该事项”；不能用一个无关标签一律禁止主动性。新建议按建议表达，不能扩写成没有依据的住处、财物、关系或日程决定。

技术错误另行恢复。已保存的回复保留；系统提供轻量状态与“重新识别已保存对话”操作，不让角色用台词为解析器补作业。

## 三条独立流程

1. 对话：生成 → 提取完整可见内容 → 保存消息 → 显示。缺失进度附加信息本身不应吞掉完整回复。
2. 理解：读取当前事件及已保存上下文 → 识别玩家意向、角色选择、已发生动作 → 返回带原文引用的观察结果。
3. 提交：原有业务所有者检查事件版本、分支、必要事实、当前选择、物件/日程回执 → 原子保存 → 发出解锁、奖励、CG等副作用。

结构不完整的传输与“事实尚未完成”是不同问题。半截JSON、工具调用参数缺失、封套未闭合需要技术恢复；正常的暂缓和未决不触发自动重写。完成信息丢失时优先补取观察结果，不重新生成已显示的对白。

观察器只报告当前上下文支持的事实，不输出一个可以跳过全流程的万能“通过”。引用包括消息ID与片段位置；明确记录发言主体。玩家选择不能从角色猜测中提取；角色自己的选择不能归给玩家；旁白中的计划、假设、回忆和否定不能等同于当前动作已完成。

引用存在只证明来源存在，不能证明模型理解一定正确。因此真实模型的反例验证是独立验收层，不能用人工填好的观察结果替代。

## 九类接入约定

| 类别 | 由谁确定 | 应识别的语义 | 提交及自然承接 |
|---|---|---|---|
| 微信邀约 | 日程系统确定已生效的接受/拒绝和时间地点 | 自由表达的赴约意向、拒绝、提议改期、已有安排；区分提议与已生效变更 | 显示准确的约定记录；角色不必复述时间地点口令。玩家改期提议可照常显示，待日程重新裁定后才替换安排 |
| 孕产及家庭计划通知 | 孕情/家庭计划系统确定胎次、事件类型和发生时间 | 通知内容与事实是否冲突；区分已经发生与将来计划 | 业务发生与消息送达各自记录。报孕、性别、预产、生产、合照、住院/出院和家庭计划逐项适配，不能因玩家转题抹掉已发生事件 |
| 许曼君《分居》 | 玩家决定，原分居状态机提交 | 当面参与/其他参与方式/不参与/暂缓；后续继续或结束关系等原有分支 | 从玩家上下文理解实际选择，分别处理两个决定节点。未决可挂起，不反复把玩家送回必须答题的提示 |
| 许曼君《离婚》 | 当前场景事实与法律、物件状态的原所有者 | 证件已领取、所选参与者实际在场、牵手等当前动作、钥匙归档、居住选择 | 每拍只检查该拍事实。阶段与演员选择保留，不能一段泛泛结束语完成全线路；提交失败不提前发放后续效果 |
| 离婚后日常 | 当前日常事件与对应结算所有者 | 本次工作范围已明确、该范围内事项完成；处理改衣、房间整理、预算三类各自对象 | 范围和完成可跨轮积累，不强制说“尺寸/账本”等词。最终完成才结算一次奖励及冷却 |
| 《双重继承》 | 道具状态、角色自身选择、当前场景 | 钥匙实际位置、角色决定留下、门实际关闭 | 三项事实分别有来源。钥匙提及不等于归位；尚未完成的收束可保留。已完成的旧档不得倒退或重做 |
| 《不必停》 | 当前玩家意向、门状态与角色约定 | 当前是否继续、门的实际状态、后续联系/安排的真实约定 | 按每拍契约接入；不要求说出固定成语。玩家后来的暂缓/改变方向优先于旧的同意 |
| 《不再留门》 | 当前玩家许可与既有物件/操作所有者 | 本次许可、所允许的对象与范围、当前动作是否发生 | 保留已有按钮与自由表达两种入口；历史许可不替代本次许可，NPC台词不能替玩家许可 |
| 冷落安抚 | 当前面对面回合与原冷落系统 | 是否回应眼前失落、理解感受或表达具体支持；区分引用、否定、敷衍和转题 | 不要求说“别担心/我陪你”。保留对象、回合资格、余波和成长结算；每个合格回合最多计一次，不串到微信每日联系计数 |

表中“业务所有者”不等于每种事实已有独立按钮或回执。落地时须逐项核对：已有结构化状态直接读取；只有叙述事实则由观察器提供有来源的候选，再交给原状态机确认。不能为省事伪造一个可信回执。

通知可使用由真实业务数据生成的事实卡，承担日期、对象、地点等精确信息。NPC自然回复不必承担机器协议。确实与既定事实矛盾的生成稿应由技术层修复；无法修复时仍展示真实事实卡并说明本次对白生成异常。不能静默丢消息，也不能把玩家的改期提议误当作错误内容删除。

## 观察协议和恢复

每个待处理事件包含协议版本、事件ID、阶段版本、聊天/楼层/分支标识、参与者、当前步骤需要的事实及其来源。每批消息有唯一批次ID；观察结果只对应保存后的实际文本。

状态分别保存：事实累积、最新意向、观察是否完成、是否正在技术复核、事件是否已提交。未决/暂缓/拒绝是有效语义结果；协议缺失/超时/损坏是技术状态。二者不能共用“失败”计数。

正常路径同轮附加观察结果；无效时每批最多自动补取一次，只读已经保存的对话。失败后不无限重试；同一观察手动重识别的双击合并。茶话会若还有知情范围待确认原稿，先复核原稿，再识别其事件进度，各调用一次，只读取已保存内容。刷新中断的任务恢复成待人工重试状态，不自动发起一轮轮新请求。

旧批次晚到不能覆盖新批次选择。新消息已到而观察尚未完成时，不拿旧同意提交。提交端在真正写入前同时比较事件阶段和对话版本，不能只在请求开始时检查。回档、切聊天或切分支后，旧结果不得写进新状态。

事实允许跨轮累积，决定允许被后续明确表达修正；当前步骤已确定的客观事实不要求重演。行为与提交顺序由各原状态机保留，解释器不能改变线路原先的选择种类、演员安排和物件规则。

## 暂停与主流程锁

手机回复天然可以先保存、后提交进度；固定场景主回合还持有场景事务、MVU写入权和前台生成锁。正式迁移必须新增“本轮对话已保存、事件仍待续”的结束状态：保存有效楼层、挂起业务事件、释放本轮执行锁。不能直接忽略原验收错误后继续运行原来的完成分支。

下次自然回到事件时恢复相应步骤。玩家离开、取消、暂缓时按原场景生命周期清理临时楼层和租约，不保留一个永不释放的“正在生成”。奖励、冷却、公开事实与解锁只能发生在业务成功持久化之后。

原回合引擎和原生入口的验收/提交都要适配；只改其中一个仍可能显示正常但无法推进，或越过另一入口的保护。

## 旧档与预设

旧档已有完成事实继续有效，不重判、不反向清空。正在等待的事件首次运行时初始化新观察状态；无法还原的历史依据保留未知，不凭空补成完成。纯历史记录的旧兼容读取不能重新成为新消息的关键词回退门。

正文、工具调用参数中的最终回复都经统一输出抽取后处理；reasoning内容不充当可见回复或事实来源。防截断开关对应的返回格式分别用固定样本回归。附加进度丢失只影响解释，不影响已取得的完整可见正文。

现有群聊的知情/隐私过滤也需要语义作用域复核，例如“先不谈某件事”不能仅因为出现该词就被判成泄露。该残余问题属于正式接入验收，不能被新的观察协议遮住。

## 验收门槛

九类各自通过才算全部通过。用户在发布0.92.6时明确取消再次使用TauriTavern验证实际流程，改用生产入口、实际状态所有者和隔离存储的自动化回归。模型与宿主I/O替身必须明确标注；这些测试验证协议、接入与结算，不声称验证了真实模型的自然表达效果。未接正式入口、只检查生成文本或只检查共用协议，均不足以证明该类已经接入。

每类正式入口至少覆盖：自然肯定表达；否定、假设、转述；暂缓/拒绝/转题；跨轮部分事实；正常显示但缺标记的补取；补取超时及手动恢复；切聊天/回档；新消息和旧识别并发；写入失败和刷新；同一次副作用不重复；旧存档保留。通知另测所有子类型、时间地点与胎次；日常另测三个项目；分居另测两个决定。

自然聊天另做多轮观察：连续未推进不会产生任务式反问；话题自然相关时允许顺势表达角色关切；玩家转题后不反复拉回；玩家重新提起时能接续已有事实。

角色主动引导必须单独验收，不能用玩家主动提问后的回答代替。至少覆盖六种行为：玩家只闲聊但角色有独立现实动机时主动说明实质内容；没有新契机时继续眼前聊天；玩家明确暂缓时收住；同一情境刚提过时不催问；玩家接话时承接自己的真实想法；玩家暂缓后继续一轮仍保留空间。逐条检查上下文、发言主体和是否虚构决定，不以是否含问号或关键词判定。主动发言允许是陈述，不要求反问。

原型通过这些样例后，正式接入仍需证明上述契机来自实际游戏上下文、同一情境去重及暂缓状态能跨轮保留，并检查前端显示、存档重载和合法业务提交。人工预设“有新顾虑”的模型样例仅能证明该输入下的生成行为，不能证明游戏已经具备自动识别契机的能力。可选契机下不要求每次都引导；不得为提高通过率改成强制发问。

测试分层记录：

- 原型协议：真实接收、引用验证、候选事实与提交门，外部模型/原子事务用明确测试替身。
- 原有生产回归：验证此前功能基线，不能证明九类新设计已经接入。
- TauriTavern真实观察器：真实客户端、当前模型、原始返回再进入原型；业务回执仍是测试数据。
- 生产功能自动化：正式游戏入口或恢复入口 → 保存的回复 → 原业务状态机 → 隔离存档；本版按用户最新要求执行。新的TauriTavern正式流程不在本次验收中。
